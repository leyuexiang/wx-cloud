任务：M0-02。日期：2026-10-31。状态：**策略冻结，字段、错误码和应用登记细节进入 M0-03。**

## 1. 已确认决策

| 编号 | 决策 | 来源 | 影响 |
| --- | --- | --- | --- |
| DEC-01 | 租户端登录使用“租户编码＋手机号＋密码”作为用户输入；服务端先用租户编码定位租户，再在该租户内按手机号定位账号。 | 用户确认 | 前端登录表单增加租户编码；后端不得做全平台手机号唯一假设 |
| DEC-02 | 租户普通用户区分场景编辑者和只读用户。编辑者只能维护本租户自己拥有的场景；只读用户只能读取被授权内容。 | 用户确认 | 需要新增/映射场景编辑能力，不能只依赖页面按钮隐藏 |
| DEC-03 | 共享资源由租户管理员维护；普通编辑者不获得租户共享资源的全局维护权。 | 用户选择的建议包含该边界 | 资源写权限与场景写权限分离 |
| DEC-04 | 服务端身份来源为有效访问令牌、登记应用、平台和令牌中的真实租户；请求头 `tenant-id` 只能作为一致性校验输入，不能改变令牌身份。 | 现有租户过滤器及项目规则 | 请求头与 `LoginUser.tenantId` 不一致返回禁止访问 |
| DEC-05 | 平台超级管理员维护全局资源和平台范围配置；不能仅凭同名角色或客户端提交的租户号获得平台权限。 | 现有 ART 合同及项目设计 | 全局写入同时检查受信平台租户和真实平台角色 |
| DEC-06 | 预览访问者使用发布票据，不获得后台管理身份；管理令牌、刷新令牌、预览票据、对象签名各自限制用途。 | 前端预览适配器及总体设计 | 公开/受限预览分别校验票据和访问模式 |
| DEC-07 | 运营端使用手机号登录，运营账号手机号在运营账号命名空间内全局唯一。 | 用户确认 | M1 适配现有 username 登录时，需建立手机号到运营账号的明确映射，重复手机号拒绝迁移 |
| DEC-08 | 场景编辑者可以发布自己拥有的场景；跨租户授权必须由租户管理员或平台管理员执行。 | 用户确认 | 发布动作与跨租户授权动作分离，发布后仍按场景和资源范围授权 |

## 3. 进入 M0-03 的合同细节

这些问题影响正式接口合同或账号迁移，策略已明确但实现细节仍待冻结：

1. **平台应用登记：**运营端、租户端的 `clientId`、状态、允许的接口范围和配置来源。不得使用前端 `.env.example` 中的示例编号作为生产身份。
2. **租户编码字段：**使用租户表的 `website`、独立编码字段，还是新增稳定编码。若复用 website，需定义大小写、唯一性、变更和泄漏规则。
3. **账号跨租户：**同一用户是否允许属于多个租户。若允许，登录会话必须固定一个租户上下文，并在切换时重新签发/重验身份；不能复用一个令牌伪造切换。
4. **应用停用行为：**应用停用、租户到期、用户禁用后，是立即撤销访问令牌，还是在下一次请求校验时拒绝。建议请求校验立即拒绝，并清理会话缓存。

## 4. M1 实施约束

- 租户端登录请求新增 `tenantCode`，但在 M0-03 冻结具体 JSON 字段和错误码前不修改控制器。
- 服务端查询顺序必须是：校验应用/平台 → 按租户编码定位有效租户 → 按手机号定位该租户用户 → 校验账号状态/密码 → 签发绑定平台、应用、用户和租户的令牌。
- 无租户编码、租户不存在、手机号不存在、跨租户请求和应用平台不匹配分别记录可审计失败原因；对外消息不暴露租户是否存在的敏感枚举细节。
- 业务请求默认从 `LoginUser.tenantId` 建立租户上下文；显式 `tenant-id` 只能等于该值。内部受信平台操作使用服务端明确的系统租户路径和角色检查。
- 权限码与页面能力分离。前端能力快照只负责展示和交互，后端必须在控制器/服务层再次检查场景、资源和发布权限。

## 5. M0-02 结论

用户已确认租户编码登录、运营手机号唯一、编辑者/只读用户分层及编辑者发布自己场景。项目已确认服务端租户不得由请求头覆盖。应用 clientId 登记、租户编码字段来源、多租户账号策略和停用撤销时机属于接口/实现细节，进入 M0-03。M0-02 策略任务完成，M1 仍须等待 M0-03 合同冻结。
