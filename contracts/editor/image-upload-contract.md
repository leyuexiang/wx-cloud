# 图片资源新增上传接口及数据合同（IMG-01）

日期：2026-11-10。状态：本地合同基线已形成，尚未部署或通过业务方页面验收。此合同只覆盖普通图片文件及图片目录新增所需的文件身份，不改变 ART 受控资源合同。执行状态见 [IMG-00～IMG-06](../../docs/03_近期执行任务.md#img-00图片资源新增上传功能完善计划2026-11-10)。

## 1. 范围及兼容边界

- 浏览器现有公共文件入口保持 `/api/resource/oss/...`，文件接口不插入 `operation` 或 `tenant/web`。网关只为已列明的精确路径改写到基础设施服务，不开放通配写入。
- 运营/租户平台身份仍由 `Authorization`、`ClientId` 和现有租户一致性规则认证。客户端不声明可信用户、租户或平台角色；服务端从已认证登录上下文取得 `tenantId`、`userId`。
- `ossId` 精确映射本地 `wx_infra_file.id`，响应、路径与请求均使用十进制字符串。它与旧外部 OSS 编号、`wx_3d_icon.id`、ART `resourceId` 均不自动等同；遇到历史编号须有单独审计映射。
- 既有 `/admin-api/infra/file/upload` 和 RPC `FileApi.createFile` 的地址字符串响应不变；新接口走独立的有归属上传方法。
- 第一阶段读取仅支持目前前端真实消费者调用的单个文件编号；不从路径分隔符猜批量语法。未来批量接口需单独定量限额与合同。

## 2. 路径和请求

| 方法/路径 | 请求 | 成功数据 | 用途 |
| --- | --- | --- | --- |
| `POST /api/resource/oss/upload` | `multipart/form-data`，字段 `file`，恰好一个文件 | `OssFile` 对象 | 按当前认证身份上传并创建私有待绑定文件记录 |
| `GET /api/resource/oss/listByIds/{ids}` | `{ids}` 必须是单个正十进制本地文件编号 | `OssFile[]`，找到时一项，未找到/不可见时空数组 | 为已有消费者按编号重取可短期使用的读取地址 |
| `POST /api/operation/dim3d/icon/add`、`POST /api/tenant/web/dim3d/icon/add` | 既有图标 JSON 字段；`iconFileId` 是本地文件编号 | 真实图标目录编号按字符串返回 | 新增图片目录；服务端另行验证分类、文件、归属及权限 |

网关精确规则：

- `/api/resource/oss/upload` → `/admin-api/infra/file/resource/oss/upload`。
- 当前前端 admin 模式的 `/admin-api/resource/oss/upload` 和 `/admin-api/resource/oss/listByIds/{ids}` 转发至相同基础设施适配。直接管理路径也清除外部伪造身份头。
- `/api/resource/oss/listByIds/{ids}` → `/admin-api/infra/file/resource/oss/listByIds/{ids}`。路由不校验编号 Regex；基础设施控制器只接受正十进制单编号并验证 `Long` 上限。
- 三维控制器应用项目管理端的路径前缀规则，类级 `/dim3d` 与 `/admin-api` 组合，运营及租户别名转发至 `/admin-api/dim3d/...`，实际运行映射由部署后联验确认。
- `/api/operation/dim3d/icon/add` → `/admin-api/dim3d/icon/add`；`/api/tenant/web/dim3d/icon/add` → `/admin-api/dim3d/icon/add`，租户服务依可信认证上下文区分归属。若核查现有网关/控制器基路径与本表不一致，应先修正合同及测试，不新增宽泛代理。

认证、`ClientId` 和可选 `tenant-id` 校验沿用现有系统。三条写路径均不得匿名访问。查询虽返回空数组以避免文件编号枚举，也要求已认证身份。

## 3. 字段和校验

### `OssFile`

| 字段 | 类型 | 规则 |
| --- | --- | --- |
| `ossId` | string | 正十进制 `wx_infra_file.id`；不得以 JSON 数字输出 |
| `url` | string | 文件读取短期签名地址；不持久化至目录记录，不写日志 |
| `originalName` | string | 原始显示名；UTF-8；不含服务端路径 |
| `fileSuffix` | string | 小写扩展名，不含点；基于服务端解析结果 |

不输出存储配置密钥、桶名、对象键、内部主机名。当前前端仅依赖 `ossId` 与 `url`；`fileName`、`ext1`、`service` 不作为必需字段。若消费者审计发现实际依赖，再通过版本化字段补充，不猜测旧字段语义。

### 上传约束

- 仅允许 `.webp`、`.svg`、`.png`、`.jpg`、`.jpeg`；空文件拒绝，最大文件大小 `5,242,880` 字节。
- 服务端以文件内容检测媒体类型并与扩展名对照，位图完整解码且尺寸有界，WebP 通过已接入的纯 Java 解码器验证有效及损坏载荷。SVG 使用禁用外部实体与资源的 XML 解析，拒绝脚本、事件处理器、外部引用及活动内容，样式正文同样参与检查。前后端分别执行适用的校验。
- 原始名去除路径部分、NUL 和控制字符后保留作显示；对象键由服务端随机生成且逐次唯一，不能用用户文件名覆盖对象。
- multipart 体积必须在写存储前有界检查；不得把超限文件读入无界堆缓冲。已有 `FileService.createFile` 的其他调用和 16 MiB 全局上传上限不随本合同改动。

### 图片目录新增约束

- `iconName` trim 后 1～50 字符；`iconDesc` 最多 200 字符；`category` 必须是启用的 `dim3d_icon_category` 字典 `dictValue`；`resourceBelong` 只能为 `SYSTEM` 或 `MINE`。
- `iconFileId` 必须引用存在、上传完成且在认证身份可绑定范围内的本地普通文件。客户端提交的租户/上传者字段一律忽略或拒绝。
- `SYSTEM` 资源只允许经服务端验证的运营平台管理员维护；租户账号只能新增 `MINE` 且归属当前认证租户。只读身份不可写入。
- 同租户上传用户可在文件未绑定期间读取和重试绑定。绑定后文件可见范围按目录归属收敛：`MINE` 为当前租户可读；`SYSTEM` 为所有已认证租户可读，写入仍受平台角色限制。越权/不可枚举文件编号返回统一空结果或权限错误，不回显目标归属。

## 4. 文件归属及生命周期数据

在 `wx_infra_file` 增量增加可空的 `tenant_id BIGINT`、`uploader_id BIGINT`、`visibility_scope VARCHAR(20)`。新上传必填可信 `tenant_id/uploader_id`，`visibility_scope` 初始为 `PRIVATE_UPLOAD`；已有行保持空/`LEGACY`，不得按主键、文件名或 URL 自动推定归属。由于当前基础设施租户配置显式忽略 `wx_infra_file`，每个新适配查询必须显式加归属谓词，不能仅依赖 MyBatis 租户插件。

文件成功绑定目录后，在与目录新增的同一数据库事务中将可见范围改为 `TENANT` 或 `GLOBAL`，并保留可信上传者/租户审计来源。对象存储写入与数据库不能共享事务：先写唯一对象，再插入文件行；文件行失败时仅删除本请求确认写入的对象。目录事务失败时保留 `PRIVATE_UPLOAD` 文件供原用户重试，按清理保留期另行核对引用并回收；不得在请求失败路径同步删除可能已被并发绑定的对象。

迁移先核对生产和测试库真实表结构、记录/目录引用及对象可达性，生成带前置断言的增量迁移和精确回退。回退只允许在确认新增字段无使用后执行，不删除新增图片、文件行或对象。正式配置/桶调整属于 IMG-02，必须先备份并验证对既有消费者的影响。

## 5. 响应、错误与重试

- 成功外层沿用 `CommonResult`，业务成功码为 `200`；分页/目录回执不在上传响应里混用。
- 缺失身份 `401`；已认证但无写/读权限 `403`，对象不可枚举时允许按具体读取合同返回 `data: []`；格式、媒体类型、超限、分类或文件引用校验失败为 `400/422`，存储不可用为 `503`，数据库提交失败为服务错误。错误不含路径、签名地址、桶配置和秘密。
- 当前 Web 客户端没有传请求幂等键。首次合同不承诺同请求重放返回同文件编号；每次被服务端接受的上传生成新对象和新文件编号。前端必须阻止并发重复提交，响应丢失后的重复上传可能产生未绑定文件，由 `PRIVATE_UPLOAD` 清理策略处理。
- 图片目录新增当前没有操作编号字段，不能伪造幂等回执。失败重试复用上传得到的 `iconFileId`；同一图标重复新增可能生成两条目录，后续如需重放幂等需先为消费者增加操作号及唯一约束，不能靠名称去重。
- 查询按编号每次重签读取 URL；签名有效期最长 10 分钟，签名不得写入持久数据或审计。撤销/移除范围阻止新签发，已签签名在自身到期前可能继续可用。

## 6. 需要在实现前/集成时验证的环境差异

1. 确认当前图标控制器位于运营及租户路由的真实服务路径；现源码实体字段长度与本合同不一致，须在业务代码、目录映射和分页投影中统一为兼容长度，不能只改表单提示。
2. 基础设施 `FileClient` 既有 `getPresignedObjectUrl` 生成 PUT 上传签名，不能用于读取；本地候选新增独立 `getPresignedDownloadUrl`，默认实现失败关闭，目前仅 `S3FileClient` 提供 GET 签名，非 S3 存储 client 必须先实现并验证方可启用。
3. `S3FileClient` 目前使用配置域名返回普通 URL；MinIO 私有桶的服务端地址、浏览器可达的下载域名和签名主机必须现场验证，健康检查 `200` 不构成上传/下载证据。
4. `wx_infra_file` 在现配置中是租户拦截忽略表；增量列本身不会自动启用租户隔离，必须有显式范围查询和跨租户拒绝测试。
5. 旧图标文件编号可能来自独立 OSS 域；在确认对应文件行和内容之前不得宣称旧记录可由新编号服务回显。应单独产出历史映射/不可达清单，避免数字相同误关联。

## 7. IMG-01 完成出口

### 2026-11-11 实施约束补充

图片目录和文件归属采用现阶段共库的短事务提交方式。图片领域服务只操作目录行及文件归属列，文件对象读写、文件元数据创建和签名继续复用基础设施服务。部署前必须确认这两个服务连接同一目标库，文件归属列迁移已应用。图片目录新增使用当前字典服务校验分类，远程校验位于数据库事务开始之前。事务内锁定目标文件行，校验真实上传者与租户，再提交目录及文件可见范围。

新增 `SYSTEM` 目录归属哨兵租户 `0`，平台写权限复用现有 `ArtResourceAccess`。新增 `MINE` 目录归属登录租户，上传者和审计字段由服务端填充。编辑时维持已绑定文件的范围，改变资源归属需要新上传的私有文件，以免使其他目录仍在引用的文件扩大或丢失访问范围。更新失败整体回滚，原关联保持有效。

图片上传使用现有图片、封面或场景编辑写权限，文件读取依登录身份及显式文件归属校验。图片消费者无需取得后台文件管理菜单权限。WebP 采用纯 Java ImageIO 解码器与 PNG/JPEG 共用有界解码检查，支持页面已声明的五种格式。

2026-11-11 实际接口核对确认 `9000` 返回对象存储 XML 协议响应，`9001` 返回管理控制台网页。提供的 MinIO 账号可在 `9000` 完成签名认证。对象存储客户端配置使用 `9000` 或其有效代理地址，凭据仅通过受控部署配置读取。

合同路径、字段、鉴权、文件编号命名空间、文件可见性状态、错误/幂等边界、迁移与失败恢复均进入本文件及差异清单；网关、存储环境、数据脚本和真实部署尚不因此完成。实现逐片采用“失败测试 → 最小代码 → 真实依赖验证”，先完成上传身份及读取授权切片，再完成图标绑定/列表和页面验收。
