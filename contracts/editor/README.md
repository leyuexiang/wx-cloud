## 4. 当前前端字典读取补充（2026-11-04）

- 依据：用户指定的 `jtyf-web-three/src/servers/manual/dim3d/api/dictionary.ts` 及真实接口契约维护文档。前端所有分类共用 `GET /api/system/dict/data/type/{dictType}`，设置 `skipPlatformPath=true`；`dim3d_icon_category` 是本次请求的图标分类类型。
- 网关仅把该路径改写为 `/admin-api/system/dict/data/type/{dictType}`，后者也支持直接调用。继续携带现有会话的 `Authorization`、`ClientId`，`tenant-id` 按现有系统一致性规则处理；不增加匿名访问或字典写权限。
- 系统适配使用现有字典服务单次按类型和启用状态查询，复用原有排序，再投影为字符串 `dictCode`、原值 `dictValue`、名称 `dictLabel` 和类型 `dictType`。原 `/system/dict-data` 管理接口及其响应保持原契约。
- 类型是单个非空路径段；模型、图标、场景、访问模式及前端传入的模板类型复用同一读取能力。未知或未配置类型返回 `data=[]`，不读取旧图标分类表，也不使用前端测试数据初始化业务分类。
- 本地请求测试与配置检查不等于部署验收；分类数据、登录、跨租户和真实页面验收状态统一见 [M1-02 执行记录](../../docs/03_近期执行任务.md#m1-02-字典读取适配执行记录)。
- 用户随后确认图片分类为设备、建筑、药材、仓储。对应[字典数据增量](../../deploy/test148/migrations/dictionary01/README.md)为缺失类别提供稳定默认编码，已有同名类别沿用原编码；启用并按截图顺序排列。“全部”不入字典，数量沿用前端真实图片分页总数，不保存截图数字。
