# 编辑器权限矩阵

任务：M0-02。状态：策略已冻结，M0-03 冻结字段、错误码和审计细节后作为接口合同附件。以下使用角色码和权限码示意，真实权限码需与系统菜单迁移一起确认。

## 1. 角色与范围

| 身份 | 认证平台 | 数据范围 | 说明 |
| --- | --- | --- | --- |
| 平台超级管理员 `super_admin` | 运营端 | 平台配置、全局资源及被授权的运营场景 | 必须是真实平台租户和系统角色，不接受请求体或请求头声明 |
| 租户管理员 `tenant_admin` | 租户端 | 本租户全部场景、共享资源、成员和授权 | 可维护租户共享资源并执行跨租户授权 |
| 场景编辑者 `scene_editor` | 租户端 | 本租户自己拥有的场景；可读取授权资源 | 可编辑自己的场景；共享资源写入仍由租户管理员维护 |
| 只读用户 `viewer` | 租户端 | 本租户可见场景和系统/共享资源 | 不创建、编辑、删除或发布场景 |
| 预览访问者 | 无后台管理平台或受限平台 | 单个发布快照及其授权依赖 | 只持有短时预览票据，不获得管理令牌 |

`scene_editor` 是本次用户确认后的目标能力分层，当前数据库测试脚本只有 `tenant_admin/viewer`，M1 需要新增角色或等价权限映射。角色是权限集合，不应作为业务请求字段由客户端提交。

## 2. 动作矩阵

| 动作 | 平台管理员 | 租户管理员 | 场景编辑者 | 只读用户 | 预览访问者 |
| --- | --- | --- | --- | --- | --- |
| 登录/读取个人资料 | 是 | 是 | 是 | 是 | 仅票据解析 |
| 查询本租户场景 | 按平台授权 | 是 | 是 | 是 | 仅已发布快照 |
| 创建场景 | 按平台权限 | 是 | 建议是 | 否 | 否 |
| 编辑/保存自己场景 | 按平台权限 | 是 | 是 | 否 | 否 |
| 编辑他人/共享场景 | 按显式授权 | 按租户策略 | 否 | 否 | 否 |
| 删除自己场景 | 按平台权限 | 是 | 建议是，需保留审计 | 否 | 否 |
| 发布自己场景 | 按平台权限 | 是 | 是，仅限自己拥有的场景 | 否 | 否 |
| 取消/修改他人发布 | 平台权限 | 场景/租户权限 | 否 | 否 | 否 |
| 维护租户共享资源 | 平台权限 | 是 | 否 | 否 | 否 |
| 维护全局资源 | 是，须平台租户和角色同时满足 | 否 | 否 | 否 | 否 |
| 场景授权给其他租户 | 是/平台策略 | 是，按租户策略 | 否 | 否 | 否 |
| 上传普通文件 | 按平台权限 | 按租户权限 | 可上传到自己的场景草稿 | 否 | 否 |
| 上传/提交受控 Unity 资源 | 平台权限或租户管理员权限 | 是 | 可创建自己场景所需的操作，最终资源维护权仍按 ART 合同 | 否 | 否 |
| 读取发布预览 | 是 | 是 | 是 | 是 | 有票据才允许 |

场景编辑者发布自己场景已由用户确认；M0-03 仍需冻结错误码、审计、撤销、发布有效期及跨租户授权细节。编辑者不能进行跨租户授权，也不能维护租户共享资源。

## 3. 授权判定顺序

每个受保护请求按以下顺序判定，遇到失败立即结束：

1. 验证访问令牌状态、应用、平台和会话撤销状态。
2. 从令牌读取真实用户、用户类型和租户；显式 `tenant-id` 只允许与令牌一致。
3. 验证租户有效期、账号状态和所需角色/权限码。
4. 读取目标对象的真实归属、状态、锁持有者和发布范围。
5. 对写动作验证对象归属、场景锁、预期修订、操作幂等及资源范围。
6. 写入审计记录；不得把访问票据、密码、刷新令牌或签名 URL 写入审计正文。

## 4. 直接拒绝案例

| 案例 | 期望结果 |
| --- | --- |
| 租户用户把 `tenant-id` 改成其他租户 | 403；不查询、不写入目标租户数据 |
| 普通用户在请求体指定 `operatorId/tenantId/role` | 忽略身份字段或 400；身份只来自令牌和服务端归属 |
| 场景编辑者编辑其他用户场景 | 403；不得仅因同租户放行 |
| 只读用户调用保存、删除、发布 | 403；前端隐藏按钮不构成安全控制 |
| 租户管理员维护平台全局资源 | 403；必须同时满足平台租户和平台角色 |
| 预览票据调用管理写接口 | 401/403；票据不能升级为后台令牌 |
| 失效、撤销或跨应用令牌继续请求 | 401；不能自动降级匿名成功 |
| 公开预览票据读取其他发布编号 | 403/404，避免枚举；不返回管理数据 |

## 5. 现状差异及 M1 输入

- 前端当前 `StandaloneLogin.vue` 只收手机号和密码，租户端需要增加租户编码输入。
- 后端 `AdminAuthServiceImpl` 当前按 `username` 认证；需要新增兼容适配，不能直接把手机号传到现有 username 登录而声称完成。
- 后端 `AdminUserDO` 已有 `mobile` 和 `tenantId`，`LoginUser` 已携带 `tenantId`；可以复用数据模型和租户过滤器。
- 后端 OAuth2 客户端目前没有明确平台字段；平台与应用绑定需在 M0-03 冻结后决定配置或新增字段，不能用示例 `clientId` 直接上线。
- 前端当前租户能力快照已隐藏模板、授权和导入入口，并按 `SYSTEM/MINE` 区分资源操作；后端仍需按真实归属和权限码执行同样边界。
