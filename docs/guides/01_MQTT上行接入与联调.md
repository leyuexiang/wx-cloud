# MQTT 上行接入设计与联调

日期：2026-10-20。范围：外部设备/平台通过消息队列遥测传输协议（MQTT）上报到 IoT 服务；服务到三维可独立采用 WebSocket 或 MQTT。

本文涵盖已实现的单连接兼容模式（SINGLE）和同租户动态多连接模式（DYNAMIC）。实现边界见[动态多连接方案](../design/05_IoT动态多连接接入方案.md)，本轮验证见[2026-10-20 记录](../records/03_20261020动态多连接验证记录.md)。

## 首版实现约束

提供 MQTT 3.1.1 通用 JSON 适配器，采用至少一次传输（QoS 1），功能默认关闭。工作进程明确指定一个租户：SINGLE 管理指定连接器，DYNAMIC 动态发现该租户内启用的多个 MQTT 连接器。两种模式互斥，不混合滚动部署；连接器、绑定和点位映射沿用数据库管理。

连接地址及凭据引用来自 MQTT 连接器。凭据引用指向 `IOT_MQTT_` 前缀的环境变量，内容为 `{"username":"...","password":"..."}`，不在数据库或日志保存密码。默认仅允许 `ssl://主机:端口`，校验服务器证书和主机名；自签名证书通过 JVM 信任库配置。开发环境可显式允许 `tcp://`。不允许地址嵌入用户名密码、路径、查询参数或任意协议。

连接器 `configJson` 采用 `{"topics":["pilot/device/telemetry"],"qos":1}`。首版仅允许 1 至 32 个确切主题，不启用通配订阅、厂商动态脚本或下行命令。客户端标识由租户、连接器和配置指纹确定，配置变化时使用新会话，防止旧持久订阅继续接收已移除主题。旧会话由 Broker 管理员清理或按 Broker 会话策略过期。

启用持久会话（`cleanSession=false`）和手动确认。报文通过校验并进入数据库接收记录（Inbox）后才发送 MQTT 确认；确认表示平台持久接收，不表示 Kafka 已发布或设备业务已处理。Kafka 异步失败仍保留在 Inbox，继续使用现有失败查询和人工重放；Broker 必须为发布方配置 QoS 1、持久存储与合适的离线队列上限。

每次接收均使用工作进程指定租户查询当前连接器，校验启用状态、主键、配置版本和指纹；动态模式同时校验数据库运行所有者，不增加重复查询。报文不能指定其他租户、连接器或内部身份，要求存在启用的设备绑定。MQTT 回调恢复外层线程租户上下文，复用既有点位换算、去重和发布链路。

无效报文、数据库故障和租约失效时不确认消息，连接关闭后采用有上限的指数退避重连。无效报文可能形成阻塞，需要修复平台报文/绑定或由运维隔离 Broker 队列；首版不静默丢弃，也不假定日志等于可靠隔离。没有实际平台契约时不猜测厂商字段。

MQTT 协议版本暂固定为 3.1.1；MQTT 5.0 的原因码、会话过期和共享订阅作为下一阶段能力，不将“支持 MQTT”解释为支持所有版本或厂商协议。TLS 使用 JVM 系统信任链，当前未提供管理端上传客户端证书或双向 TLS 配置。

## 通用上报格式

每条消息表示一个点位，UTF-8 JSON，最大 64 KiB。`eventTime` 使用 ISO 8601 时间字符串；`traceId` 由来源提供并在重试时保持不变。同一事件的时间、点位、值和追踪号重试时不得变化。

```json
{
  "externalDeviceId": "sensor-001",
  "pointCode": "temperature",
  "value": 26.125,
  "valueType": "NUMBER",
  "unit": "°C",
  "quality": "GOOD",
  "eventTime": "2026-10-19T02:00:00.123456789Z",
  "traceId": "sensor-001-seq-1001"
}
```

客户端认证及主题访问控制由 Broker 执行；同一个连接器的主题只应允许其管理范围内的设备或平台发布。统一事件进入 `twin.event.v1` 后由三维投影和规则消费者分别处理；三维前端的通信协议不改变本适配器。

## 生命周期与故障边界

工作线程定期检查连接器，启用后建立连接，停用、删除、配置变化或租约丢失时释放连接。连接失败采用带随机抖动的指数退避，最长五分钟；连续稳定连接一分钟后才重置故障计数，避免毒消息导致快速重连。生命周期资源在应用停止时释放，不使用无限本地消息队列或重复创建线程池。

租约有截止时间，回调在截止时间后拒绝接收与确认；定时续租必须比较随机令牌，旧实例不得续租或删除新实例租约。正常无阻塞情况下，每五秒检查连接器；数据库或网络阻塞会延长检查间隔，每条报文还会重新检查连接器。停用检查与消息入库之间没有跨系统事务，已进入处理的报文可能完成持久接收。尚未完成真实 Broker、数据库和网络故障联调前，不宣称生产验收完成。

## 配置与启用顺序

| 环境变量 | 默认值 | 说明 |
|---|---|---|
| `IOT_MQTT_ENABLED` | `false` | 创建 MQTT 工作进程的开关 |
| `IOT_MQTT_MODE` | `SINGLE` | 选择 SINGLE 或 DYNAMIC，两种模式互斥 |
| `IOT_MQTT_TENANT_ID` | 空 | 必须为已启用的有效租户 |
| `IOT_MQTT_CONNECTOR_ID` | 空 | SINGLE 必填；DYNAMIC 必须留空 |
| `IOT_MQTT_ALLOW_INSECURE` | `false` | 仅本地联调时允许 `tcp://` |
| `IOT_MQTT_MAX_CONNECTIONS` | `64` | 动态模式管理的前 N 个启用连接器，范围 1—1024 |
| `IOT_MQTT_CONNECT_CONCURRENCY` | `4` | 建连并发 1—32，不能超过连接上限，无建连等待队列 |
| `IOT_MQTT_CONTROL_CONCURRENCY` | `4` | 控制线程上限 1—32，处理续租和配置核对 |
| `IOT_MQTT_DISCOVERY_BATCH_SIZE` | `32` | 游标查询批次 1—256，一轮最多读取容量加一条 |
| 连接器的 `credentialRef` 指向的变量 | 无 | `IOT_MQTT_...` 名称，JSON 用户名密码 |

1. **先升级数据库**：新库使用更新后的 `wx-module-iot/db/iot.sql`；旧库在表前缀迁移后停写、备份，并执行一次 `wx-module-iot/db/iot-connector-runtime-migration.sql`。实体增加了运行所有者字段，升级应用前必须迁移，不能仅依靠 MQTT 开关跳过。脚本不自动执行，本轮未在真实数据库执行。
2. 在 Broker 准备应用账号、允许订阅的确切主题、QoS 1 与持久会话；同时配置持久化、离线队列容量、报文大小上限及会话清理策略。适配器限制业务载荷 64 KiB；Paho 在回调前已经读取网络帧，因此 Broker 的报文上限同样必须配置。
3. 使用现有管理接口创建 `connectorType=MQTT` 的连接器，填写 endpoint、credentialRef 与 configJson。创建默认停用；保存和启用会校验协议结构，不会测试网络连通性或回显凭据。业务编号创建后不可修改，展示名称可修改。
4. 创建并启用外部设备绑定，维护内部设备编号、场景对象及点位映射。
5. 在受限环境文件中提供引用凭据并选择模式。动态模式设置 `IOT_MQTT_MODE=DYNAMIC`、有效租户和空连接器编号；数据库、Redis、Nacos 与 Kafka 沿用原配置。
6. 调用连接器 `/enable` 接口。正常周期五秒，成功订阅后为 `CONNECTED`；新增、修改、停用由动态管理器发现。编辑应提交查询响应的 `version`；并发冲突需刷新，旧客户端省略版本时仅有服务端读写窗口的并发保护。
7. 分别向至少两个连接器发布示例报文，核对 Inbox、事件归属与三维投影。重复发布保持同一事件编号；不能只用发送端“发送成功”证明业务链路完成。

## 动态模式的所有权与资源边界

- Redis 60 秒令牌租约协调会话，本地保守截止时间为 55 秒；数据库同时保存 60 秒运行期限和所有者令牌。数据库接管只允许空或过期所有者，状态回写需匹配租户、主键、版本、令牌及未过期期限，避免旧实例覆盖新状态。
- 每个客户端捕获运行代次，停用、失租约、关闭和重新建立会话后，旧代次不能因续租恢复确认。Redis 与数据库之间仍没有分布式事务，不据此承诺严格单次业务执行。
- 配置发现与会话控制分别调度，控制、建连和关闭使用独立有界执行器。慢建连不占用续租控制线程；控制队列及关闭队列最多为连接容量，每个会话只允许一个同类在途任务。
- 新版本先等旧客户端关闭并清理所有权，再建立新会话。配置指纹变化会使用新客户端号，旧队列不会自动迁移；按现有 Broker 队列隔离或清理策略处理，不承诺无损零中断切换。
- 每轮按主键顺序选择前 N 个启用的 MQTT 连接器，超额记录不入队；多个实例主要协调同一组连接的接管，尚未提供跨实例负载均衡和跨租户分片。
- 停机先使接收资格失效，再等待在途建连及关闭任务完成并回调。部署需为实际连接规模预留优雅停机预算；若外部强制终止，剩余所有权依赖期限过期，不视为所有资源已自然清理。

凭据解析接口已抽出，默认仍读取环境变量；只对已注入的引用支持运行时新增连接器。后台动态新增真实秘密、证书管理和密钥轮换仍属于后续 M2。

首次接入时，Broker 拒绝订阅或将确认 QoS 降级为 0，均视为接入失败。用户名密码轮换后应重启该工作进程；相同 credentialRef 的环境值不会在长连接期间自动刷新。

## 实际依赖验收清单

真实环境仍需核验服务账号的主题权限、证书和主机名验证、Broker 持久存储、进程重启后未确认报文重投、双实例抢占、Redis 故障/租约过期、数据库不可用、连接器停用、毒消息阻塞处理和最终 Kafka/三维投影结果。跨地域 Redis 复制或主从切换可能改变租约可见性，不能将本租约当成数据库与 Broker 之间的严格分布式事务。
