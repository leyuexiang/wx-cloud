# 148 MQTT 认证与主题权限探测

核对日期：2026-10-23。用途：在启动 IoT 服务前验证 148 MQTT Broker 的账号、客户端编号和单个主题的订阅权限。当前已确认 `192.168.10.148:1883` 存在 MQTT 3.1.1 入口，但匿名连接被拒绝；`8883` TLS 入口尚未发现。

## 1. 探测工具

脚本 [probe-mqtt.py](../../tools/iot/probe-mqtt.py) 只使用 Python 标准库，流程为：

```text
CONNECT（clean session）
  → CONNACK 返回码 0
  → SUBSCRIBE（QoS 1）
  → SUBACK 确认 QoS 1
  → UNSUBSCRIBE → UNSUBACK 编号匹配
  → DISCONNECT
```

脚本不发布消息、不进入 Inbox/Kafka、不写设备数据；客户端编号默认随机，结束时关闭清洁会话。密码只从当前进程环境变量读取，不打印到命令行或输出。只有用户名、密码（允许显式空密码）和确切主题全部注入、配置校验通过后才打开网络连接，禁止 `+`、`#` 通配符。

Broker 可能在订阅确认前或取消订阅期间推送保留/实时消息，工具只丢弃，不打印、不保存、不发送业务消息确认。等待每个确认使用固定截止时间，单包上限 1 MiB；超过上限或协议异常会失败退出，清洁会话关闭后清理临时订阅。探测会在 Broker 留下短期会话及访问日志。

## 2. 使用方式

在受控终端注入部署方提供的账号、密码和一个确切主题：

```powershell
$env:IOT_MQTT_PROBE_HOST = '192.168.10.148'
$env:IOT_MQTT_PROBE_PORT = '1883'
$env:IOT_MQTT_PROBE_TOPIC = '实际/确切/主题'
$env:IOT_MQTT_PROBE_USERNAME = '部署方提供的账号'
$env:IOT_MQTT_PROBE_PASSWORD = '部署方注入的密码'
$env:IOT_MQTT_PROBE_TLS = 'false' # 仅用于已授权的受控开发网络。
try {
    & python .\tools\iot\probe-mqtt.py
    $probeExitCode = $LASTEXITCODE
} finally {
    Remove-Item Env:IOT_MQTT_PROBE_HOST, Env:IOT_MQTT_PROBE_PORT, Env:IOT_MQTT_PROBE_TOPIC, Env:IOT_MQTT_PROBE_USERNAME, Env:IOT_MQTT_PROBE_PASSWORD, Env:IOT_MQTT_PROBE_TLS -ErrorAction SilentlyContinue
}
Write-Host "探测退出码=$probeExitCode"
```

密码应由部署方在受控进程中注入，上述赋值仅为变量说明，不要把真实密码写进脚本或终端历史。如果部署方提供 TLS 端口，改为相应端口并设置 `IOT_MQTT_PROBE_TLS=true`；最低 TLS 1.2，校验证书链和主机名，可用 `SSL_CERT_FILE` 指定可信 CA 文件。不要为了通过探测关闭 TLS 校验。

可选变量：

| 变量 | 默认值 | 作用 |
|---|---|---|
| `IOT_MQTT_PROBE_CLIENT_ID` | 随机 `probe` + 18 位十六进制数字 | 23 位字母数字；可注入部署方分配的独立探测编号，不得复用在线客户端编号，避免顶掉既有会话 |
| `IOT_MQTT_PROBE_TIMEOUT` | `10` | 建连、TLS 握手和每个 MQTT 确认阶段的超时，有限值且大于 0、不超过 60 秒；不是整个进程的总时限，系统 DNS 解析时间受操作系统控制 |

## 3. 结果解释

- `CONNACK 返回码=0`：账号认证通过，继续检查主题订阅结果。
- `CONNACK 返回码=2`：客户端编号被 Broker 策略拒绝。
- `CONNACK 返回码=4/5`：用户名密码错误或没有授权。
- `SUBACK 返回码=128`：订阅被拒绝；`0` 表示降级为 QoS 0，均不满足本次 QoS 1 要求。
- `SUBACK`/`UNSUBACK` 类型、长度或报文编号不匹配：协议确认失败，不输出成功。
- 退出码 `0`：认证、QoS 1 订阅确认和取消订阅确认均通过；退出码 `1`：配置、网络、认证、订阅或协议确认失败。
- TLS 握手失败：先核对端口、证书链和主机名，不改为明文绕过。

探测成功只证明当前账号和客户端编号通过认证、Broker 接受该主题的 QoS 1 订阅并确认取消。部分 Broker 会接受订阅后静默过滤无权消息，因此不证明实际投递 ACL、发布权限、跨租户隔离或设备上行可用；本工具不发布探测消息，也不据此扩大权限。多连接器、其他主题、设备绑定、Inbox、Kafka 和三维状态仍需按 IoT 联调顺序验证。测试凭据不得提交到 Git，也不要粘贴到聊天记录。
