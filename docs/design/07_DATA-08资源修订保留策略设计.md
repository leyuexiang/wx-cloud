# DATA-08 资源修订保留策略设计

更新日期：2026-11-19。新保存请求与书签接口已在隔离三维服务验证，当前执行状态与部署证据统一见 [近期任务 DATA-08](../03_近期执行任务.md#54-data-08-关闭双写后恢复与负载验证)。历史请求回填及清理仍保留后续验收。

## 1. 目标与边界

本设计只处理场景修订和共享正文的保留判断，不改变当前修订指针、不覆盖不可变四包、不直接执行物理删除。资源对象的发布引用继续由 ART/DATA-09 的固定资源引用表负责，本文只消费其引用结果。

回收候选必须同时满足：

1. 不是场景当前修订；
2. 不存在活动编辑锁；
3. 不被模板首版、发布历史、有效票据或持久书签引用；
4. 请求幂等保留窗口已经结束；
5. 场景删除时已超过删除审计窗口；未删除场景不能仅凭“旧修订”进入回收；
6. 共享正文没有其他租户或修订引用。

任何引用状态无法确认时保全数据，审计工具只输出计划，不执行删除。

## 2. 持久书签

当前 `Dim3dSceneService.bookmark()` 只是保存接口回执，不构成持久引用。新增 `wx_3d_scene_bookmark` 时使用以下字段：

| 字段 | 约束 | 说明 |
| --- | --- | --- |
| `id` | 主键 | 服务端生成的书签编号 |
| `tenant_id` | 非空 | 书签所属租户 |
| `scene_id`、`revision_no` | 非空 | 固定引用的场景修订 |
| `bookmark_type` | 非空 | `EDITOR`、`PREVIEW` 或后续扩展类型 |
| `bookmark_key` | 租户内唯一 | 外部页面、任务或客户端稳定键 |
| `status` | 默认 `ACTIVE` | 撤销只改状态，保留历史 |
| `expires_time` | 可空 | 空值表示由业务明确长期保留 |
| `created_by`、`created_time` | 非空 | 审计来源 |
| `revoked_by`、`revoked_time` | 可空 | 撤销审计 |

唯一键为 `(tenant_id,bookmark_type,bookmark_key)`，查询索引为 `(tenant_id,scene_id,revision_no,status,expires_time)`。保存、预览或任务创建只有在确实需要跨请求保留修订时才写入书签；普通保存回执不自动创建书签。

## 3. 请求幂等保留

修订行内的 `request_id` 继续保留用于历史审计，但请求重放不应永久阻止保留判断。新增独立 `wx_3d_scene_request` 表保存 `(tenant_id,scene_id,request_id,request_hash,revision_no,expires_time)`，保存事务先锁定场景，再按该表判断重放。迁移时从已有修订回填请求记录，过期时间使用统一配置的幂等保留窗口；新保存必须在同一事务写入请求记录和修订引用。

幂等记录过期只表示“不能再用请求号重放”，不表示可以删除修订正文。正文仍需经过第 1 节全部引用门禁。

### 2026-11-19 实施边界补充

- 保留修订表原有请求号唯一约束；已到期请求返回 409，调用方必须生成新请求号，不允许重用历史编号。缺少保留记录的历史修订沿用旧幂等回执且继续保全，不自动赋予历史数据过期资格。
- 新请求保留记录只插入一次，并随修订事务提交；重复回执不续期，摘要或修订指向不一致时拒绝，不覆盖审计身份。
- 持久书签使用 `POST /dim3d/scene/bookmark/{sceneId}`，正文包含 `revisionNo/bookmarkType/bookmarkKey/expiresInSeconds`（60～86400 秒）；服务端固定当前身份、租户及到期时间。仅允许管理员角色。同键重试返回原书签，不续期、不换版；撤销或到期后需新键。
- `DELETE /dim3d/scene/bookmark/{sceneId}/{bookmarkId}` 幂等撤销，不删除行；仅创建者可撤销，租户及场景必须匹配。新增和撤销均先取得场景行锁，与保存共用锁顺序。
- 发布、票据、模板沿用现有权威引用表，不重复生成书签。书签接口只记录显式跨请求保留，不擅自接入前端每次保存流程。
- 本轮请求期限是服务端重放门禁；完整历史回填、客户端书签生命周期及清理执行器未验收前，审计候选仍固定为零。

## 4. 审计和清理流程

1. 只读审计批量读取当前指针、锁、模板、发布、票据、书签、请求记录及共享正文反向引用，输出每条修订的保留原因。
2. 计划阶段不改库，记录数据库摘要、规则版本、候选数量和所有阻断原因。
3. 执行阶段停写并备份场景、修订、共享正文及引用表；事务内重新核对候选，任何字段变化立即放弃本批。
4. 首次处理只做逻辑删除和审计记录，观察窗口结束且再次核对无引用后才允许物理清理共享正文；原修订四包在兼容期保留。
5. 回退只恢复状态和引用，不依赖重建正文；备份保留到观察窗口结束。

## 5. 实施顺序与验收

1. 两张保留表已在隔离库应用，迁移仍必须遵守备份标记和显式确认门禁；不据表存在判定引用链路已完成。
2. `Dim3dSceneService` 的写入和回放门禁由关闭即兼容的开关控制；开启后首版和保存事务写入请求摘要、修订号及 30 天默认保留期限，重放不续期。
3. 显式书签接口已接入；发布、票据和模板继续读取各自权威引用表。跨租户、撤销、过期和并发保存分别验证，不重复制造引用。
4. `audit-data08-retention.py` 读取书签和请求记录并检查摘要错配，时间使用数据库纪元秒以消除审计主机时区影响；默认仍为只读且未知状态保全。
5. 在隔离库创建带专用前缀的书签和过期请求，验证当前指针、发布、票据、模板及书签任一存在时均无候选；所有引用解除且超过窗口后才生成候选。
6. 完成备份、停写、回填、回读、重复执行和回退演练后，才评审小范围灰度。

本设计不把全量回读通过视为保留策略完成；历史请求仍有未回填记录，客户端书签生命周期和清理执行器仍待实现与验收，继续保全全部数据。
