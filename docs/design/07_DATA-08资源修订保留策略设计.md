# DATA-08 资源修订保留策略设计

更新日期：2026-11-19。状态：结构层已在隔离库应用，请求记录写入代码完成但开关关闭，待书签接口和回收演练。

## 1. 目标与边界

本设计只处理场景修订和共享正文的保留判断，不改变当前修订指针、不覆盖不可变四包、不直接执行物理删除。资源对象的发布引用继续由 ART/DATA-09 的固定资源引用表负责，本文只消费其引用结果。

回收候选必须同时满足：

1. 不是场景当前修订；
2. 不存在活动编辑锁；
3. 不被模板首版、发布历史、有效票据或持久书签引用；
4. 请求幂等保留窗口已经结束；
5. 场景删除时已超过删除审计窗口；未删除场景不能仅凭“旧修订”进入回收；
6. 共享正文没有其他租户或修订引用。

任何引用状态无法确认时保全数据，审计工具只输出计划，不执行删除。

## 2. 持久书签

当前 `Dim3dSceneService.bookmark()` 只是保存接口回执，不构成持久引用。新增 `wx_3d_scene_bookmark` 时使用以下字段：

| 字段 | 约束 | 说明 |
| --- | --- | --- |
| `id` | 主键 | 服务端生成的书签编号 |
| `tenant_id` | 非空 | 书签所属租户 |
| `scene_id`、`revision_no` | 非空 | 固定引用的场景修订 |
| `bookmark_type` | 非空 | `EDITOR`、`PREVIEW` 或后续扩展类型 |
| `bookmark_key` | 租户内唯一 | 外部页面、任务或客户端稳定键 |
| `status` | 默认 `ACTIVE` | 撤销只改状态，保留历史 |
| `expires_time` | 可空 | 空值表示由业务明确长期保留 |
| `created_by`、`created_time` | 非空 | 审计来源 |
| `revoked_by`、`revoked_time` | 可空 | 撤销审计 |

唯一键为 `(tenant_id,bookmark_type,bookmark_key)`，查询索引为 `(tenant_id,scene_id,revision_no,status,expires_time)`。保存、预览或任务创建只有在确实需要跨请求保留修订时才写入书签；普通保存回执不自动创建书签。

## 3. 请求幂等保留

修订行内的 `request_id` 继续保留用于历史审计，但请求重放不应永久阻止保留判断。新增独立 `wx_3d_scene_request` 表保存 `(tenant_id,scene_id,request_id,request_hash,revision_no,expires_time)`，保存事务先锁定场景，再按该表判断重放。迁移时从已有修订回填请求记录，过期时间使用统一配置的幂等保留窗口；新保存必须在同一事务写入请求记录和修订引用。

幂等记录过期只表示“不能再用请求号重放”，不表示可以删除修订正文。正文仍需经过第 1 节全部引用门禁。

## 4. 审计和清理流程

1. 只读审计批量读取当前指针、锁、模板、发布、票据、书签、请求记录及共享正文反向引用，输出每条修订的保留原因。
2. 计划阶段不改库，记录数据库摘要、规则版本、候选数量和所有阻断原因。
3. 执行阶段停写并备份场景、修订、共享正文及引用表；事务内重新核对候选，任何字段变化立即放弃本批。
4. 首次处理只做逻辑删除和审计记录，观察窗口结束且再次核对无引用后才允许物理清理共享正文；原修订四包在兼容期保留。
5. 回退只恢复状态和引用，不依赖重建正文；备份保留到观察窗口结束。
