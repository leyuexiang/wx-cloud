# 三维场景持久化与二维组件数据设计

整理日期：2026-10-19。本文描述目标数据模型与迁移方向，本轮未核验整套场景版本化交付，也未执行数据库迁移；不得按文中表结构直接认定现有系统已实现。当前专项状态见[后端台账](../plan/01_后端里程碑与进度台账.md)。

## 1. 文档目的

本文定义三维编辑器的场景、公共配置、三维对象、二维组件、二维图表、资源、数据绑定、版本、发布和协作锁的持久化边界。

适用范围：

- 服务端三维模块；
- 前端三维编辑器；
- 本地三维与地理三维场景；
- 旧引擎场景的兼容迁移。

本文只定义目标数据模型与迁移规则。新增表应通过增量脚本创建，禁止删除或直接改写现有生产表。

## 2. 现状与问题

当前工程表 `engineering` 同时保存场景名称、节点、组件实例、相机、图标和前端场景配置。该方式可快速交付，但存在以下问题：

1. 场景配置、二维组件配置和图表数据配置混在同一份长文本中，无法单独版本化、复用和查询。
2. 保存操作直接覆盖当前配置，无法处理多人并发编辑，也无法可靠回滚。
3. 资源、资源详情、资源版本、文件和对象存储文件之间缺少统一引用关系。
4. 任务表通过不断增加设备专属字段扩展，难以支持新设备和新交互类型。
5. 已发布场景若读取“当前配置”，可能被后续编辑静默改变。

前端已具备以下稳定概念：场景定义、场景对象、图层、资源引用、特效、流式加载、组件实例、图表渲染配置、数据配置和字段绑定。后端应围绕这些概念建立持久化模型。

## 3. 总体原则

### 3.1 单一事实来源

- 场景空间结构和公共配置的事实来源是场景版本快照。
- 二维组件实例配置的事实来源是组件实例版本。
- 图表样式的事实来源是图表配置版本。
- 动态数据绑定的事实来源是数据绑定版本。
- 关系投影只用于检索、统计、权限、资源回收和运行优化，不得反向覆盖版本数据。

### 3.2 版本不可变

已保存的版本不可修改。每次保存创建新版本，发布记录固定指向某一个完整版本集合。

### 3.3 配置与运行态分离

以下内容可以持久化：布局、样式、资源引用、数据源引用、刷新策略、默认相机、天空和环境设置。

以下内容不得写入场景库：实时相机位置、资源加载进度、实时图表数据、消息队列消费状态、渲染引擎对象、访问令牌和密码。

### 3.4 分层而不过度拆分

结构化、高频查询或独立生命周期的数据拆表；仅用于渲染且不需要单独查询的复杂参数保持为结构化文本字段。禁止把同一配置同时作为多个表的可编辑事实来源。

## 4. 核心关系

```text
场景主表
  ├─ 场景版本表
  │    ├─ 场景对象投影
  │    ├─ 图层投影
  │    ├─ 场景资源引用
  │    └─ 组件实例版本
  │         ├─ 图表配置版本
  │         └─ 数据绑定版本
  ├─ 场景发布记录
  └─ 场景编辑锁

组件定义 ──< 组件实例 ──< 组件实例版本
资源主表 ──< 资源版本 ──< 场景资源引用
对象存储文件 ──< 资源版本
```

## 5. 场景数据设计

### 5.1 场景主表

保留现有 `engineering`，但收敛职责为场景的身份、归属和生命周期信息。建议将表名逐步迁移为 `scene`；迁移期可继续使用原表名。

建议新增字段：

| 字段 | 类型 | 说明 |
|---|---|---|
| `scene_code` | 字符串 | 场景业务编码，全局稳定，不因复制和改名改变 |
| `scene_type` | 字符串 | 本地三维、地理三维等场景类型 |
| `coordinate_system` | 字符串 | 坐标系类型 |
| `cover_asset_id` | 长整型 | 封面资源引用 |
| `default_camera_key` | 字符串 | 默认相机标识，仅用于快速定位 |
| `current_revision_id` | 长整型 | 当前编辑版本 |
| `published_revision_id` | 长整型 | 当前已发布版本 |
| `publish_status` | 小整数 | 草稿、发布中、已发布、已下线 |
| `lock_version` | 整数 | 乐观锁版本号 |
| `scene_schema_version` | 整数 | 当前场景结构版本 |
| `tenant_id` | 长整型 | 多租户场景必须使用 |
| `deleted` | 小整数 | 逻辑删除标记 |

建议索引：

```text
唯一索引：(tenant_id, scene_code)
普通索引：(tenant_id, platform_type, publish_status, update_time)
普通索引：(current_revision_id)
普通索引：(published_revision_id)
```

以下旧字段停止新增依赖，待迁移完成后只读兼容：`nodes`、`coms_instance`、`com_points`、`hotfix_components`、`dic_com_system_info`、`camera_initial_position`、`camera_initial_euler`、`locked_gameobject_list`、`comm_com_jsons`、`icon_infos`。

### 5.2 场景创建模型

场景创建必须区分普通三维场景与地理信息场景。两类场景的坐标系、初始配置、可用资源、运行适配器和参数校验不同，禁止通过创建后再修改类型的方式互相转换。

当前前端已经定义两种创建类型：

| 前端业务类型 | 场景定义类型 | 坐标系 | 创建时的默认配置 |
|---|---|---|---|
| `CommScene` | `local3d` | 本地坐标，单位为米，向上轴为 Y | 空对象、空图层、空特效、开启网格 |
| `GisScene` | `gis` | 地理坐标 | 空对象、空图层、空特效、默认经纬度、地形关闭、阴影关闭 |

两种场景在主表中的 `scene_type` 必须是不可变字段。允许修改名称、封面和公共配置；不允许将已创建的普通三维场景直接改为地理信息场景，反向也不允许。需要转换时，应执行“复制为另一类场景”的显式流程，并重新校验资源和对象坐标。

建议提供两个独立创建接口，内部可共用创建服务：

```text
POST /dimensions/scenes/local3d
POST /dimensions/scenes/gis
```

普通三维场景创建请求：

```text
name                    场景名称
platformType            平台类型
coverAssetId            封面资源，可选
templateSceneId         模板场景，可选，且模板必须为普通三维场景
coordinateUnit          坐标单位，默认米
upAxis                  向上轴，默认 Y
```

地理信息场景创建请求：

```text
name                    场景名称
platformType            平台类型
coverAssetId            封面资源，可选
templateSceneId         模板场景，可选，且模板必须为地理信息场景
longitude               初始经度
latitude                初始纬度
height                  初始高度
terrainEnabled          是否启用地形
gisDataSourceId         默认地理数据源，可选
```

创建服务必须由后端生成首个场景版本，前端不能在场景编号尚未生成时直接写入最终配置。处理流程如下：

```text
校验场景名称和类型
  ↓
按类型创建场景主表记录
  ↓
生成类型专属的最小场景定义
  ↓
创建首个场景版本
  ↓
写入当前版本和乐观锁
  ↓
返回场景编号、场景类型、首个版本编号
```

校验规则：

1. 普通三维场景只允许本地模型、图片、贴图、材质、特效等本地渲染资源作为默认资源。
2. 地理信息场景允许影像、地形、矢量、地理三维瓦片和地理坐标对象；经纬度必须处于合法范围。
3. 地理数据源的访问凭据只保存在受保护的数据源配置中，场景版本仅保存数据源编号。
4. 模板复制必须保持相同场景类型；跨类型复制必须走专用转换任务，不得直接复制配置文本。
5. 场景列表、权限校验、发布校验均以 `scene_type` 为条件，不通过解析配置文本判断类型。

### 5.3 场景版本表

新增 `scene_revision`，用于保存场景空间结构和公共环境的不可变快照。

| 字段 | 类型 | 说明 |
|---|---|---|
| `id` | 长整型 | 主键 |
| `scene_id` | 长整型 | 场景主表编号 |
| `revision_no` | 整数 | 场景内递增版本号 |
| `schema_version` | 整数 | 前端场景定义版本 |
| `platform_type` | 字符串 | 适配的平台类型 |
| `definition_json` | 长文本 | 场景结构快照，不含二维组件完整配置 |
| `settings_json` | 长文本 | 相机、天空、环境、灯光和全局设置 |
| `content_hash` | 字符串 | 全量配置摘要 |
| `base_revision_no` | 整数 | 客户端保存时基于的版本 |
| `change_summary` | 字符串 | 保存说明 |
| `status` | 小整数 | 草稿、已发布、已归档 |
| `created_by` | 长整型 | 创建人 |
| `created_time` | 时间 | 创建时间 |

建议索引：

```text
唯一索引：(scene_id, revision_no)
唯一索引：(scene_id, content_hash)
普通索引：(scene_id, status, created_time)
```

`definition_json` 只保存场景对象、图层、特效、流式加载和组件实例版本引用。它不保存引擎运行对象、实时数据或密钥。

### 5.4 场景公共配置

场景公共配置分为主表摘要和版本配置两部分。

| 数据 | 存储位置 | 原因 |
|---|---|---|
| 场景名称、类型、平台、封面、发布状态 | 场景主表 | 列表和权限查询高频使用 |
| 默认相机标识、坐标系 | 场景主表和版本表 | 主表快速定位，版本表确保回滚一致 |
| 相机位置、朝向、视场角、裁剪面 | 场景版本 `settings_json` | 可编辑且需回滚 |
| 天空盒、环境贴图、曝光、雾、太阳光、环境光 | 场景版本 `settings_json` | 可编辑且需发布冻结 |
| 雨雪、云层、后处理和天气特效 | 场景版本 `settings_json` 或特效数组 | 可编辑且需发布冻结 |
| 实时相机位置、天气动画进度 | 不落场景库 | 属于运行态 |

公共配置建议结构：

```json
{
  "camera": {
    "defaultCameraKey": "main-camera",
    "position": [0, 10, 20],
    "rotation": [0, 0, 0],
    "fieldOfView": 60,
    "near": 0.1,
    "far": 5000
  },
  "environment": {
    "skyAssetId": 101,
    "environmentAssetId": 102,
    "exposure": 1,
    "fog": { "enabled": true, "near": 50, "far": 500 }
  },
  "lighting": {
    "sunDirection": [1, 1, 0],
    "sunIntensity": 1.2,
    "ambientIntensity": 0.5
  }
}
```

## 6. 三维对象、图层和资源

### 6.1 当前检索投影

版本快照是事实来源。为提高查询和发布校验效率，新增以下只读投影表：

| 表 | 主要字段 | 用途 |
|---|---|---|
| `scene_object_projection` | `scene_id`、`revision_id`、`object_key`、`layer_key`、对象类型、资源版本、可见状态、变换数据 | 对象树、对象检索、设备映射 |
| `scene_layer_projection` | `scene_id`、`revision_id`、`layer_key`、图层类型、顺序、数据源信息 | 图层树和图层筛选 |
| `scene_effect_projection` | `scene_id`、`revision_id`、`effect_key`、特效类型、参数摘要 | 特效校验和运行预加载 |
| `scene_streaming_projection` | `scene_id`、`revision_id`、区块、分组、边界、优先级 | 流式加载调度 |

保存版本后刷新投影。投影刷新失败时不得标记保存成功。

### 6.2 资源统一模型

现有 `resource`、`resource_info`、`resource_version`、`file_info`、`files_minio`、`material`、`icon_info` 在迁移期保留。新增统一资源模型：

| 表 | 用途 |
|---|---|
| `asset` | 资源逻辑身份，如模型、图片、贴图、材质、特效、环境贴图、地理瓦片 |
| `asset_revision` | 资源版本、摘要、解析信息、缩略图、转换状态 |
| `storage_object` | 对象存储物理文件 |
| `scene_asset_ref` | 某个场景版本对某个资源版本的引用 |

`scene_asset_ref` 应包含：`scene_revision_id`、`asset_id`、`asset_revision_id`、`usage_type`、`object_key`、`layer_key`、`required`。

唯一索引：

```text
(scene_revision_id, asset_revision_id, usage_type, object_key, layer_key)
```

## 7. 组件与实例设计

### 7.1 组件定义

新增 `component_definition`。它描述可拖拽、可复用的组件模板，不代表画布中的一个实际组件。

| 字段 | 说明 |
|---|---|
| `component_code` | 组件稳定编码 |
| `package_name` | 组件分类 |
| `component_key` | 前端组件键 |
| `name` | 组件名称 |
| `component_version` | 组件定义版本 |
| `default_config` | 默认配置 |
| `config_schema` | 可校验的配置结构 |
| `icon_asset_id` | 图标资源 |
| `status` | 启用状态 |
| `is_system` | 是否系统组件 |

唯一索引：`(component_code, component_version)` 与 `(package_name, component_key, component_version)`。

### 7.2 场景组件实例

新增 `scene_component_instance`。它代表场景中真实存在的一个二维组件或三维挂载组件。

| 字段 | 说明 |
|---|---|
| `scene_id` | 所属场景 |
| `component_definition_id` | 组件定义 |
| `instance_key` | 场景内稳定唯一标识 |
| `parent_instance_id` | 容器嵌套关系 |
| `layer_key` | 所属图层 |
| `object_key` | 绑定的三维对象，可为空 |
| `display_name` | 实例名称 |
| `sort_no` | 绘制层级 |
| `enabled` | 是否启用 |
| `deleted` | 逻辑删除 |

唯一索引：`(scene_id, instance_key)`。

组件定义、组件实例和实例配置不得放在同一张表：定义可被多个场景复用；实例归属于一个场景；配置必须随场景版本冻结。

### 7.3 组件实例版本

新增 `scene_component_instance_revision`。

| 字段 | 说明 |
|---|---|
| `scene_revision_id` | 所属场景版本 |
| `component_instance_id` | 所属组件实例 |
| `component_definition_version` | 发布时固定的组件定义版本 |
| `layout_config` | 位置、宽高、层级、旋转、透明度 |
| `base_config` | 名称、可见性、基础属性 |
| `style_config` | 非图表组件样式 |
| `interaction_config` | 点击、联动、事件配置 |
| `config_hash` | 配置摘要 |

唯一索引：`(scene_revision_id, component_instance_id)`。

## 8. 二维图表与数据绑定

二维图表配置必须独立存储。图表在前端既有渲染配置，也有独立的数据配置；两者变更频率和安全要求不同。

### 8.1 图表配置版本

新增 `chart_config_revision`，与组件实例版本一对一。

| 字段 | 说明 |
|---|---|
| `instance_revision_id` | 组件实例版本 |
| `chart_type` | 图表类型 |
| `render_config` | 标题、坐标轴、系列、图例、提示框等渲染配置 |
| `theme_config` | 主题、色板、字体等 |
| `dataset_config` | 数据集字段、维度和编码映射 |
| `refresh_policy` | 手动、定时、实时刷新策略 |
| `config_schema_version` | 图表配置结构版本 |
| `config_hash` | 配置摘要 |

唯一索引：`(instance_revision_id)`。

`render_config` 只存图表样式和展示语义，不存接口密钥，也不存持续增长的运行数据。

### 8.2 数据绑定版本

新增 `component_data_binding_revision`，图表和其他动态组件共用。

| 字段 | 说明 |
|---|---|
| `instance_revision_id` | 组件实例版本 |
| `source_type` | 静态数据、接口、消息订阅、设备指标 |
| `data_source_id` | 数据源标识 |
| `request_config` | 请求方法、参数、刷新设置 |
| `extractor_config` | 响应结果提取规则 |
| `dataset_config` | 数据维度和字段定义 |
| `binding_config` | 组件属性与字段映射 |
| `static_data` | 小体量演示数据 |
| `secret_ref` | 密钥引用，不保存明文 |
| `enabled` | 是否启用 |

规则：

1. 小体量演示数据可存 `static_data`。
2. 历史数据、设备实时数据、接口响应结果必须存业务库、缓存或时序库，不得复制到场景配置库。
3. 接口密码、令牌和第三方密钥只能保存 `secret_ref`。
4. 已发布场景引用的数据绑定版本不可修改；修改后创建新版本并重新发布。

| `published_by` | 发布人 |
| `published_time` | 发布时间 |
| `rollback_from_publish_id` | 回滚来源 |

发布前必须校验：场景版本存在、所有必需资源存在、组件定义版本可用、图表配置和数据绑定完整、配置结构合法。

### 10.2 编辑锁

新增 `scene_edit_lock`：

| 字段 | 说明 |
|---|---|
| `scene_id` | 场景 |
| `lock_token` | 编辑锁令牌 |
| `user_id` | 持有人 |
| `client_id` | 客户端标识 |
| `base_revision_no` | 开始编辑时版本 |
| `expire_time` | 过期时间 |
| `heartbeat_time` | 最后心跳时间 |

唯一索引：`(scene_id)`。

锁到期后允许其他用户抢占。保存接口必须同时校验编辑锁和乐观锁版本。

## 11. 保存、读取和发布流程

### 11.1 保存

```text
前端提交：场景编号、基准版本、场景定义、组件实例配置、图表配置、数据绑定配置
  ↓
后端校验编辑锁、乐观锁、配置版本和资源引用
  ↓
创建场景版本
  ↓
创建或复用组件实例版本、图表配置版本、数据绑定版本
  ↓
写入场景版本引用
  ↓
刷新对象、图层、资源等检索投影
  ↓
更新场景主表当前版本和乐观锁
```

场景版本、组件实例版本、图表配置版本、数据绑定版本和投影刷新必须处于同一事务边界；大文件解析和缩略图生成应异步执行，但不得阻塞版本保存。

### 11.2 读取

```text
读取场景主表
  ↓
按“当前版本”或“已发布版本”读取场景版本
  ↓
读取该版本引用的组件实例版本
  ↓
补充图表配置版本与数据绑定版本
  ↓
组装为前端完整场景定义
```

预览和线上运行必须读取 `published_revision_id`，编辑器读取 `current_revision_id`。

### 11.3 发布

```text
选择一个场景版本
  ↓
校验资源、组件、图表和数据绑定
  ↓
生成资源清单与发布摘要
  ↓
创建发布记录
  ↓
更新场景主表已发布版本和发布状态
```

## 12. 接口契约调整

保存场景接口应从“覆盖配置文本”升级为“创建版本”。请求至少包含：

```text
sceneId                 场景编号
baseRevisionNo          基准版本号
lockToken               编辑锁令牌
schemaVersion           场景结构版本
sceneDefinition         场景结构与公共配置
componentRevisions      组件实例配置集合
chartConfigurations     图表配置集合
dataBindings            数据绑定集合
changeSummary           保存说明
```

响应至少返回：

```text
sceneId
revisionId
revisionNo
lockVersion
savedTime
conflict                是否发生并发冲突
conflictRevisionNo      冲突时服务端当前版本
```

重命名应并入保存场景元数据接口，避免前端先保存配置、再改名的两个请求交叉覆盖。

## 13. 迁移计划

### 第一阶段：建立新结构

1. 新增版本、组件、图表、数据绑定、资源引用、发布和编辑锁表。
2. 为 `engineering` 新增当前版本、发布版本、乐观锁和场景结构版本字段。
3. 不删除任何旧字段和旧接口。

### 第二阶段：回填历史数据

1. 将每条现有工程记录的 `scene_config_info` 生成首个场景版本。
2. 将旧 `coms_instance`、`icon_infos` 解析为组件实例和实例版本。
3. 将旧资源地址解析为资源引用；无法解析的地址标记为待处理资源。
4. 为每个成功回填的场景设置当前版本。

### 第三阶段：双读单写

1. 前端优先读取新版本接口；旧场景无新版本时回退旧字段。
2. 新前端保存只写新版本结构。
3. 保留旧接口只读或转换为调用新保存服务。

### 第四阶段：发布切换

1. 发布、预览和线上运行仅使用已发布版本。
2. 旧字段仅作为兼容数据，不允许新功能写入。
3. 完成历史迁移并验证后，制定旧字段下线计划。

## 14. 性能与安全要求

1. 场景列表接口不得查询长文本配置、图表配置或资源详情。
2. 场景详情按版本一次读取，并批量加载组件、图表、数据绑定和资源引用，禁止逐条查询。
3. 对象、资源和组件引用使用批量插入与批量查询。
4. 大型场景配置可压缩存储，但必须保留可查询的摘要字段和版本号。
5. 图表实时数据使用缓存、消息服务或时序数据库，不能写入场景配置表。
6. 场景配置中禁止出现任何密码、访问令牌或第三方密钥。
7. 数据源凭据使用密钥引用，由服务端按权限生成短期访问能力。
8. 发布包使用内容摘要校验，资源版本变更后必须重新校验发布有效性。

## 15. 验收标准

满足以下条件后可完成迁移：

1. 保存场景后可查看任意历史版本，并可完整回滚。
2. 两个用户基于同一版本保存时，后提交者收到明确冲突，不会覆盖前者。
3. 图表样式修改、图表数据绑定修改、场景空间结构修改均可独立追踪并随场景版本发布。
4. 已发布场景不会因草稿编辑或组件定义更新而改变。
5. 删除资源前可以准确查询其被哪些场景版本和发布记录引用。
6. 场景列表、对象树和资源引用查询不依赖解析整份场景长文本。
7. 新增设备动作类型时无需修改 `task_event` 的字段结构。
