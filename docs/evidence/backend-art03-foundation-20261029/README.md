# ART-03 主清单校验与对象冻结基础（2026-10-29）

## 本轮结果

新增后端组件 `ArtResourceManifestVerifier` 与 `ArtResourceObjectStore`，实现严格主清单解析、确定性内容摘要、文件与入口引用校验，以及暂存对象回读和独立前缀冻结。**ART-03 仍在实施中**：本轮没有接通上传签名或数据库原子提交，线上接口保持未启用，不算单资源替换全链路完成。

- 中文资产名的内容摘要与 ART-01 既定夹具完全一致；覆盖字段/文件顺序变化、未知字段、资源 ID 绑定、UTF-8/重复属性/多根JSON、路径越界、主清单改名自引用、文件大小/数量及容量规则。
- 存储测试模拟暂存在校验与复制之间被改写，最终字节摘要不符则拒绝；源或目标前缀相同、重复路径、坏包、缺对象和已有冻结对象均被拒绝。
- [真实测试 MinIO 的5项检查](minio-probe.json)通过：暂存对象回读、冻结及最终回读、暂存改写不影响冻结对象、摘要错误拒绝、已有冻结对象禁止覆盖。使用独立随机前缀和小二进制文件，验收对象已清理。

## 实现约束

不能把客户端短时PUT地址用于最终内容前缀；旧地址在过期前可能重复写入。目标流程是客户端写暂存前缀，后端核验、复制到服务端独占且每次唯一的冻结前缀，再核验最终字节，最后才提交数据库指针。只校验暂存或只使用ETag不足以保证一致性。

冻结组件是内部存储边界，后续提交服务必须分配唯一最终前缀并串行约束同操作的提交，不给客户端签发最终前缀的写能力。对象存在检查不等于跨系统原子锁；真正并发和幂等由后续操作状态/事务处理。冻结失败可遗留孤立对象，不能切换当前指针，清理继续按保留策略后置。

文件按流处理，不一次读取大包；主清单最多4 MiB、4096个文件，单文件最多2 GiB、闭包最多4 GiB。这里的大小是后端校验上限，不保证浏览器能同时加载这些资产；实际运行包内存预算仍须测试。

当前主清单校验只证明元数据与摘要规则，不证明原生 AssetBundle 的Unity可加载性。包依赖图、材质/贴图、Shader兼容和灯光Renderer/布局关联仍待集成检查；主清单没有悬空入口不等于整个依赖闭包已通过。
