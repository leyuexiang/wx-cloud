# IOT-M3-05A/B 有界接收与定向分发复测

2026-11-17，**1000 个逻辑设备、每设备 5 秒一条、50 条认证协议连接的两轮一分钟测试均通过本轮工程门槛**。每轮 12000 条 QoS 1 上报、600000 次推送全部收到，0 重复、0 客户端错误；第 95 百分位延迟分别为 **1342.541 毫秒、111.764 毫秒**。测试接入与三维应用已切换，原程序与配置以停止的容器保留回退。

本批是一个模拟网关连接、同一租户账号的 50 条 WebSocket 连接，各订阅全部 1000 个测点；不代表 1000 条独立 MQTT 连接、50 个独立身份或 50 个真实浏览器的渲染容量。测试为草稿订阅容量，固定发布范围及撤销另以真实依赖回归验证；未将固定发布的额外票据校验开销外推为同样容量通过。5 秒为本轮工程观察门槛，正式业务延迟指标、长时稳定性及现场签收仍待。

## 实施与可靠性边界

| 修改 | 原因与实际行为 |
| --- | --- |
| 应用共享有界持久接收池 | 接入回调原为串行；新增固定线程池、有界队列、单连接在途配额。默认 8/256/16，本次接入部署显式使用 16/256/16，单载荷仍限 64 KiB；取得名额后只复制一次载荷 |
| 确认及生命周期 | 排队不确认；持久接收成功后复核原租约代次及活动状态，确认与关闭互斥，关闭幂等；饱和、失租约、异常或关闭时保留未确认消息供持久会话重投 |
| 发布结果回写 | 实际线程栈确认 Kafka 网络线程在执行接收记录结果更新；回写复用同一个有界池，满额或关闭时回退完成通知线程，保留原始结果、不丢弃、不自动重发；关闭排空已有结果任务 |
| 通用有界 Kafka 分发 | 新增 `wx.websocket.sender-kafka.max-pending`，默认 0 保留同步语义，1～4096 开启有界待确认；本批三维使用 1024。完成通知释放名额，满额最多等待 5 秒，失败按原快照补偿合同处理 |
| 会话校验流水线 | 原逐会话 Redis 往返改为每批最多 128 项流水线；仍逐项比较完整登记值，保留票据、租户、域、场景、点位及期限校验，缺失/替换会话不投递 |
| 高频日志 | 成功发送改为调试元信息，不再每帧输出完整正文；未降低错误日志或可靠性约束 |
| 数据库池容量 | 隔离接入与最终常驻接入显式 `spring.datasource.dynamic.druid.max-active=24`，配合 16 工作线程。数据库持久化参数保持 `innodb_flush_log_at_trx_commit=1`、`sync_binlog=1` |

合同和配置边界见[设计第 12 节](../../design/06_IoT定向WebSocket推送交付设计.md#12-千设备容量目标与持久接收优化边界2026-11-17)。未修改 Web/Unity 源码、发布静态文件、数据库表结构或原物联网设备映射。

## 持久对账、恢复及原发布回归

本批累计 **77520 条测试消息全部为 PUBLISHED**，无 CLAIMED/FAILED/DEAD_LETTER，见[最终对账](inbox-final.json)。该累计包含成功、失败阶段已经由代理确认的消息和两次恢复尝试；不以最终落库代替每轮实时投递完整性。

恢复演练停止本轮隔离接入，排队 10 条消息后重启隔离 MQTT 与接入容器。首轮脚本要求收到每个中间状态而超时，后台对账证明全部 11 条当时消息已发布、最新值 `100011` 正确，见[首次尝试](recovery-attempt1.json)及[超时后独立查询](recovery-after-timeout.json)。并发处理同点位突发报文时，较新版本先投影会抑制随后到达的旧版本，这是既有当前态防回退合同，不等于接收记录丢失；未为通过测试而更改该业务规则。

按持久完整性与最新状态合同复验：**约 22.621 秒恢复，12 条接收记录完整，最终值 `100012`、状态版本单调、0 重复、同一 WebSocket 保持**。本轮收到 4 条状态更新，中间旧状态按版本被抑制，见[恢复报告](recovery.json)。共享主机未重启，不能替代断电、Kafka/Redis 整机或备份恢复。

常驻切换后复用原场景及固定发布进行真实 MQTT 回归：错域/实例/点位、旧发布借用新组件、伪造租户均拒绝；重复只新增一条 Inbox，迟到不回退，重连查询补齐，单票据撤销后查询与推送均停止，温度最终 29.5、开关 true。见[发布回归](published-regression.json)。本批未重做 Unity 画面或浏览器渲染验收。
