## 真实产物来源与限制

原始资源来自2026-10-28用户现有Unity生成工具/工作台产出的普通汽车，其旧发布摘要为 `sha256:7afc01c33690d48dc872bb4282f55e2ee8f1efa09124272aa0e4a8ec5b6483b7`。验收通过原HTTPS样本入口获取包、原生根清单、包清单和目录，逐项核对已有大小与SHA-256，再包装新稳定ID的单资源主清单；没有伪造或修改原生模型包。

新接口的B/D/E/F内容只修改资源目录中的显示元数据，保留真实模型包原始字节。这证明同ID内容切换与失败保护，不证明车身材质改变、灯光画面或植被效果。灯光关联使用本地正负结构测试，真实烘焙效果仍须ART-06B验证。

本轮新接口由验证脚本调用，不等于Unity工作台按钮已经适配；工作台正式生成、发布回显、运行时按ID消费及浏览器画面属于ART-04/05/06。服务端验证原生包UnityFS标识、字节摘要和声明依赖关系，不在Java进程内冒充Unity解析器，也不替代Player的实际兼容性、Shader和材质加载验证。

## 事务与不可变规则

- 同操作UUID先绑定完整上传计划，相同计划可重签，不同键/大小/摘要拒绝。计划保存在现有操作表JSON，客户端只获5分钟暂存PUT地址；服务端不向客户端提供冻结前缀写能力。
- 主清单原文严格UTF-8、拒绝重复字段/多根文档；大小、SHA-256、稳定资源ID、平台和兼容信息一致后，验证完整文件集合。包图与资源图拒绝悬空和循环依赖，资产引用与包内声明对应；兼容既有Unity的 `sha256:` 表示及资产路径大小写。
- 文件IO在事务外，按流处理。每次验证分配独立冻结前缀，暂存及最终对象均回读校验；暂存变化不能影响已提交内容。最终对象存在即拒绝覆盖。
- 操作使用VERIFYING状态、15分钟验证租约和唯一尝试编号，避免长时间持数据库锁。相同操作正在验证时返回进度；租约允许中断后重试，旧尝试不能越过状态及尝试编号检查提交。
- 最终短事务锁定当前资源和操作，再次鉴权、检查未删除/目标范围/预期修订，一次更新当前指针、关联目录、前后快照和COMMITTED回执。修订冲突记CONFLICT；IO或数据库失败不改变旧指针。数据库不可用且失败回执也无法写入时依赖租约恢复，不伪造成功。
- 包依赖、材质/贴图和灯光关联随同不可变清单被当前指针原子引用，不为每个依赖重复建立业务资源或整版版本表。目录显式关联保留原文件字段；删除与恢复时目录状态纳入同一数据库事务及快照。
- 旧冻结内容与失败产生的孤立对象不自动物理清理；保留与垃圾回收仍按ART-08处理。验收仅清理独立测试前缀及自身记录。

## 数据库故障和回退

真实MySQL失败测试临时建立一个只针对随机验收资源的触发器，在写COMMITTED回执时故意报错，验证同事务的指针/修订回滚，随后删除触发器并以同一操作重试成功。触发器已删除，不影响其它资源；永久库结构仍82表。

服务回退备份路径见部署记录，恢复旧程序与配置并重建三维服务即可回退程序。但新操作与资源历史不能靠降级删表清除，后续应保持向前兼容；本轮真实验收记录已清理，不代表未来正式上传数据也能随程序回退撤销。
