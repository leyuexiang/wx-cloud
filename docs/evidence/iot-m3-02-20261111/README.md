## 待用的单条消息样本

在测试租户准备一个默认停用的 MQTT 连接器。绑定外部设备 `iot-pilot-sensor-01` 到内部设备 `iot-pilot-device-01`，映射版本为 `pilot-v1`。把 `rawTemperature` 映射到 `temperature`，使用数值类型、倍率 1 和偏移 0。测试使用获准的独立主题，服务质量等级（QoS）为 1，关闭消息保留（`retain=false`）。

```json
{
  "externalDeviceId": "iot-pilot-sensor-01",
  "pointCode": "rawTemperature",
  "value": 26.125,
  "valueType": "NUMBER",
  "unit": "°C",
  "quality": "GOOD",
  "eventTime": "<发送时的 UTC ISO 8601 时间>",
  "traceId": "<本轮唯一追踪编号>"
}
```

发送前替换时间与追踪编号。回读接入服务生成的 `eventId`，核对同一事件的接收记录 `PUBLISHED`、Kafka 主题 `twin.event.v1` 的分区和偏移、Redis 中该租户和内部设备的 `temperature=26.125`，以及授权查询结果。重复用例重发同一份报文。清理时停用连接器并解除测试绑定，保留消息与审计记录。[上行配置与报文合同](../../guides/01_MQTT上行接入与联调.md)

## 执行前缺项

- MQTT 需要从 246 可达的通用消息代理 TLS 地址和信任链、确切主题、发布身份、订阅凭据引用以及客户端编号约束。设备或边缘网关直接向该测试主题发布。
- Kafka 需要 246 生产端与 148 三维消费端均可达的地址，以及源主题、消费组和死信主题权限。若使用隔离验证环境，先固定容器、地址和主题范围，再对候选服务启用上行及投影。
- 状态查询需用已授权测试身份复验 `dimensions:iot-state:query`，并用另一租户验证拒绝或无数据。MQTT、Kafka、投影就绪前，样本保持待执行。
