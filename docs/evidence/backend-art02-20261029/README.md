## 数据与部署回退

接口测试使用明确命名的合成资源/范围夹具；结束后清理这些主资源与操作记录。READY 夹具仅用于范围过滤，不是已上传美术包，也不作为内容提交证明。额外租户和测试身份保留用于复测，密码仅存服务器 `art02-identities.json`、权限 600，不进入本目录；旧 API 回归产生的合成模型记录逻辑删除。

首次候选启动误用了基础镜像入口，已改为显式 Java 入口，失败容器未承接业务。第一次正式替换因配置合并重复根键导致启动失败，自动回退恢复旧程序，见[首次回退](first-rollback.json)；修正为修改已有配置项后第二次部署、健康和两套接口检查通过。备份在部署结果列出的服务器目录，含旧 JAR 和配置，不复制到 Git。

直接访问三维服务与经过网关的内部身份头信任边界不同，不能把网关验证脚本简单改端口后用于验证伪造头。最终 20 项伪造身份回归从原网关执行；三维端口仅监听回环地址，不对外暴露。

## 剩余验收与下一步

当前 `9443` 在监听，但它是原隔离验证路径的 HTTPS 代理，只转发旧样本目录，不能直接用作新资源桶的签名下载入口。服务未配置新 `dim3d.resource.download-endpoint` 时返回 `2030001014`，不降级为 HTTP 或公开桶地址。尚未验证真实资源下载、跨租户下载隔离及签名失效；**这部分仍属于 ART-02 的剩余工作**。

上传目标与内容提交路由只在鉴权后返回未启用错误，不能切换当前指针、物理删除或伪报成功。真实 DELETE/RESTORE 执行和对象校验/原子替换在 ART-03 实现，当前只创建受控操作。旧转换接口在回执返回后拒绝覆盖受管资源，但转换服务本身及其外部文件副作用仍需 ART-03 集成时核验。

下一步先完成新资源桶的受控 HTTPS 入口和真实下载权限检查，达到 ART-02 完整退出，再进入 ART-03。未进行 Unity 或三类模型视觉验收，本轮没有截图。最初 ART-00 的冷启动权限异常和测试许可证有效期仍按原记录保留观察。
