[权限边界](security-checks.json)：独立查看用户不能借用原租户发布票据，返回 `FORBIDDEN`；伪造租户、无订阅权限的握手 HTTP 403，匿名握手 HTTP 401。边界测试原发布的独立票据已撤销，三条登录会话均注销。

## 诊断与位置对照

[日志计数](log-pressure.json)未发现此前逐帧会话未命中记录，不回传业务正文。确认常驻主进程为 Java 且没有缩短信号支持的启动参数后，只在独立诊断轮发送两次线程转储信号，进程继续运行；报告过滤为线程标题、状态及栈，未保存交错的业务日志。[首次栈](diagnostic-thread-1.json)处于订阅准备，[第二次栈](diagnostic-thread-2.json)两个 Kafka 消费线程恰在轮询等待。瞬时栈不足以定位或排除所有服务端热点，不能以此单独认定客户端瓶颈。

为区分发生器运行位置，在测试服务器受限目录复制现有纯 Python 客户端和两个 MQTT/容量工具，未安装或升级系统依赖。对[33 个源文件逐一比较摘要](runner-equality.json)，全部一致。客户端版本 1.9.0，工作站为 Windows/Python 3.13.12，测试主机为 Linux/Python 3.13.13；[主机运行信息](runtime.json)保留工具摘要。运行时、网络路径及主机资源不是同一条件，不能把这次位置对照写成单因素因果实验。

首次服务器发生器打包漏掉 `probe-mqtt.py`，子进程在发送前退出：[失败报告](host-smoke-missing-helper.json)为零发送、50 张票据撤销、50 会话注销。补齐原文件后用新的报告名称复测，没有覆盖失败记录。[本机短测](host-smoke.json)100000 次推送完整，P95 71 毫秒。

工作站以太网协商为 1 Gbps；[8 MiB SSH 测量](transfer-check.json)包括建连开销，仅约 64 Mbps，不能当作持续吞吐上限。随后[32 MiB 随机流](transfer-steady.json)首字节前约 1.098 秒、正文约 0.361 秒，持续约 744 Mbps，不保存载荷。这是单条未压缩 SSH 流，不能代替 50 路 WSS/线程接收能力，也不能据此认定物理带宽不足或网络没有影响。
