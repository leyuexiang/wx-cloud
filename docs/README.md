# 后端项目总览与进度口径

核对日期：2026-10-21。用途：提供后端规则、整体设计、专项计划和验收记录的统一导航。

## 目录结构

```text
docs/
├─ README.md       文档总览、当前目标与进度口径
├─ rules/          后端开发规则
├─ design/         平台架构及各专项设计
├─ plan/           总里程碑与专项当前进度
├─ guides/         部署、联调及工具操作手册

└─ records/        版本验证记录与文档迁移记录
```

根目录 `AGENTS.md` 和 `README.md` 保留为工具及仓库入口，详细项目文档统一放在本目录。数据库 SQL、运行配置和构建资源仍位于对应业务目录。

## 1. 整体目标

后端按事件驱动的数字孪生体系演进：外部数据接入 → 统一身份与数据模型 → 内部事件分发 → 三维状态与规则判断 → 告警处置流程 → 受控命令及执行回执。同时维护既有平台业务、场景资源及植被生成等服务，采用兼容接口和分域迁移，避免以单项改造替代全平台目标。

整体目标和服务边界继续维护在[全栈改造路线图](design/00_数字孪生平台全栈改造路线图.md)，本文件负责导航，不另写一份平行总体设计。规则解决“怎么做”，设计解决“做成什么”，计划解决“按什么顺序”，验收记录说明“实际完成到哪里”。

## 2. 开始任务时的读取顺序

1. 根目录 [AGENTS.md](../AGENTS.md) 与[后端开发规则](rules/01_后端开发规则.md)。
2. 本总览与[后端里程碑台账](plan/01_后端里程碑与进度台账.md)，定位当前工作和交付来源。
3. 本次相关的专项设计、当前进度和验证记录；进入子目录后检查其规则。

只读取本任务所需专项，不把所有历史规划变成每次执行的前置条件。

- Git 提交、远端分支同步、其他工作树和实际部署分别记录；推送代码不代表应用已部署或实际依赖已经验收。

## 5. 阶段编号和状态口径

平台路线图原“阶段 0—7”对外引用为 `PLAT-P0—PLAT-P7`。IoT 动态多连接方案原 `M0—M5` 对外引用为 `IOT-M0—IOT-M5`。这是引用别名，不要求改动原节点含义；其他专项新增节点使用自己的前缀，避免混算。

| 状态 | 定义 |
|---|---|
| 待核验 | 有历史代码或规划，但没有足够证据确定该节点交付范围 |
| 待实施 | 目标明确，已知尚未实现相应交付 |
| 进行中 | 当前正在推进，且只有部分交付或部分验证 |
| 已实现待验收 | 已核验到对应代码，约定验收尚未完成 |
| 已验收 | 约定条件已满足，记录范围、基准和可定位证据 |
| 受阻 | 指定下一步缺少必要输入或环境；写明条件和可继续的独立工作，不把整个项目笼统判为受阻 |

## 6. 证据与百分比

证据分别注明静态检查、编译、测试替身、真实依赖联调、实际部署或业务验收。报告至少保留日期、工作树与提交/差异基准、命令或步骤、成功/失败/跳过数量、未验证范围及可定位结果。临时目录中的报告只作为本地记录，跨环境复核前需归档可重放的稳定摘要或结果。

IoT 及三维代码回归的最近结果见[管理接口验证记录](records/04_20261021连接器管理接口验证记录.md)，M1 历史结果见[动态多连接验证记录](records/03_20261020动态多连接验证记录.md)，专项摘要同步到 IoT 进度。必须区分历史结果与本轮实际复跑，不将本地测试替身通过解释为动态多连接或整个后端可部署。

当前不提供整个后端的百分比。此前“约 40%”只属于 IoT 专项粗估；“主线约 65%”也不是完整项目验收率。全局以范围清楚的专项节点和验收证据汇报。确需百分比时，先冻结范围、权重和完成条件，再给出计算方法与日期。

## 7. 更新方式

专项细节先更新其来源，总台账仅同步跨专项状态和下一步。归档旧记录时保留日期和范围，不删除尚未解决的风险。新增文档按上述目录分类并同步本表；经用户要求迁移文档时，同步所有仓库内引用、相对链接及迁移记录，保持业务代码和 SQL 原位。
