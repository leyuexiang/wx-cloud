# 单资源上传与替换事务实现（ART-03）

2026-10-29已在测试服务器接通。总体数据/API合同沿用[设计15](15_资源模板数据结构与接口合同.md)，本轮复用82表结构，不新增永久表。

## 调用顺序

1. `POST /admin-api/dim3d/resource-operations`：按CREATE/REPLACE/DELETE/RESTORE创建操作，取得稳定资源ID。替换/删除/恢复带预期修订。
2. CREATE/REPLACE构建 `wx.art-resource.v1` 主清单和全部包、目录、依赖及必要灯光文件。
3. `POST /resource-operations/{operationId}/upload-targets`：固定该操作的完整文件计划，返回短时HTTPS PUT目标。大小必须为整数，摘要为小写64位SHA-256，路径严格相对；计划不可改。
4. 上传全部文件到暂存；不要把签名URL或凭据写入清单、数据库或日志。
5. `POST /resource-operations/{operationId}/commit`：提交清单路径/摘要、内容摘要、格式、平台和兼容标识；DELETE/RESTORE为空对象。服务端独立回读与校验、冻结到独占前缀，再短事务提交。
6. 状态为VERIFYING时查询原操作，不创建另一资源；COMMITTED及提交修订是成功依据。响应丢失后重试同一操作/载荷，不重复递增；CONFLICT须刷新当前描述并创建新的操作。

文件上传HTTPS入口9445只代理暂存前缀，读取入口9444只读私有桶；两者都保留S3签名所需Host，不记录签名查询串。当前证书和跨域是测试配置。

## 一致性和限制

上传地址仍可在有效期内重放，因此最终内容必须复制到未向客户端开放写入的新前缀。冻结后的字节二次校验，数据库当前指针、目录关联、快照与成功回执同事务提交。失败保留旧指针，旧对象和孤立内容按保留策略延迟清理。

操作JSON保存 `filePlan`、固定 `commit`、验证尝试编号和租约；没有新增业务版本表。验证租约15分钟，整个操作沿用一小时截止时间，文件与摘要工作不长时间占用数据库锁。服务器中断后可按同一载荷恢复；取消不假称能终止已经在验证中的事务。

首期灯光只接受固定BakedWorld布局、非方向性纯烘焙；检查模型键/精确内容标识、贴图角色、Renderer集合、图集索引、UV、有限且可逆仿射矩阵。混合、方向和Shadowmask等尚未支持的模式拒绝。Java只检查原生包基础标识、摘要与声明关系；真正Unity解析、材质/Shader和画面必须在兼容Player上验收。
