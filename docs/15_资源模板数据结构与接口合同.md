# 资源模板数据结构与接口合同（ART-01）

更新日期：2026-10-29。本文固定单资源数据与接口合同；接口在 ART-02/03 实现。ART-01 的结构迁移、回退和离线合同验证不等于权限接口或资源热更全链路通过。

## 1. 核心约定

- 资源是可复用模型、材质、贴图、必要灯光及依赖的完整闭包，不关联项目。
- `wx_dim3d_resource.id` 是稳定业务资源 ID；替换只改变当前内容。内部 `current_revision` 用于并发，内容摘要用于一致性和缓存，均不要求业务用户选择版本。
- 新接口的 ID、租户和修订使用规范十进制字符串，服务端按有界 `Long` 校验，避免浏览器大整数失真。
- 同一场景加载上下文固定某个资源的描述；已有 A 实例保持 A，新上下文或场景重新打开按原 ID 取得当前 B。不同资源无需形成整库版本。

机器可读合同：[接口规范](../contracts/art01/openapi.yaml)、[JSON 数据结构](../contracts/art01/resource-contract.schema.json)、[示例](../contracts/art01/examples.json)、[错误码](../contracts/art01/errors.json)。示例摘要、资源 ID 和域名是说明数据，不是已上传资源。

## 2. 现有数据关系与兼容边界

完整字段、类型、默认值、索引及外键见[资源相关表结构清单](16_资源相关表结构清单_ART01.md)。源码与测试库核查发现：

| 现有领域 | 已核实关系 | 本轮处理 |
| --- | --- | --- |
| `wx_dim3d_resource` | 旧转换接口存储转换回执的 ID、名称、类型、资产名和相对路径 | 主键和旧字段不改名；新增当前内容能力 |
| `wx_dim3d_model.model_file_id` | 前端模型上传将转换接口 `data.id` 写入该字段，随后按它请求资源详情 | 保留旧字段；仅在资源确实存在、同租户、双方未删除时回填 `resource_id` |
| `wx_dim3d_icon.icon_file_id`、目录封面 | 前端使用普通对象存储接口返回的 `ossId` | 不认作资源主键，也不能无证据认作本地 `wx_infra_file.id`；新后端并未实现该旧 OSS 合同 |
| `wx_dim3d_template.template_file_id` | 旧模板/业务快照域有独立编号与恢复语义 | 保留；新增关联仅供可复用资源模板使用，不把业务场景快照当模型闭包 |
| `wx_resource`、`wx_resource_info` | 旧整数主键和 `unique_id`/项目/平台/路径字段；不是转换资源 ID 的别名 | 原数据及接口保留，按旧命名空间审计和显式映射，不按数字相同合并 |
| `wx_resource_info.art_res_version_id` | 旧版本字段对应 `wx_resource_version` 领域，当前无数据库外键 | 保持兼容；不要求新单资源更新使用它 |
| `wx_infra_file`、旧文件/材质/图标表 | 各自保存文件或旧业务信息，没有通往新资源主表的自动外键关系 | 保留原职责，资源闭包中的包/贴图/灯光通过清单描述，不按依赖重复建立业务资源 |

调用证据包括三维前端 `jtyf-web-three/src/views/resourceManage/modelManage/AddDialog.vue` 的模型转换回执、`src/servers/manual/dim3d/api/resource.ts` 的详情请求、图标上传的 `ossId`，以及本后端 `Dim3dResourceCatalogServiceImpl` 的 `convertAndSave`。前端声明的旧详情/OSS 路由不表示本后端已实现或可用。

迁移前测试库资源主表、旧资源域和文件表均无记录；模型目录有 5 条、全部逻辑删除，有效目录为 0。旧 `metabase_3d` 的 7 条资源不在此次迁移内。完整核查见[迁移前结构](evidence/backend-art01-20261029/schema-before.json)与[引用核查](evidence/backend-art01-20261029/reference-audit.json)。

三类目录新增可空 `resource_id` 并建立索引，旧字段继续存在。关联由受控事务维护；旧目录请求中的 `resourceId` 只读且不能插入/更新，防止旧增改接口绕过新事务改绑。模型回填显式保持原 `update_time`。

新资源列表直接读取资源主表，不强制为每个 Unity 资源创建一条旧模型或场景模板目录。旧消费者尚不支持 AssetBundle 时，不能把新包当成旧 GLB 地址返回。目录与资源存在关联时，新事务必须验证范围、租户、类型并维护一致性。

## 3. 租户与管理员合同

保留资源域 `tenant_id varchar(20)`，暂不修改整个系统的字段类型。新增资源统一规范化：

| 范围 | 存储归属 | 读取 | 上传、替换、删除 |
| --- | --- | --- | --- |
| `GLOBAL_SYSTEM` | `tenant_id='0'`，专用全局资源哨兵，不是登录租户 | 已登录且可使用编辑器的租户用户 | 平台超级管理员 |
| `TENANT_SHARED` | 认证租户 ID 的无前导零正十进制字符串，最大为 `Long.MAX_VALUE` | 当前租户用户 | 本租户超级管理员 |
| `resource_scope IS NULL` | 保持旧值，包括 `000000` | 不进入新可消费查询 | 先审计分类，不自动扩大授权 |

平台管理判定必须同时满足：认证用户真实租户等于受信配置 `dim3d.resource.platform-tenant-id`，并由系统权限服务确认拥有启用的 `super_admin` 角色。测试环境对应平台租户 `1`；配置缺失时拒绝全局写入。不能只看请求头或任意租户创建的同名角色。

租户管理判定使用可信认证租户及系统权限服务确认的 `tenant_admin`，且目标必须是本租户共享资源。平台身份不自动赋予其它租户资源维护权。请求体不接受 `tenantId`、`operatorId`、角色或项目归属；只有创建时可声明拟创建的范围，服务端仍须授权并确定所有者。

新读取的基本谓词为：未逻辑删除、`content_state='READY'`，并且 `(resource_scope='GLOBAL_SYSTEM' AND tenant_id='0') OR (resource_scope='TENANT_SHARED' AND tenant_id=认证租户)`。列表、详情、上传任务、操作状态和下载授权须一致。全局查询只能通过专用且显式带范围条件的方法临时处理租户拦截；不把整个模块加入忽略表。

操作状态仅向该操作的认证操作者开放，且操作者仍需具备当前维护权限；不能通过知道 UUID 读取其它租户操作。取消、提交和恢复再次鉴权。权限撤销、换租户或资源删除后，不能继续利用旧上传任务提交。

## 4. 新数据结构

`wx_dim3d_resource` 增加 11 个字段：

| 字段 | 类型 | 作用 |
| --- | --- | --- |
| `resource_scope` | `varchar(20) NULL` | 显式范围；旧数据默认空 |
| `content_state` | `varchar(16) NOT NULL DEFAULT 'LEGACY'` | `LEGACY/PENDING/READY`；替换时旧 READY 保持可读 |
| `storage_prefix` | `varchar(512) NULL` | 当前不可变对象前缀，不含签名 |
| `manifest_path` | `varchar(512) NULL` | 相对前缀的清单键，例如 `manifest.json` |
| `manifest_sha256`、`content_hash` | 各 `char(64) NULL` | 小写十六进制清单字节摘要、完整闭包摘要 |
| `content_format` | `varchar(32) NULL` | 首期 `unity.assetbundle.v1` |
| `platform` | `varchar(20) NULL` | Unity 平台标识 `WebGL`，实际画面以 WebGPU 验收 |
| `app_compatibility` | `varchar(128) NULL` | 精确 Player/管线/协议兼容身份 |
| `current_revision` | `bigint unsigned NOT NULL DEFAULT 0` | 内部并发修订；服务端限定有界 Long |
| `current_operation_id` | `char(36) NULL` | 最后提交的操作 |

新建 `wx_dim3d_resource_operation`，以 UUID 为主键，保存稳定资源 ID、操作类型、资源范围/租户/操作者、请求摘要、预期/提交修订、状态、候选描述、前后快照、错误码和截止时间。目录/依赖/灯光的必要关联纳入同一次提交的快照；签名 URL、访问密钥和令牌不入快照。

操作表外键约束资源存在；主表 `(id,current_operation_id)` 复合外键指向操作表 `(resource_id,id)`，防止当前指针关联到另一资源的操作。应用层仍须在同一事务中保证操作已提交、范围/所有者一致，不能把数据库外键当作授权校验。

数据库还约束范围值、规范所有者、内容状态、摘要格式、READY 必填字段，以及 COMMITTED 操作须有后快照并满足 `committed_revision=expected_revision+1`。新资源初建为 PENDING；上传任务过期不影响其它已可用资源。操作进度与资源状态分开，不设整库激活记录。

持久化类使用独立 `Dim3dResourceCurrent`、`Dim3dResourceOperation` 和映射器；旧转换接口仍使用 `Dim3dConvertedResource`，不接受外部转换回执覆盖新的受控字段。ART-02 必须封堵旧接口对已纳入新流程的资源和关联的旁路更新；在此之前不启用新资源提交。

## 5. 接口路径与响应

以下是固定合同；ART-02/03已部署，资源文件逐项签发接口随ART-05运行时接入补充。API基路径为 `/admin-api/dim3d`。

| 方法与路径 | 职责 |
| --- | --- |
| `GET /resources?pageNum=1&pageSize=20` | 可见 READY 资源元数据列表，单页最大 100 |
| `GET /resources/{resourceId}/current` | 当前描述和经过鉴权的短时 HTTPS 清单地址 |
| `GET /resources/{resourceId}/file?revision=...&contentHash=...&path=...` | 按场景固定的修订和内容摘要定位已提交快照，复核资源现时可见性及清单成员，再签发短时HTTPS地址；旧上下文续签不跟随当前指针。主清单也可续签，清单外文件不能签发 |
| `POST /resource-operations` | 创建 `CREATE/REPLACE/DELETE/RESTORE` 操作；操作 UUID 同时作为幂等身份 |
| `GET /resource-operations/{operationId}` | 查询进度和提交结果；用于响应丢失后的安全重试 |
| `POST /resource-operations/{operationId}/upload-targets` | 为指定相对键、大小和摘要签发受限 PUT 目标；不得覆盖不同内容 |
| `POST /resource-operations/{operationId}/commit` | 校验并提交；CREATE/REPLACE 提交候选描述，DELETE/RESTORE 仅提交空对象 |
| `POST /resource-operations/{operationId}/cancel` | 取消未提交任务；已提交时返回状态冲突，不伪报取消成功 |

成功保持当前工程 `CommonResult {code:200,msg,data}`；不能按 `code=0` 或仅 HTTP 200 判定成功。业务异常沿用项目错误封装、`data=null`，入口还可能返回 HTTP 401/403。新增领域错误使用 `2030001001`～`2030001019`，详见[错误码](../contracts/art01/errors.json)与 `ArtResourceErrorCode`；不修改旧接口错误码。

创建时服务端分配稳定 ID。已有转换 ID 原样保留；新 Unity 资源复用工程的雪花编号分配机制，集群部署须配置唯一工作节点，主键冲突不得覆盖其它资源。CREATE 操作重试返回原分配结果，不重复建资源。REPLACE/DELETE/RESTORE 必须携带 `resourceId`、`expectedRevision`，禁止改变范围或所有者。

文件键仅允许规范相对路径，拒绝 `..`、`.` 段、重复斜杠、反斜杠、编码路径、协议、查询串和片段。签名目标绑定该操作、前缀、对象键、大小、摘要和有效期；重复键即使摘要不同也要拒绝。每批最多 4096 个对象，单文件上限 2 GiB；整任务配额、签名时长和运行时内存预算在实现时配置并校验，不因上传上限承诺浏览器可同时加载。

## 6. 幂等、校验与提交

1. 创建操作时，后端在认证后固定所有者、操作者、类型、目标和预期修订；对规范业务载荷计算 `request_hash`。同操作 UUID、同载荷返回原结果；异载荷返回幂等冲突，其它操作者不可探测该记录。
2. CREATE 先分配 PENDING 主记录，工作台据此生成带稳定 ID 的闭包。前缀由服务端分配，例如 `resources/{scope}/{owner}/{resourceId}/operations/{operationId}/`。它可以按操作唯一，不要求摘要已知时才分配，也不得原地覆盖当前内容。
3. 上传与文件回读发生在数据库事务外。CREATE/REPLACE 首次 commit 固定候选描述；重试只能提交同一候选。候选规范身份存入 `candidate_descriptor`，其中包含提交摘要，不含短时 URL。
4. 服务端独立核验所有对象、SHA-256、清单、包依赖、平台/运行包兼容、模型与灯光身份及布局。摘要规范必须排除摘要自身和临时授权等自引用/非内容字段；不能只信任客户端报告或 ETag。
5. 最终短事务重新鉴权并核对状态及预期修订，更新当前内容、必要目录关联、前后快照和 COMMITTED 回执。成功修订加一；并发更新或删除导致不匹配时返回冲突，不静默覆盖。
6. 成功但响应丢失时查询原操作，重签下载地址；不能因重试重复递增修订。上传或数据库失败保留旧指针，新孤立对象稍后清理。主清单含完整依赖图，不为未变化的其它资源建立整库提交。

这不是 MySQL 与 MinIO 的跨系统事务。上传对象必须在验证后保持不可变，主指针更新之前不可消费。内容 A 在旧上下文仍有引用时，不立即删除其对象。

RESTORE 只允许本资源已提交的受控快照，须重新验证对象及兼容性，并以当前预期修订产生新操作；不是业务版本选择。DELETE 同样使用操作和一次事务，逻辑删除、修订加一、保留完整快照；停止新增消费，不改写现有实例。目录已关联时在同一事务下线或逻辑删除，不能留下可用目录指向不可读资源。

### 6.1 主清单与跨语言摘要规则

主清单使用 `wx.art-resource.v1`，完整结构在 JSON 合同的 `resourceManifest` 中。主清单必须列出稳定资源 ID、内容/兼容身份、入口及完整文件集。`entry` 包含资产名、类型、包、原生根清单、资源目录和包清单路径，可选灯光清单路径；所有路径都必须出现在文件集中，依赖图和灯光关系在被摘要保护的子清单中核验。

`manifestSha256` 是最终主清单原始字节的 SHA-256，由数据库描述提供，不能写进主清单形成自引用。`contentHash` 的计算规则固定为：

1. 解析严格 UTF-8 JSON，拒绝重复属性、未知属性和不符合结构的值；主清单不把自身路径列入 `files`。
2. 从根对象去掉 `contentHash`，其它已声明字段全部参与摘要；`files` 按相对路径的 ASCII 序排序，重复路径拒绝。
3. 所有对象的键按序排列，输出无多余空白的紧凑 JSON；字符串按 JSON 标准转义引号、反斜杠及控制字符，其余 Unicode 直接编码 UTF-8，不额外做 Unicode 归一化，不输出 BOM。
4. ID、文件大小等数值以规范十进制字符串表示；根摘要输入不含浮点数。对上述 UTF-8 字节计算 SHA-256，输出小写十六进制。灯光矩阵/UV 等浮点数保留在子文件，按子文件原始字节摘要保护。

规范示例见[摘要夹具](../contracts/art01/content-hash-fixture.json)，同时提供含中文资产名的规范字节十六进制与期望摘要。Unity 和 Java 实现都须与夹具一致；签名地址、任务时间和存储前缀不属于主清单，不参与内容摘要。主清单自身可有不同字节排版，但实际下载必须匹配该次 `manifestSha256`。

## 7. 删除、保留与旧数据

首期不自动物理删除旧闭包或快照。对象清理默认关闭，ART-08 按受控保留期、当前指针、未完成操作和可恢复快照核验后启用；当前及仍受保留保护的对象不得删除。浏览器实例释放由句柄所有权负责，不等于存储侧可以立即清理。

被逻辑删除资源的新查询返回不可消费结果。场景重进若遇到缺资源或被删资源，保留原实例载荷并报告，阻止破坏性保存；不承诺删除资源后场景仍能完整还原。旧资源归属未确认时保留在旧读取域，新接口不扩大可见性。旧存档/项目命名空间下的键在 ART-07/08 显式映射，不能直接拿目录 ID 或 `unique_id` 充当主资源 ID。

## 8. 迁移与验收边界

迁移位于 [ART-01 迁移目录](../deploy/test148/migrations/art01/README.md)，执行器为 `deploy/test148/migrate-resource-art01.py`。结构与数据回填分文件，已部署的初始 81 表脚本保持原样。执行前备份完整测试库，备份只存服务器受限目录；原库 `metabase_3d` 不变。

回退只允许在新写入未启用且无新内容/操作/后续关联改动时执行；否则拒绝删除列和操作历史，使用前向兼容迁移。未来启用新接口后，回退前必须关闭写入并确认无在途请求，不能只靠检查计数消除竞态。
