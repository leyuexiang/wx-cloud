## 本轮优先修复：数值换算参数校验

现有换算公式为 `value × scale + offset`。Jackson 对非数字节点调用 `decimalValue()` 可能返回零，从而将非法配置静默转换成错误遥测值。

处理方案：保持既有映射结构及默认行为。参数缺失或为 JSON null 时沿用 `scale=1`、`offset=0`；显式配置必须为 JSON 数字，否则返回现有 `POINT_MAPPING_INVALID` 错误。数值仍使用 BigDecimal，避免引入浮点误差。校验只访问常量数量的字段，不增加数据库查询或循环。

测试先覆盖原样透传、十进制换算、默认值，以及字符串、布尔值、对象、数组等非法参数；观察旧实现失败后再修改实现。该修复仅保障现有点位换算行为，不代表完整链路已验收。

## 接入与重放异常一致性加固（2026-10-17）

### 问题与处理边界

当 Kafka 发布方法同步抛出异常后，接入服务和人工重放服务会尝试记录失败。如果此时数据库也不可用，原实现会将数据库异常返回给调用方，丢失原始 Kafka 发送错误。

继续复用现有发布及状态接口，不增加新数据库操作：首先尝试记录失败；落库失败时将记录异常添加到原发送异常的附加异常列表（suppressed exceptions），再抛出原发送异常。同一异常对象不得添加到自身。数据库不可用时不保证状态立即更新，仍依靠既有 CLAIMED 超时重新抢占机制恢复；不自动重发消息，也不把落库失败视为发布成功。

### 测试范围

- 使用真实 ObjectMapper 验证事件快照可序列化、反序列化并重放。工程启用了构造参数信息，当前测试尚未发现构建器模型的反序列化问题，不更改事件结构。
- 重放保留事件编号、事件时间；租户取记录而非快照；不允许已发布事件、错误快照或抢占失败后继续发布。
- 遥测以设备绑定为主数据，应用映射后才投递；重复输入编号稳定，未取得令牌不重复发送。
- Kafka 确认前不标记成功；异步失败只记录失败；回调携带原始租户与抢占令牌。
- 同步发送与失败状态落库同时报错时，保留两个故障。数据库插入故障不能进入重复消息处理分支。

测试使用模拟数据库与 Kafka 验证编排行为，不替代真实数据库租户拦截器、Kafka 网络和 SQL 的集成验收。

## 异步状态回写故障可观测性

### 问题

首次接入和人工重放通过 `whenComplete` 更新 Inbox 状态，但没有消费该方法返回的异步结果。数据库回写抛错时，异常被保存在无人观察的 Future 内，接口通常已经返回，运维无法仅凭服务日志定位此故障。

### 处理方案

在两条既有异步回调内捕获状态更新的运行时异常，记录错误级别日志及堆栈，携带事件原始租户、事件编号和 Kafka 是否确认成功。不能读取回调线程的当前租户作为日志归属。日志不主动写入遥测原文、签名或凭据。

保持现有数据库状态与恢复语义：不因成功回写失败而改记发送失败、不在回调中自动重发、不增加数据库查询、不阻塞接入线程。数据库无法更新时记录可能保持 CLAIMED，由原有五分钟超时抢占机制在后续投递时恢复；该机制不是自动定时重试。Broker 已确认但数据库未记录的窗口仍可能发生重复发布，下游需要基于事件编号幂等处理。

仅捕获运行时异常；严重虚拟机错误不作为普通数据库故障处理。同步发送失败继续沿用原异常加附加异常的传播行为。

### 验证

分别覆盖首次接入和人工重放，以及 Kafka 成功/失败的四种组合。使用真实延迟完成的 Future，在完成前更换线程租户，检查日志始终归属于原始事件。日志测试的监听器必须在 finally 中解除并停止，避免污染其他用例或累积引用。

### 验证结果

四个新增场景在修复前全部因异步落库错误未记录而失败；修复后连同原有 30 项，共 34 项测试全部通过、无跳过，Maven 构建成功。独立代码审查和差异格式检查通过。本轮未修改服务器，尚未完成真实数据库故障注入与 Kafka 集成验收。

## Inbox 软归档（2026-10-18）

- 新增 `archivePublishedBefore(before, batchSize)` 服务能力，使用当前租户上下文执行单批更新。
- 仅将 `PUBLISHED` 且 `received_at` 早于截止时间的记录改为 `ARCHIVED`；`FAILED`、`DEAD_LETTER`、`CLAIMED` 不会被归档，失败事件仍可人工重放。
