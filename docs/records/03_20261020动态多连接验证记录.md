## 4. 验证证据的边界

- 动态管理器的两路回环协议替身使用真实 Paho 客户端，分别接收 QoS 1 报文并在接收完成后发送确认；不替代完整 MQTT Broker 的持久化、权限、证书及进程重投验收。
- 真正阻塞一路建连任务，验证第二路建连和第一路控制续租继续执行；动态发现、版本替换、停用、失所有权、容量与停机采用受控执行器核验。
- 数据库所有权 SQL 通过实际 Mapper 注解解析和条件契约检查，但没有在真实 MySQL/MariaDB 执行。Redis 租约主要使用测试替身，三个三维 Redis 存储交互用例因未指定本机专用端口跳过。
- 编译及回归通过不代表数据库已迁移、跨实例故障已验收或整体物联网闭环完成。
- 文档相对引用、UTF-8、代码围栏和 Git 差异另行检查，最终提交保持一致。

## 5. 升级与剩余工作

旧库部署代码前须先执行 `wx-module-iot/db/iot-connector-runtime-migration.sql`，即使 MQTT 关闭也不能跳过实体表结构升级；新库使用最新 `iot.sql`。操作需备份并遵循既有迁移顺序，本轮没有代为执行。

SINGLE 与 DYNAMIC 不混合滚动部署。动态模式只管理同租户前 N 个连接器，跨实例负载均衡、跨租户分片、后台凭据安全存储、证书管理、管理页面、三维实时推送及下行回执仍待后续交付。配置指纹变化时旧 MQTT 会话积压不自动迁移；停机预算需按实际连接规模验证。
