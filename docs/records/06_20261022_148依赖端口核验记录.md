# 2026-10-22 148 依赖端口核验记录

## 1. 核验范围

- 核验主机：当前开发机到 `192.168.10.148` 的 TCP 可达性。
- 核验方式：PowerShell `Test-NetConnection`，以及一次不带密码的 MySQL 客户端握手。
- 目的：确定真实联调的下一项依赖，不执行数据库写入、迁移、Redis 清库或服务器配置修改。
- 工作树：`master`，此前提交 `74db083a`。

## 2. 结果（2026-10-22）

| 依赖/端口 | 结果 | 结论 |
|---|---:|---|
| SSH `22` | 可达 | 网络路径存在；当前环境没有记录中的 SSH 私钥，未登录服务器 |
| HTTP `80` | 可达 | Web 端口可达，不代表网关鉴权或 IoT 路由可用 |
| MariaDB `3306` | 可达 | TCP 服务响应；使用 `iot_app` 且不带密码返回 `ERROR 1045`，等待应用账号凭据 |
| Redis `6379` | 可达 | 已完成 `+PONG` 和 Redisson/Lua 三项真实测试，详见[Redis 联调记录](05_20261022_148Redis真实联调记录.md) |
| Nacos `8848` | 不可达 | 未确认 HTTP 配置/注册入口，不能进行真实注册验收 |
| Nacos `9848/9849` | 不可达 | Nacos 2.x 客户端通信也未确认 |
| Kafka `9092/29092/9093` | 不可达 | 当前没有可用的常用 Kafka Broker 入口，IoT 事件链路不能联调；MQTT `1883` 入口另见专门记录 |
| Kafka UI `58080` | 不可达 | 不能从当前网络查看 UI；UI 可用也不能替代 Broker 地址 |
| MinIO `9000/9001` | 可达 | 仅确认端口，不在本轮使用或修改对象存储 |
| IoT 应用 `48096` | 不可达 | 当前未确认 IoT 应用已部署并对外监听 |

“不可达”只表示当前开发机到该端口的 TCP 探测失败，可能是服务未启动、只监听内网、网络策略或端口变更，不能单独证明服务器上没有该组件。

## 3. 当前影响

- 148 Redis 已从“历史记录”提升为“本轮真实存储联调通过”。
- MariaDB 只能确认网络和服务端口，尚无应用账号密码，不能执行 `iot-connector-runtime-migration.sql`，也不能验证 MariaDB 10.3 的真实 SQL 兼容性。
- Kafka、Nacos 和 IoT 应用入口尚未从当前开发机打通，不能宣称 MQTT→Inbox→Kafka→三维的真实闭环。
- 不把端口探测或未带密码的登录拒绝写成服务故障；下一步需要部署方提供受限账号、实际入口和网络白名单信息。

## 4. 下一步

1. 由部署方提供 `iot_app` 的临时或正式受限凭据，并确认目标库 `wx_iot`、备份窗口和迁移授权；先只读检查表结构，再评审迁移执行。
2. 确认 Kafka 实际 `advertised.listeners`、认证方式、源主题及隔离主题 ACL；不能继续假设 `9092`。
3. 确认 Nacos 对应用网络开放的地址、命名空间和账号，再做 IoT 注册与配置读取验收。
4. 依赖就绪后按“数据库迁移 → IoT 启动 → MQTT 上行 → Kafka → 三维投影”的顺序联调，保留跨租户负向和重启恢复证据。
