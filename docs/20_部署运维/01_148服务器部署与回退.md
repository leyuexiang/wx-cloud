# 192.168.10.148 部署设计与操作说明

> 文档用途：测试部署操作说明；基线为 2026-10-30，运行状态仍须现场核查。当前执行顺序见 [00 执行总览](../00_执行总览.md)。

## 目的与范围

将当前 `wx-cloud` 源码构建为网关、系统、基础设施和三维四个服务，接管原 `metabase-backend` 的 `12522` 入口。用户已授权切换。源码提交基线为 `58f615f`；本次部署适配另以工作区差异保存。

源码要求 MySQL 8.0.16 以上的校验约束、排序规则及正则函数。现场数据库为 MariaDB 10.3，且已有另一套 WX 系统服务。为保证兼容性，新增独立 MySQL 8 和 Redis 实例，并使用独立业务端口。

本次范围沿用仓库 `deploy/test148` 方案。商城、支付、工作流等可选业务模块没有随核心服务启动。当前仓库提供后端，不包含旧服务的前端站点；旧 `/api/assets` 与当前 `/admin-api/...` 接口合同不同。

## 运行结构

| 组件 | 地址或目录 | 说明 |
| --- | --- | --- |
| 对外网关 | `192.168.10.148:12522` | 验收前使用 `12532` |
| 系统服务 | `127.0.0.1:48181` | 登录、权限、租户 |
| 基础设施服务 | `127.0.0.1:48182` | 文件及基础能力 |
| 三维服务 | `127.0.0.1:48192` | 三维业务与资源操作 |
| MySQL 8.0.44 | `127.0.0.1:13306` | 独立库 `wx_editor_test148`，容器名 `mysql8` |
| Redis 7.4.2 | `127.0.0.1:16380` | 独立密码及数据卷 |
| 资源下载 | `https://192.168.10.148:9444` | 私有桶签名读取 |
| 资源上传 | `https://192.168.10.148:9445` | 仅暂存前缀的上传 |
| 资源读取接口 | `https://192.168.10.148:9446` | 限定来源及读取路由，另含精确登录路由 |
| 发布目录 | `/opt/wx/editor-test148` | 程序包、配置、备份及验收记录 |

网关通过静态地址调用三个服务，不依赖现场已有注册中心。内部服务使用回环地址；数据库和缓存使用独立卷。对象存储复用现场 MinIO，资源使用独立私有桶 `wx-art-test148`。

## 构建与初始化

1. 在仓库根目录运行 Maven 构建，启用 `test148` 配置，选择四个服务及其依赖。运行资源、认证、角色、权限、租户及短信工厂等关键测试。
2. 运行 `python deploy/test148/prepare-config.py`。默认即生成上述隔离端口；可通过 `WX_CONFIG_OUTPUT` 将配置写入独立发布目录。自定义端口时须同时传入生成器环境与服务器 `.env`。
3. 上传部署脚本、迁移目录、配置及四个候选程序包。上传后核对安全散列算法 256 位摘要（SHA-256），将候选文件原子改名为 `jars/system.jar`、`infra.jar`、`dimensions.jar` 和 `gateway.jar`。
4. 在服务器发布目录依次执行：

```sh
python3 bootstrap-server.py
python3 migrate-resource-art01.py apply
python3 seed-test-identity.py
python3 authorize-test-server.py
python3 setup-resource-download.py
python3 setup-resource-upload.py
docker compose -f compose.yaml up -d
python3 verify-api.py
```

切换完成后执行 `WX_API_CLIENT_IP=192.168.10.16 python3 setup-resource-api.py`，为本次验收工作站开放资源读取接口。更换工作站时须显式修改该来源地址。

初始化脚本先备份旧配置、容器信息和旧 MariaDB 数据，再生成受限环境文件，校验编排配置，启动独立数据库并等待 SQL 查询成功，最后初始化新库。原结构 81 张表，执行 ART-01 后为 82 张。迁移前另行备份；迁移执行器保留文件摘要及状态，禁止猜测覆盖已迁移结构。

默认适配现场容器名 `minio`。其他环境可显式指定 `WX_MINIO_CONTAINER`。若存在 `bootstrap/mysql.cnf`，数据库工具将优先使用该私有文件；本次部署使用独立容器，不保留该文件。

数据目录归属通过临时容器读取运行镜像的默认用户确定。现场旧容器覆盖为管理员用户，镜像默认用户实际为 `100:101`；直接沿用旧容器用户会导致新服务无法读取授权文件。该差异已有回归测试覆盖。

## 配置和凭据

密码由服务器生成，保存于权限 `600` 的 `.env`；账号凭据保存在同权限的 `test-identities.json`。仓库和公开验收记录不包含密码或令牌。测试账号为 `wxadmin`、`tenantadmin`、`viewer`。

服务配置生成器保留资源上传、下载、平台租户和模型转换地址，不重新覆盖 `dim3d` 根节点。程序运行使用 Java 17 和 UTF-8。

测试授权通过源码现有生成器生成，默认 30 天；生成后验证真实宿主 UUID 和有效期。再次运行复用已有授权，不自动续期。宿主硬件查询工具位于 `/usr/sbin`，授权脚本显式补齐搜索路径。

传输层安全协议（TLS）入口复用 `/etc/wx/tls/server.crt`、`server.key`；当前证书有效期至 2027-04-23。签发机构证书为 `/etc/wx/tls/ca.crt`，客户端须信任该内部证书颁发机构（CA）。测试始终开启证书链及主机名校验。可通过 `WX_TLS_CERT_DIR`、`WX_TLS_CA_FILE` 显式指定其他证书。

## 切换、验收和回退

隔离入口的 `verification-12532.json` 必须通过。执行 `python3 cutover.py` 前再次校验编排配置；随后停止旧容器，切换新网关到 `12522` 并运行真实接口回归。失败时恢复原环境；即使新网关重建失败，也单独释放入口并启动旧容器。

手动回退命令：

```sh
cd /opt/wx/editor-test148
python3 rollback.py
```

旧镜像保留为 `metabase-backend:before-wx-replacement`，旧容器和旧数据库保留。回退不删除新数据库。网关和业务服务配置保留在发布目录 `config/`，旧数据及旧配置备份保存在 `backups/`。

成功标准包括：四个核心服务健康，真实账号登录，权限和跨租户访问边界，三维目录写入回读清理，私有资源签名及真实下载。验收报告须区分已有单元测试、实际接口验收与未执行的历史样本测试。Unity 历史汽车 A/B 样本不随源码提供，不能将其历史验收报告视为本轮验收结果。

本轮已部署并切换成功：187 项关键 Java 测试、8 项部署单元测试、126 项服务器接口检查及 3 项工作站直连检查通过。四个核心服务健康，旧容器停止保留；原有五个 WX 系统服务仍运行。完整结果见[部署验收记录](../evidence/deployment148-20261030/README.md)。

## 镜像准备

现场 Docker 守护进程的旧代理不可达。为避免影响其他容器，使用独立命名空间的镜像下载工具，经可用代理下载并验证内容摘要，再导出并由 `docker load` 导入。无需重启 Docker。所用镜像固定为 `mysql:8.0.44` 和 `redis:7.4.2-alpine`；部署记录保存实际镜像标识。
