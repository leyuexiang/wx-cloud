# 3.3 技术要求响应及实施方案

> 编制说明：本稿按照招标文件“3.3 技术要求”的原有顺序逐项编制，采用投标技术方案表述。“满足”表示拟交付目标及实施响应，不代表已经取得实测结果。正式投标时，应结合投标产品实际能力、软件授权和测试证据核实响应内容，并补充产品名称、部署配置及证明材料编号。

## 3.3.1 总体技术响应

针对本项目中心云与边缘协同、BIM 模型管理、病害空间定位及三维交互需求，本方案建设集设备接入、模型处理、坐标配准、构件管理、病害管理、三维可视化和开放接口于一体的平台。

系统按照“统一数据标准、统一构件标识、统一空间基准、模块独立部署、云边协同运行”的原则实施。招标文件规定的全部技术参数均作为最低交付要求，具体实现方案、交付成果和验收方法按下列条款对应执行。

### 关键指标响应

1. 模型格式：支持 IFC 4.0 及以上版本模型导入与解析，支持 Autodesk Revit 原生 RVT 文件直接上传、自动转换及导入。
2. 模型规模：支持单文件不小于 500MB 的 BIM 模型上传，支持不少于 10,000 个构件的模型解析、渲染和构件交互。
3. 加载性能：在约定验收环境下，已完成预处理并发布的三维模型首屏加载时间不大于 15 秒。
4. 导入可靠性：标准 IFC 4.0 格式模型导入成功率不低于 95%。
5. 空间精度：模型与现场世界坐标系配准误差不大于 5cm；病害在 BIM 模型中的位置标注误差不大于 5cm，支撑 K3 考核。
6. 数据开放：提供 RESTful API，按照 OpenAPI 3.0 规范交付接口定义、字段说明和调用示例。
7. 浏览器使用：基于 WebGL 实现三维模型浏览和交互，终端无需安装浏览器插件。

## 3.3.2 对应（1）系统架构要求

### 3.3.2.1 分层架构及职责划分

**对应要求：** 系统采用分层架构，各层职责清晰。

**技术响应：** 满足。系统划分为接入层、数据层、平台服务层、业务应用层和展示交互层，并设置贯穿各层的身份认证、权限控制、日志审计及运行监控能力。

**实施方案：**

1. 接入层：负责摄像机、传感器、巡检终端及外部系统接入，完成协议适配、数据格式转换、接入鉴权和数据初步校验。
2. 数据层：对象存储保存原始 IFC/RVT 文件、轻量化模型、视频片段和病害图像；关系数据库保存项目、版本、构件属性、病害记录和映射关系；空间索引支撑构件位置查询；缓存服务保存热点数据与任务状态。
3. 平台服务层：提供模型解析转换、模型发布、坐标转换、构件索引、版本映射、病害关联和开放接口等公共能力。
4. 业务应用层：提供项目管理、模型版本管理、病害复核、安全评级、查询统计及历史追溯功能。
5. 展示交互层：通过浏览器实现三维模型浏览、构件选择、高亮定位、坐标校准、病害标注和列表联动。

各层通过明确的接口交换数据，展示层不直接访问业务数据库，模型转换任务与在线查询服务隔离，避免大文件处理影响日常业务操作。

**交付与验收：** 交付系统架构图、服务清单、接口依赖关系和部署说明，通过部署检查及业务链路演示验证职责划分。

### 3.3.2.2 中心云与边缘网关混合部署

**对应要求：** 支持中心云＋边缘网关混合部署；中心云负责数据存储、智能计算和全局调度；边缘网关负责设备接入、协议转换、视频流处理和本地缓存。

**技术响应：** 满足。系统采用中心云统一管理、边缘网关就近处理的协同架构。

**实施方案：**

中心云部署项目与模型管理服务、对象存储、业务数据库、智能分析服务和任务调度服务，承担历史数据存储、模型处理、病害识别分析、跨网关任务编排及统一权限管理。模型转换和智能计算分别使用独立任务队列与计算资源池，根据任务数量扩展工作节点。

边缘网关部署设备接入适配器、协议转换组件、视频处理组件和本地缓存组件。根据现场设备清单接入相应协议，将设备数据转换为统一消息格式；对视频进行接入、转封装、抽帧及按需转码，按需上传图像、片段和识别任务数据。

云边通过加密链路交换配置、任务、设备状态和业务数据。边缘网关按配置保存设备数据、图像及必要的视频片段；网络中断时按本地缓存容量持续采集并记录待上传队列，网络恢复后执行断点续传和增量补传。上传记录以唯一业务标识去重，按事件发生时间入库；缓存容量、保留周期和溢出策略在部署配置中明确。

**交付与验收：** 交付云边部署拓扑、设备协议清单、缓存策略和同步配置。通过设备接入、协议转换、视频处理、云端任务下发、断网缓存及恢复补传演示验证。

### 3.3.2.3 模块化设计及按需扩展

**对应要求：** 各功能模块独立划分、独立部署、按需扩展，高内聚、低耦合。

**技术响应：** 满足。按设备接入、视频处理、模型转换、模型管理、坐标服务、构件服务、病害服务、可视化服务和接口网关划分模块。

**实施方案：**

各模块分别打包、配置和部署，采用容器或独立进程运行，支持单独升级和故障重启。在线请求通过标准接口调用，模型转换、视频分析及批量映射等耗时任务通过消息队列异步处理。模块使用独立的数据访问边界，不通过跨模块直接修改数据库实现业务协同。

模型转换服务按待处理任务数量扩容；视频服务按摄像机数量及码流负载扩容；业务查询服务按并发访问量扩容。通过健康检查、任务状态记录和可控重试恢复异常任务，避免单一工作节点故障造成全平台中断。

**交付与验收：** 提供模块部署清单，演示模型转换节点独立增减、单模块重启及其他业务持续访问。

## 3.3.3 对应（2）BIM 技术能力要求

### 3.3.3.1 模型格式及导入性能要求

#### 1. IFC 4.0 及以上版本导入与解析

**对应要求：** 必须支持 IFC 4.0 及以上版本的导入与解析。

**技术响应：** 满足。建设 IFC 标准模型导入链路，支持 IFC4、IFC4.3 等交付期适用版本，并在交付资料中明确支持的 Schema 与交换视图范围。

**实施方案：** 上传后首先识别模型 Schema，使用对应版本解析器读取空间结构、构件 GlobalId、几何表达、材料信息、属性集和定位关系。保留原始文件，建立原始构件与轻量化构件的双向索引，并输出解析日志和数据完整性检查结果。对不符合标准或存在损坏的文件输出具体错误位置与原因。

**验收方法：** 使用双方确认的 IFC4、IFC4.3 标准模型进行导入，核查构件树、几何、属性、标识及空间位置是否正确，不以仅能上传文件作为导入成功依据。

#### 2. Autodesk Revit 原生 RVT 格式导入

**对应要求：** 必须支持 Autodesk Revit 原生 RVT 格式导入。

**技术响应：** 满足。用户可直接上传 RVT 文件，由平台自动完成解析转换和模型发布，无需用户先行导出 IFC。

**实施方案：** 建设 RVT 专用转换工作节点，采用依法授权且支持相应版本的 Revit 引擎及 Revit API 执行自动转换。工作节点按实际引擎要求部署在受支持的 Windows 环境，并纳入中心云统一调度。导入过程提取 Revit UniqueId、源文件 ElementId、类别、族类型、属性、几何及共享坐标信息，建立与平台构件标识的对应关系。

通过文件版本识别将任务分配给兼容的转换引擎；对低版本模型按引擎支持规则处理升级，对高于现有引擎版本的文件给出明确状态并通过相应版本引擎处理。链接模型按项目约定统一收集，保存链接实例及坐标变换关系。软件授权、部署方式、支持的 Revit 年份版本及无人工干预转换能力在投标配置和交付清单中逐项落实。

**验收方法：** 直接上传约定版本的原生 RVT 文件，演示自动转换、场景加载、构件属性查询和坐标核对，并检查转换引擎及授权材料。

#### 3. 不小于 500MB 文件上传

**对应要求：** 支持不小于 500MB 的 BIM 模型文件上传。

**技术响应：** 满足。上传能力按照 GB 级文件设计，单文件上限配置不低于 500MB。

**实施方案：** 采用分片上传、断点续传和对象存储直传机制，上传完成后进行分片合并、文件长度及摘要校验。同步配置接口网关、反向代理、存储服务的请求限制与超时参数，避免某一链路环节限制大文件上传。前端展示上传进度、失败分片及续传状态。

**验收方法：** 上传实际大小不小于 500MB 的模型文件，在上传过程中中断并恢复网络，核查续传结果、文件大小和摘要一致性。

#### 4. 不少于 10,000 个构件解析与渲染

**对应要求：** 支持不少于 10,000 个构件的模型解析与渲染。

**技术响应：** 满足。解析、索引和渲染链路均按不少于 10,000 个独立构件实施。

**实施方案：** 服务端将模型拆分为空间分块和多级细节资源，使用几何去重、实例化、网格压缩和材质合并减少数据体积及绘制次数。合批过程中保留构件标识与几何片段的映射，确保优化后的模型仍可按构件选取、查询和高亮。

浏览器按视锥、可见性和屏幕占比调度资源，使用分层加载、后台解码和显存资源回收控制峰值负载。构件属性按需查询，避免首屏一次性传输全部属性数据。

**验收方法：** 使用不少于 10,000 个可独立识别构件的模型，核对解析数量与源模型基准数量，演示全模型浏览、随机构件选择、搜索及高亮，不以渲染批次或网格数量替代构件数量。

#### 5. 三维模型首屏加载不大于 15 秒

**对应要求：** 三维模型首屏加载时间不大于 15 秒。

**技术响应：** 满足。通过模型预处理、首屏优先调度和渐进加载实现首屏指标。

**实施方案：** 模型导入后预先生成轻量化资源、场景清单和默认视点索引。打开模型时优先获取默认视点覆盖范围内的低层级几何，在形成可识别主体结构且可旋转、缩放、平移的首屏后继续补充细节。首屏不以空白画布、单个包围盒或静态封面图计为完成。

性能验收使用约定的最低客户端配置、浏览器版本、网络带宽、时延和并发条件，优先对不少于 500MB、10,000 个构件的代表性原始模型经预处理后的结果进行测试。拟定基准包括四核处理器、16GB 内存、支持 WebGL2 的图形设备、100Mbps 可用网络带宽及不高于 50ms 的往返时延；最终配置写入投标配置清单和验收方案，招标文件另有规定时执行招标规定。

**验收方法：** 从用户打开模型、客户端发出场景加载请求开始，到形成满足上述定义的可交互首屏结束计时。以浏览器模型资源冷缓存连续测试不少于 5 次，记录每次结果，各次不大于 15 秒；同时记录后续精细资源完成时间。上传和首次转换耗时单独记录，不与已发布模型的首屏加载计时混淆。

#### 6. 标准 IFC 4.0 导入成功率不低于 95%

**对应要求：** 标准 IFC 4.0 格式导入成功率不低于 95%。

**技术响应：** 满足。以具备代表性的标准 IFC4 样本集验证导入成功率。

**实施方案：** 测试样本覆盖不同来源软件、专业类型、模型大小及几何表达方式。导入成功须同时满足任务正常完成、场景可渲染、构件标识可查询、关键属性可读取及主要空间关系正确。失败模型保留原始输入、解析日志和问题分类，形成整改闭环。

**验收方法：** 测试前确认并冻结样本集及判定规则，建议不少于 20 个有效标准样本。导入成功率＝成功导入的有效样本数÷全部有效标准样本数×100%，结果不低于 95%。样本有效性在测试前确定，不得在测试后将解析失败的有效模型移出分母。

### 3.3.3.2 模型坐标系与配准能力

#### 1. BIM 坐标与现场世界坐标一致或具有明确转换关系

**技术响应：** 满足。以项目统一的现场世界坐标系作为空间基准，保存 BIM 模型坐标到现场世界坐标的可追溯转换关系。

**实施方案：** 为项目登记坐标参考系、水平与高程基准、单位、轴方向及项目原点；为每个模型版本保存源坐标信息和变换参数。对 IFC 读取定位层级及适用的地理参考信息，对 RVT 读取项目坐标、共享坐标及链接实例变换。

在局部工程坐标范围内，以齐次变换矩阵表达平移、旋转及必要的单位换算；涉及不同地理坐标参考系时，先执行相应投影及基准转换，再实施局部配准，不用单一刚体矩阵替代地理坐标变换。浏览器采用局部原点渲染，服务端保留双精度世界坐标，减少大坐标数值精度损失。

**验收方法：** 核查坐标参数及转换记录，使用已知控制点执行正反向转换，与现场测量坐标对比。

#### 2. BIM 坐标转换 API 及病害图像坐标映射

**技术响应：** 满足。提供 BIM、现场世界坐标及病害图像定位相关 API。

**实施方案：** API 支持 BIM 坐标与现场世界坐标双向转换、图像观测点向三维空间投影、三维空间点匹配构件等操作。图像到三维定位采用“相机标定—像素去畸变—空间射线计算—深度求解—坐标转换—构件关联”的处理链路。

单幅二维图像的像素位置本身不能唯一确定空间点。系统结合相机内参、拍摄时刻外参，以及深度数据、双目/多视角重建结果或已配准模型表面射线交点求取三维位置；根据现场条件选用可满足精度的采集与定位组合。遮挡、多交点或缺少有效深度时标记待复核，保留人工选择目标表面的入口。

输入记录包括图像标识、像素坐标、相机标定标识、时间戳、定位方式和模型版本。输出包括 Element ID、BIM 坐标、世界坐标、单位、坐标系标识、配准版本、质量状态和不确定度信息。

**验收方法：** 选取具有独立测量真值的现场病害点，调用接口完成图像到 BIM 定位，核查返回字段、空间位置及质量记录。实际端到端误差按病害标注精度条款验收。

#### 3. 坐标配准误差不大于 5cm，支撑 K3

**技术响应：** 满足。采用实测控制点约束、最小二乘配准和独立检查点复核，实现模型坐标与现场世界坐标配准误差不大于 5cm。

**实施方案：** 选择分布覆盖作业区域、具有明确几何特征的控制点，通过满足精度要求的测量手段获取现场坐标。配准计算至少使用满足求解条件且不共线的控制点，实际增加冗余控制点改善稳定性，必要时结合点云精配准。模型自身几何偏差较大的区域进行现场核实与模型校正，避免仅靠坐标变换掩盖形变。

建立涵盖现场测量、配准、相机标定、深度估计和标注计算的误差预算。模型配准合格不直接替代病害端到端定位合格，两项分别验证；对新增模型版本、相机位置变化及控制点变化触发重新校验。

**验收方法：** 使用未参与拟合的独立检查点，在约定覆盖范围逐点计算三维欧氏误差 e＝√[(ΔX)²＋(ΔY)²＋(ΔZ)²]。本方案按每个有效检查点 e≤0.05m 验收，同时提交最大误差和 RMSE。检查点数量、布置和测量精度在验收前固定；K3 的抽样与统计口径如另有明确规定，按其要求进一步执行。

#### 4. 可视化坐标系校准、人工微调及验证

**技术响应：** 满足。提供模型与现场参考数据叠加的可视化校准工具。

**实施方案：** 工具支持显示坐标轴、控制点、现场点云或测量参考点；支持配对选点、自动求解、残差查看以及平移和旋转人工微调。单位换算与真实几何缩放分别管理，禁止通过无约束缩放改变工程尺寸以制造配准合格结果。

用户可对比校准前后效果，查看各检查点误差，保存校准草稿、发布配准版本及回退历史结果。每次保存记录操作人、时间、输入控制点、变换参数、误差报告和适用模型版本。

**验收方法：** 演示选点配准、人工微调、误差验证、版本保存及回退，并核查转换 API 使用的配准版本与已发布结果一致。

### 3.3.3.3 构件 ID 管理要求

#### 1. 每个构件具有全局唯一 Element ID

**技术响应：** 满足。建立平台级全局唯一 Element ID，作为病害关联的唯一构件标识。

**实施方案：** 为构件生成并持久化平台 UUID，同时保留项目、模型、来源文件、IFC GlobalId、Revit UniqueId 及源 ElementId。源软件中的数字型 ElementId 不直接作为跨文件全局主键；重复插入的链接模型通过链接实例命名空间区分。

病害记录、构件属性、几何片段和版本实例均通过平台 Element ID 建立关联。构件分类编码、名称、渲染对象编号作为独立字段管理，不替代平台唯一标识。

**验收方法：** 跨项目、多模型及链接实例检查 ID 唯一性，核查同一病害关联的构件标识是否保持一致。

#### 2. 模型版本之间 ID 一致或提供映射

**技术响应：** 满足。采用“稳定构件身份＋版本构件实例＋显式映射”的管理方式。

**实施方案：** 对确认延续的构件复用平台 Element ID；优先依据 IFC GlobalId、Revit UniqueId 及来源关系匹配，辅助使用分类、名称、空间位置和几何特征校验。对复制重建、拆分、合并或源 ID 改变的构件建立一对一、一对多或多对一映射，记录匹配依据、审核状态和变更原因。低可信匹配进入人工确认，不自动覆盖既有病害关联。

**验收方法：** 使用包含未变更、修改、新增、删除、拆分及合并构件的版本样本，核查稳定 ID 和映射结果，并导出映射清单。

#### 3. 按 Element ID 快速定位及高亮

**技术响应：** 满足。构建 Element ID 到属性记录、空间包围盒、资源分块和渲染对象的索引。

**实施方案：** 输入 Element ID 后直接查询构件位置和几何资源；构件尚未加载时优先调度对应分块，完成相机聚焦并显示轮廓或颜色高亮。对于隐藏或被剖切的构件，提供显示提示与恢复可见性的操作。

**验收方法：** 在不少于 10,000 个构件的模型中随机输入多个 Element ID，验证定位对象、属性对象和高亮对象一致，并记录定位响应时间。

#### 4. 遵循 GB/T 51269-2017 分类和编码标准

**技术响应：** 满足。按 GB/T 51269-2017《建筑信息模型分类和编码标准》建立构件分类与编码规则。

**实施方案：** 根据标准正式文本及项目专业范围配置分类字典、编码结构和校验规则，将源模型类别、类型和专业属性映射到标准分类编码。对缺码、无效编码或不能自动归类的构件形成待补充清单，经审核后入库。保存标准版本、分类编码、源类别及映射依据，区分标准分类编码和用于实例唯一识别的 Element ID。

**验收方法：** 按专业和类别抽样，对照标准正式文本检查编码及含义，提供分类字典、映射规则和校验结果。

### 3.3.3.4 模型版本管理要求

#### 1. 同一项目多版本统一管理

**技术响应：** 满足。建立项目、逻辑模型、模型版本三级管理结构。

**实施方案：** 每个版本独立保存原始文件、轻量化资源、构件清单、坐标参数、上传人、上传时间、版本说明及发布状态。已发布版本保持只读，需要变更时生成新版本；使用原始文件摘要校验版本文件完整性。

**验收方法：** 在同一项目创建多个版本，核查版本记录、文件及元数据可独立查询。

#### 2. 版本切换、历史追溯及场景正确加载

**技术响应：** 满足。支持历史版本查询、切换和追溯。

**实施方案：** 版本切换时统一切换场景资源清单、构件属性索引、坐标配准参数及关联数据视图，清理失效渲染资源，避免新旧资源混用。历史浏览按当时模型版本和映射记录展示，可查询版本发布、替换与回退操作日志。

**验收方法：** 连续切换不同历史版本，核对构件数量、关键构件位置、属性、配准参数和病害展示结果。

#### 3. 一个项目关联多个 BIM 模型版本

**技术响应：** 满足。支持同一项目关联多个专业或分区模型，并为各逻辑模型保存多个版本。

**实施方案：** 项目使用模型组合清单明确各逻辑模型所选版本，支持单模型浏览及多模型联合场景。模型组合绑定统一空间基准，记录模型间变换关系，避免联合加载时因版本或坐标不一致造成错位。

**验收方法：** 为一个项目关联多个模型及其版本，演示单独切换和组合加载，并核查组合清单。

#### 4. 历史病害与最新版本关联或提示重新映射

**技术响应：** 满足。历史病害保留原始证据，同时建立面向最新模型版本的关联状态。

**实施方案：** 病害原始记录保存发现时的 Element ID、模型版本、图像、世界坐标、局部锚点及配准版本。新版本发布后，根据稳定 ID、版本映射和局部表面位置校验生成最新关联。构件发生拆分、合并、删除或表面变化时，标记“待重新映射”，在病害列表和详情中明确提示。

对重新映射进行人工确认并记录过程，保留原始关联及历次映射，禁止无记录迁移或直接删除历史病害。构件几何变化时优先结合表面锚点和新几何重投影，不能仅复制旧世界坐标。

**验收方法：** 发布包含构件变更的新版本，检查正常继承的病害、待映射提示及人工重映射后可追溯记录。

### 3.3.3.5 数据接口开放要求

#### 1. 标准 RESTful API 查询构件、位置和关联病害

**技术响应：** 满足。通过统一 API 网关开放项目、模型、版本、构件、空间位置、坐标转换和病害查询能力。

**实施方案：** 使用 HTTPS、JSON 和标准 HTTP 方法，支持按项目、模型版本、Element ID、名称和空间范围查询。集合接口提供分页，病害接口支持类型、评级及时间范围过滤。接口执行身份认证与项目权限校验，并提供版本管理、访问审计及必要的流量控制。

典型接口资源包括构件详情、构件几何、构件关联病害、模型版本、坐标转换及版本构件映射。接口契约以 OpenAPI 定义为准，避免外部系统依赖内部数据库结构。

**验收方法：** 使用独立接口调用工具完成身份认证、构件查询、空间查询及病害联查，验证权限范围和返回结果。

#### 2. 返回完整构件信息

**技术响应：** 满足。提供构件 ID、几何数据、空间坐标、自定义属性及必要关联信息。

**实施方案：** 构件详情返回平台 Element ID、源系统标识、项目及版本、名称、类别、标准分类编码、包围盒、定位点、坐标系、单位、变换参数和自定义属性。几何接口提供实际几何数据，包括顶点、索引和必要的法线等信息；大体量几何支持分块下载，同时返回格式、精度、摘要和关联构件标识，不仅返回包围盒或不可访问的资源地址。

属性集保留属性名称、值、类型、单位及来源；构件关联病害返回病害标识、类型、评级、发现时间、位置和质量状态。

**验收方法：** 抽取典型构件，核查字段完整性，实际下载几何并验证其与场景构件一致，检查自定义属性及关联病害可正确读取。

#### 3. OpenAPI 3.0 及完整文档

**技术响应：** 满足。交付符合 OpenAPI 3.0 规范的机器可读接口定义和可阅读接口文档。

**实施方案：** 文档包括服务地址、认证方式、接口路径、请求参数、返回字段、数据类型、枚举、单位、坐标系约定、分页规则、错误码、限流规则、接口版本及调用示例。对几何下载、坐标转换和图像定位提供完整请求响应示例，明确依赖数据和质量状态含义。

**验收方法：** 使用 OpenAPI 校验工具验证定义文件，依据文档由独立调用方完成构件及病害查询、坐标转换和几何获取。

## 3.3.4 对应（3）BIM 可视化与交互能力

### 3.3.4.1 三维渲染能力

#### 1. 基于 WebGL、无需插件

**技术响应：** 满足。采用基于 WebGL 的浏览器三维渲染引擎，优先使用 WebGL2 能力，用户通过受支持的主流浏览器访问。

**实施方案：** 三维资源通过标准网络请求加载，浏览器完成渲染、拾取及交互计算；模型转换与视频处理在服务端或边缘执行。无需在用户终端安装 Revit、专用模型查看插件或浏览器扩展。

**验收方法：** 在未安装模型插件的验收终端打开系统，完成模型浏览及构件交互，检查浏览器兼容清单。

#### 2. 旋转、缩放、平移

**技术响应：** 满足。支持鼠标和界面控件执行模型旋转、缩放和平移。

**实施方案：** 提供轨道旋转、滚轮缩放、拖拽平移、全景适配和视图复位。选中构件后可将旋转中心切换至该构件，结合模型尺度控制近远裁剪面及缩放范围。

**验收方法：** 对代表性模型执行连续交互，检查响应、视点变化和模型显示结果。

#### 3. 按构件 ID 高亮

**技术响应：** 满足。支持依据 Element ID 单选或多选高亮。

**实施方案：** 通过构件索引定位几何片段，以描边或覆盖材质显示选中状态，并联动属性面板；清除选择后恢复原有显示。高亮与安全评级颜色分层管理，避免选中状态破坏评级数据表达。

**验收方法：** 输入指定 Element ID，核对高亮构件、属性和位置，并验证取消高亮后评级颜色正确恢复。

#### 4. 安全评级 A/B/C/D 对应绿/黄/橙/红

**技术响应：** 满足。严格按 A 级绿色、B 级黄色、C 级橙色、D 级红色进行构件着色。

**实施方案：** 为构件保存评级、来源、评定时间及有效状态，前端按 Element ID 更新颜色。设置常驻图例，并配合等级文字或标记辅助识别；未评级构件使用独立中性色，不混入 A 级。构件具有多条病害时，按项目确认的安全评定规则形成构件评级，不以病害识别置信度直接代替安全评级。

**验收方法：** 导入各等级样本，逐项核查颜色、图例、等级文字及评级更新后的联动结果。

#### 5. 病害三维标注及悬浮信息

**技术响应：** 满足。支持在模型对应构件表面展示病害点、线或区域标注，并显示悬浮信息。

**实施方案：** 标注锚定至构件及其局部表面位置，同时保存世界坐标。悬浮时显示病害类型、发现时间、置信度、关键参数和评级，点击后打开完整详情及原始图像。采用距离缩放、遮挡判定和标注聚合控制密集区域显示，展开后保留单条病害访问能力。

**验收方法：** 演示不同尺度和视角下标注跟随模型显示，检查悬浮信息和病害详情一致。

### 3.3.4.2 模型交互能力

#### 1. 点击选择构件及属性详情

**技术响应：** 满足。支持鼠标点击选中构件并查看属性详情。

**实施方案：** 使用 GPU 拾取或空间加速结构识别命中的几何片段，映射到平台 Element ID。属性面板显示名称、类别、标准编码、模型版本、空间坐标、自定义属性及关联病害；支持隐藏、隔离和取消选择等辅助查看操作。

**验收方法：** 对不同专业和遮挡条件下的构件进行点击，核对选取对象、Element ID 与属性数据一致性。

#### 2. 预设视点及自定义视点保存

**技术响应：** 满足。提供俯视、正视、侧视等预设视点，支持自定义视点保存和恢复。

**实施方案：** 保存相机位置、观察目标、投影类型、缩放参数和适用模型版本，并按需保存剖切面、构件可见性及标注显示状态。提供视点命名、列表选择和权限控制；跨版本恢复时校验目标构件及坐标关系。

**验收方法：** 切换预设视点，保存自定义视点后退出并重新打开，检查相机及约定场景状态准确恢复。

#### 3. 任意平面剖切

**技术响应：** 满足。支持任意方向、任意位置的平面剖切，查看内部结构。

**实施方案：** 采用平面方程和渲染裁剪实现剖切，提供拖拽控制器及数值输入，支持调整平面法向、位置、保留方向及开关状态。剖切后仍支持构件选取和属性查询，病害标注按所属位置同步处理可见性。

**验收方法：** 执行水平、竖向和斜向剖切，连续移动剖切面，核查内部结构、构件选择及标注显示。

#### 4. 按构件 ID/名称搜索及定位

**技术响应：** 满足。支持 Element ID 精确搜索及名称关键词搜索，并定位目标构件。

**实施方案：** 服务端建立 ID 与名称索引，结合项目、模型和版本过滤检索。名称匹配多个结果时列出候选构件，用户选择后调用统一定位能力，完成资源调度、相机聚焦、高亮及属性展示。

**验收方法：** 分别输入有效 ID、名称关键词及无结果条件，检查检索、候选选择和定位正确性。

### 3.3.4.3 病害可视化能力

#### 1. 病害位置精确标注，误差不大于 5cm

**技术响应：** 满足。病害标注基于经验证的坐标配准和图像三维定位结果，位置误差不大于 5cm。

**实施方案：** 病害数据保存世界坐标、BIM 坐标、Element ID、局部锚点、发现时模型版本及配准版本。显示时通过统一坐标服务将病害定位到构件表面，避免按屏幕位置或模型包围盒比例估算病害位置。标注图标可进行视觉偏移以避免遮挡，但引线端点始终对应真实空间锚点。

定位链路同时校核模型几何、现场配准、相机内外参及深度信息。质量不足的结果进入复核流程，补充测量或重新定位后方可作为满足精度要求的正式标注。

**验收方法：** 在预先约定的作业范围和距离条件下，使用独立测量获得的病害真值点，计算图像识别/定位至最终 BIM 标注的端到端三维误差。按各有效验收点误差不大于 0.05m 执行，并提交抽样规则、最大误差、RMSE、采集条件和原始记录；不得以屏幕像素误差或模型配准误差替代病害端到端误差。

#### 2. 标注包含类型、时间、置信度和参数

**技术响应：** 满足。病害标注和详情具备招标规定的完整信息。

**实施方案：** 统一病害数据结构，保存病害类型、发现时间及其时区、识别置信度、病害参数、参数单位、关联图像、构件 ID、安全评级和复核状态。按病害类型配置裂缝长度与宽度、剥落面积、渗漏范围等适用参数；未经标定的图像估算值标明来源和测量状态，不以无依据数值作为实测结果。人工录入病害的置信度明确标为不适用，不伪造算法置信度。

**验收方法：** 选取不同病害类型，核查悬浮卡片、详情和接口数据一致，关键字段及单位完整。

#### 3. 按类型、评级和时间范围筛选

**技术响应：** 满足。支持按病害类型、A/B/C/D 评级及发现时间范围独立或组合筛选。

**实施方案：** 前后端使用同一筛选条件生成列表、统计和三维标注集合。明确评级筛选采用病害记录中的评级及其来源；如同时提供构件评级筛选，两者在界面及 API 参数中分别标识。统一时区和时间边界处理，支持条件重置及结果数量展示。

**验收方法：** 设置各类单条件和组合条件，核对列表条数、三维标注和接口结果一致，并验证时间边界数据及空结果。

#### 4. 病害列表与三维模型双向联动

**技术响应：** 满足。支持点击病害列表定位模型，点击模型中的病害标注或关联构件查看详情。

**实施方案：** 点击列表记录后，以病害 ID 和 Element ID 查询其模型版本与空间锚点，调度必要几何资源、聚焦目标位置、高亮关联构件并展开病害详情。点击三维病害标注时反向定位列表记录并展开详情；点击有病害的构件时列出关联病害，由用户选择具体记录。

对病害被筛选隐藏、目标构件未加载、历史版本不一致及待重新映射等状态给出明确提示，并提供相应操作入口。通过统一选中状态同步列表和场景，避免重复触发或详情对象不一致。

**验收方法：** 演示列表到模型、病害标注到列表、构件到病害详情的双向操作，核对病害 ID、构件 ID、版本和空间位置，并检查未加载及待映射状态。

## 3.3.5 实施与交付安排

### 3.3.5.1 实施步骤

1. 基础条件确认：确认项目坐标基准、模型来源、IFC/RVT 支持版本、设备协议、病害类型、安全评级规则、K3 统计口径及验收环境，形成配置基线和测试样本清单。
2. 平台部署：部署中心云及边缘网关，完成存储、数据库、任务队列、模型转换、视频处理和接口服务配置，落实 RVT 转换软件授权。
3. 模型接入与空间校准：完成模型导入、轻量化、标准分类编码、构件索引、现场控制点采集、配准及独立检查点复核。
4. 业务联通：完成病害图像定位、构件关联、安全评级着色、版本映射、查询筛选及列表模型联动。
5. 联调验收：按逐条响应内容执行功能、性能、精度及接口测试，对失败项整改后复测并形成交付记录。

### 3.3.5.2 交付成果

1. 中心云与边缘网关可运行系统、模块部署包和部署配置。
2. IFC 与 RVT 模型导入服务、模型发布资源及格式版本兼容清单。
3. 项目模型、构件属性、标准分类字典及编码校验结果。
4. 坐标转换接口、可视化校准工具、控制点记录、配准参数及误差报告。
5. 全局 Element ID 规则、构件版本映射和历史病害关联记录。
6. WebGL 三维场景、评级着色、病害标注及双向联动功能。
7. OpenAPI 3.0 接口定义、接口文档、调用示例及联调记录。
8. 大文件上传、万级构件解析与渲染、首屏加载、IFC 导入成功率及端到端定位精度测试报告。
9. 系统使用说明、运维说明、培训材料及相关软件授权证明。

### 3.3.5.3 验收记录与指标闭环

每项验收记录应对应本方案条款编号，至少包含需求内容、测试环境、输入样本、操作步骤、预期结果、实测结果、证据位置和结论。对于 500MB 上传、10,000 个构件、15 秒首屏、95% 导入成功率及 5cm 精度等量化指标，保留原始文件、任务日志、浏览器计时或测量原始记录，确保结果可复核。

项目交付以实际功能和实测指标为依据。外部模型质量、现场采集条件和运行环境在测试前固化，不在测试后通过调整统计口径替代整改。招标文件对验收环境、K3 定义或测量方法另有规定时，按其规定执行，并在本方案基础上补充相应证据。
