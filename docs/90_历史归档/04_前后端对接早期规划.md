# Unity 前端对接与后端实施规划

> 状态：历史归档。保留完整源码调研及早期任务建议；当前架构以 [01 总体设计](../01_项目总体设计.md) 为准，任务及状态仅维护在 [03 近期执行任务](../03_近期执行任务.md)。

日期：2026-10-31。性质：基于两端源码的实施规划，不表示本文件所列新增接口已实现或部署。

## 1. 目标与结论

前端为 `F:/JTYFGitWorkSpace/wx-vue-unity`，后端为 `F:/JTYFGitWorkSpace/wx-cloud`。

首个交付目标是：运营端、租户端能登录 148 后端，创建场景，在二维编辑器编辑并保存，退出后重新打开能恢复完整内容，同时保留未编辑的三维数据。随后补齐资源、模板、发布预览，再接入 Unity 的真实资源和渲染流程。

不能仅替换前端服务器地址。需要补齐协议兼容、可信身份识别和新的场景业务。优先复用现有系统、权限、租户、对象存储和资源事务能力。

## 3. 协议差异与实现原则

应用程序接口（API）以实际前端调用、现行交接合同和后端安全边界三者共同核对。开放接口规范（OpenAPI）用于保存双方认可的路径和数据结构。

| 项目 | 前端需要 | 当前后端基础 | 下一步处理 |
| --- | --- | --- | --- |
| 登录 | `/api/auth/operation/login`、`/api/auth/tenant/login`；`phonenumber/clientId/accountType/grantType` | `/admin-api/system/auth/login`，既有账号及令牌服务 | 在系统模块增加前端认证适配，复用服务，不用重写路径替代身份校验 |
| 用户资料 | `/api/system/user/getInfo`、`/api/tenant/profile/getInfo`；`user/roles/permissions` | `/admin-api/system/auth/get-permission-info` 等 | 显式投影字段，验证应用、平台和真实租户 |
| 租户识别 | 客户端主要提供令牌与 `ClientId` | 现有租户上下文及请求头约束 | 新接口从可信会话恢复租户；已有显式租户头必须与身份一致，禁止取浏览器参数覆盖 |
| 响应 | 成功 `code=200`；列表按各适配器的 `rows/total` 要求 | 现有 `CommonResult`，目录分页为 `data.list/total` | 每接口适配；不能只做网关路径映射 |
| 大编号 | 编号为十进制字符串 | 既有 Java 长整型主键 | 外部传输统一字符串，避免浏览器精度丢失；不必为此全库改主键 |
| 资源目录 | `/api/{平台}/dim3d/model|icon|template/...` | `/admin-api/dim3d/...` | 复用目录服务，在平台适配层映射字段与权限 |
| 普通上传 | `/api/resource/oss/upload`、`listByIds/{ids}`；返回 `ossId` 等 | 基础设施文件服务及 MinIO | 增加文件身份适配；不能把任意 `ossId`、旧模型编号和文件主键按数字相同合并 |
| 新场景 | `/dim3d/scene/...`、`saveAll`、四包、锁 | 旧场景接口和数据结构 | 在三维模块新增明确的场景领域，不把旧接口直接别名化 |
| 场景发布 | 固定 `publicationId`、访问模式、票据、按实例依赖 | 旧工程发布标记、资源操作快照 | 新建场景发布能力；场景发布快照与单资源操作快照各自保留职责 |
| Unity 资源 | 可加载的包、平台及兼容信息 | 受控单资源上传/提交/读取已有 | 复用已建合同；旧转换接口的网页模型路径不等于 Unity 可加载资源 |

网关负责路由、请求头清理、跨域等入口策略。认证、字段转换、范围授权和业务事务放在对应服务中。新平台路由必须检查令牌所属应用及平台，不能凭 URL 或 `ClientId` 获得运营权限。

## 4. 阶段安排与验收出口

### 阶段 0：冻结接口差异和最小业务范围

交付内容：

- 建立 `contracts/editor/`，按认证、字典/租户、目录/文件、场景/锁、模板、发布/预览分组保存接口清单、请求示例、响应示例和错误规则。
- 对前端 `standalone.ts`、`scene.ts`、`sceneRuntime.ts`、`dictionary.ts`、`model.ts`、`icon.ts`、`template.ts`、`oss.ts` 的调用逐项登记“可复用/需适配/需新增/依赖外部服务”。
- 明确登录时的租户识别规则：前端只提交手机号和应用编号时，服务端如何唯一定位账号及租户。存在多租户同手机号时，不默认取第一条账号，也不把通用租户应用编号当作唯一租户编号。
- 冻结平台身份、时间单位、分页结构、业务错误以及字符串编号。分类字典的业务值由现有前端/业务配置确认，不擅自编造完整分类库。
- 明确初期只覆盖独立双端、二维场景编辑保存；嵌入身份交接和公开预览在其阶段单独验收。

验收出口：对每项前端第一批请求，都有确定的后端模块、接口、身份规则和测试样例。未冻结的云渲染协议不混入首批合同。

### 阶段 1：双端认证、权限和基础配置

系统模块增加兼容控制器，复用现有账号、角色、权限及开放授权（OAuth2）令牌服务。

- 实现两端登录、两端资料、退出。将令牌有效期显式转为剩余秒数，不能将绝对毫秒时间直接填入 `expire_in`。
- 注册本项目自己的运营和租户应用编号，不复用参考服务器示例中的应用身份。
- 将平台、用户、应用和租户绑定到可信会话；对同一令牌换应用、换平台、换租户的请求明确拒绝。
- 为编辑器初始化可重复执行的权限及字典迁移。字典包括 `dim3d_model_category`、`dim3d_icon_category`、`dim3d_scene_category`、`dim3d_access_mode`、两类模板分类。
- 适配 `/api/system/dict/data/type/{dictType}` 和业务平台下的 `/tenant/dashboard/list`；租户查询按权限限制，不把全平台租户信息开放给普通租户。
- 续期初期保持前端开关关闭。启用前补齐刷新令牌轮换、摘要存储、旧令牌重放检测和退出撤销，不将现有刷新接口改个名称就宣称满足合同。

验收出口：真实账号可从 Vue 登录页登录、恢复页面、读取正确权限和字典、退出；运营身份和租户身份不能串用。这里不以返回管理员万能权限掩盖缺失配置。

### 阶段 2：场景管理、编辑锁和四包保存

这是后端首批核心开发工作。

- 新建 `/api/{平台}/dim3d/scene/page|info|add|edit|remove|copy`，其中平台分别为 `operation` 和 `tenant/web`；按合同使用各自正确的方法和路径参数。
- 实现 `POST /scene/lock/{id}?clientKey=...`、`POST /scene/heartbeat/{id}` 和 `DELETE /scene/unlock/{id}?clientKey=...`。锁绑定用户、租户、场景、可信会话及页签；有效期按合同为 20 分钟。
- 保持合同特殊语义：`locked=false` 且取得有效 `lockToken` 才表示当前持锁；不要根据字段字面含义反转。
- 实现 `PUT /scene/saveAll`，接收 `sceneId/lockToken/requestId/baseRevisionNo/schemaVersion` 及 `sceneJson/threeDJson/twoDJson/dependenciesJson` 四份字符串。
- 当前草稿只维护一份内容和递增保存书签，不把每次自动保存都扩展成历史发布版本。
- 保存时整体更新四包、派生索引、书签和幂等结果。同一请求编号和相同正文返回原结果；同号异正文拒绝。旧书签冲突按合同返回冲突信息，不覆盖他人内容。
- 二维编辑保存必须完整保留三维原文、扩展配置、未知依赖和隐藏实例。后端不执行场景中保存的脚本、数据查询或渲染命令。

验收出口：创建场景 → 添加文字/图表及数据绑定 → 保存 → 关闭 → 重开内容一致；两个页签抢锁、锁过期、保存重试、旧书签及事务故障都不造成数据丢失。验收样本必须包含超出浏览器安全整数范围的字符串编号和原文保留字段。

### 阶段 3：目录、普通文件与稳定资源引用

- 复用 `Dim3dResourceCatalogServiceImpl` 的模型、图片和模板目录服务；补齐分页、字段、状态和平台范围投影。
- `SYSTEM/MINE` 是前端目录表达；新资源域的 `GLOBAL_SYSTEM/TENANT_SHARED` 有独立授权规则。建立显式映射及文件身份关系，不能用显示标签取代资源范围鉴权。
- 基于基础设施服务补齐普通文件上传和元信息查询。封面、图片重开时按稳定编号重新解析地址，不把临时签名地址当作永久场景内容。
- 继续复用 ART 单资源操作及私有桶策略；兼容接口不得绕过已存在的提交、摘要和范围校验。
- 对模型转换代理建立依赖清单：当前仍依赖 `192.168.10.200:30080`。先核实服务归属、输入输出和失败规则；未经确认不切除依赖，也不把代理请求成功等同于已具备本地转换能力。

验收出口：前端可使用真实图片和模型目录；上传失败不留下可消费的错误元数据；跨租户取文件被拒绝；临时地址到期后重新打开场景仍能解析资源。

### 阶段 4：模板、不可变发布及访问控制

- 实现 `/scene/saveAsTemplateFromSnapshot`，使用当前编辑器传入的四包，不以最后保存的场景内容替代未保存的内存内容。
- 模板范围为 `twoD/threeD/all`；验证裁剪后的跨域依赖。模板类型沿用前端实际值 `dim3d_template_industry/exhibition`。
- 实现场景发布、取消、授权租户、回收授权及授权记录。发布时复制一致的草稿快照，生成固定 `publicationId`；重复发布相同内容和设置可以复用结果。
- 支持 `PERSONAL/ENTERPRISE/PUBLIC_ENCRYPT/PUBLIC_SHARE`。场景访问授权与底层资源授权必须联动设计；发布不自动使整个私有桶公开。
- 按前端合同实现访问解析、短时预览票据和发布快照的 `sceneBasic/threeD/twoD/dependenciesByinstances`。依赖请求正文是字符串编号数组，响应四类依赖的元素是单条 JSON 字符串原文。
- 按发布编号与实例拥有者建立依赖索引；批量查询一次取回，避免逐实例查库。撤销发布或授权后，后续请求和票据续签必须重新受控。
- 票据绑定发布编号和用途，管理令牌、预览票据、文件签名各司其职。公开预览不能依赖写入前端构建的管理员密码。

验收出口：编辑草稿不改变已发布页面；四种访问模式均有真实成功和拒绝测试；隐藏实例首次显示能按需取依赖；取消发布和回收授权后不能继续取得新的可用凭据。

### 阶段 5：Unity 真实资源和双端渲染联调

- 对接前端的 Unity Web 启动描述、真实包产物和云渲染客户端，使用精确的平台、构建和兼容身份。
- 将场景中的稳定资源引用映射到当前后端资源描述及固定修订读取能力；读取地址过期时按原修订续签，不能悄悄切到最新内容。
- 使用真实包分别验证模型加载、资源替换 A/B、旧内容读取、重开场景、实例销毁和重复进入。原有资源单元测试或 HTTP 下载通过不等同于 Unity 已加载成功。
- 云渲染会话申请、续租、释放及启动器调度另立专项。前端当前没有会话控制调用，必须先与实际信令、启动器及 Unity 工程冻结鉴权和协议，再实现后台控制面。
- 后端负责身份、会话、容量和资源，Unity 负责渲染；不让后端模拟编辑器运行时命令来伪造画面验收。

验收出口：本地 Web 构建和云渲染分别记录真实画面及恢复/释放结果。未拿到对端源码、包或服务时明确登记为外部依赖，不阻塞前面的二维交付。

### 后续专项：业务数据、媒体、地理信息和植被

按已确定的页面需求接入。前端已有媒体网关服务代码，应先核对并复用，不默认再在 Java 中建设相同代理。业务数据中间件的地址、鉴权和字段需单独确认；不把 148 服务器上其他 WX 服务的接口直接视为本次编辑器的合同。

地理信息和植被结合现有后端模块做差异清单，按实际调用部署必要服务。商城、支付等模块不因资源目录带价格字段就自动进入首批范围。

## 5. 建议的软件设计

### 5.1 模块归属

| 模块 | 职责 |
| --- | --- |
| `wx-gateway` | 精确路由公共认证、运营、租户业务；清理伪造内部身份头；跨域配置 |
| `wx-module-system-biz` | 前端认证适配、应用/平台会话校验、用户权限投影、字典和租户查询 |
| `wx-module-infra-biz` | 普通文件上传、元信息及受控读取，复用已有文件客户端 |
| `wx-module-3d` | 目录适配、新场景、草稿、锁、模板、发布、预览和资源引用 |
| `contracts/editor`（拟新增） | 冻结接口及两端共享测试样例；与既有 `contracts/art01` 并存 |
| `deploy/test148/migrations/editor`（拟新增） | 可审计的增量迁移、基础配置和回退说明；不重跑初始化覆盖数据 |

兼容控制器调用服务或模块接口，不通过服务内部回调公网 HTTP 路由复用自身逻辑。跨服务能力沿用项目已有远程调用方式，不新建平行认证服务。

### 5.2 数据结构提案

以下为拟新增结构，最终字段在阶段 0 的结构文档和迁移中确定。当前 82 表仅是部署基线，不表示已有以下能力。

| 拟新增表 | 关键约束 |
| --- | --- |
| `wx_dim3d_scene` | 场景身份、归属、用途、分类、封面、当前草稿书签和发布指针；列表按租户与状态索引 |
| `wx_dim3d_scene_draft` | 每场景一份四包原文，`scene_id` 唯一；协议版本、内容摘要、递增书签 |
| `wx_dim3d_scene_lock` | 每场景一条有效锁记录；持有者、应用/会话、页签、令牌摘要、过期时间及锁代次 |
| `wx_dim3d_scene_save_request` | 用户/租户/场景/请求编号唯一；正文摘要和已提交结果 |
| `wx_dim3d_scene_publication` | 固定发布编号、不可变四包、发布人、访问模式及撤销/期限信息；密码只存哈希 |
| `wx_dim3d_scene_dependency_index` | 发布编号、域、实例/拥有者、依赖类别及稳定键；保留原文位置或原文，不取代完整依赖包 |
| `wx_dim3d_scene_grant` | 场景/被授权租户唯一关系、状态和审计 |

不复制系统用户、租户及资源主表。文件身份适配是否需要新增映射表，先审查现有基础设施文件字段再决定。

编辑锁以 MySQL 行状态作为保存事务的权威依据，和草稿、书签在同一短事务内校验；Redis 可用于通知及缓存，不作为另一个无法与保存原子提交的唯一真相。

### 5.3 保存与发布边界

1. 请求入口验证会话、平台及归属，不能在业务写入后才返回认证失败。
2. 四包结构及已知引用在事务外预检；使用集合和索引检测重复、环和缺失引用，复杂度按节点及引用总量控制，避免逐节点嵌套查库。
3. 短事务内重新锁定锁记录及草稿，检查租约、代次、幂等记录和基准书签；整体更新并提交。幂等重试优先回读已提交结果，不能因为书签已前进就把成功重试判为新冲突。
4. 发布生成新的不可变快照及派生依赖索引，原子更新当前发布指针。旧快照是否保留可读由访问策略决定，不能删除被引用内容来完成普通撤销。
5. 文件上传/转换不在长数据库事务内执行；普通文件与资源包沿用各自明确的身份和提交流程。

场景结构只解析校验所需字段，保留四包和扩展原文。内容摘要使用安全散列算法（SHA-256），规范明确区分原文摘要和规范化业务正文摘要，禁止经浮点数解析后改变大编号。
