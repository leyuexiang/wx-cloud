# 01 BIM模型处理微服务详细设计

> 文档状态：V1.0设计基线配套稿，供评审使用。总体职责与实施顺序遵循[00 平台总体架构](./00_数字孪生平台总体架构与改造路线图.md)。本文定义拟建能力和验收目标，不表示功能已实现或实测达标。

## 1 项目理解与建设目标

本方案面向项目BIM模型导入、解析、轻量化发布、三维交互、坐标配准、构件查询、版本追溯及病害关联需求，采用“中心云统一管理与计算、边缘网关就近接入与缓存”的混合部署架构。平台新增独立BIM模型处理微服务，复用现有网关、对象存储、消息队列、租户权限及三维业务基础设施；IFC和RVT解析、模型几何处理与发布由隔离的工作进程承担，避免重型任务影响在线业务。

方案逐项响应3.3技术要求。对500MB文件、10,000个构件、15秒首屏、95% IFC导入成功率和5cm配准误差，均通过明确的实现措施、测量口径和验收报告闭环。目标指标将在约定的模型样本、硬件、网络、浏览器及测量条件下进行验证。RVT解析通过独立适配器支持，并在实施阶段冻结目标Revit版本及许可方式。

## 2 总体技术架构

### 2.1 分层架构

| 层次 | 主要职责 | 关键组成 |
| --- | --- | --- |
| 展示交互层 | 模型查看、构件检索、病害联动、坐标校准和版本切换 | Web三维客户端、WebGL渲染、业务工作台 |
| 接入与网关层 | 统一认证、租户隔离、路由、限流、审计及边缘设备接入 | API网关、边缘网关、设备协议适配器 |
| BIM业务服务层 | 模型、任务、版本、构件、坐标、病害关系和开放接口管理 | `wx-module-bim` API与业务服务 |
| 异步处理层 | IFC/RVT解析、几何优化、LOD生成、分块和发布 | IFC Worker、RVT Worker、几何与发布Worker、Kafka |
| 数据与存储层 | 元数据、属性、空间索引、任务状态、原始文件和发布产物 | MySQL、Redis、MinIO及空间索引 |
| 运维与安全层 | 监控、日志、追踪、资源隔离、密钥、备份及恢复 | 容器平台、指标与日志平台、权限和审计 |

模块按职责独立划分、独立部署和按需扩容。BIM业务服务不执行大规模几何运算；IFC与RVT解析器分别隔离，发布处理可独立增加工作节点。模块通过REST接口、Kafka事件及受鉴权的内部回调协作，消息仅传递任务、版本和对象存储标识，不传输模型二进制。

### 2.2 中心云与边缘网关协同

中心云部署BIM业务服务、模型元数据与版本库、对象存储、任务调度、解析/发布工作节点、统一接口及全局监控，负责数据存储、智能计算、全局任务调度和跨项目管理。边缘网关部署现场设备接入、协议转换、视频流接入与必要的视频流处理、断网缓存、上传队列及安全代理，负责现场数据就近汇聚。

边缘网关在网络可用时将模型文件分片、坐标控制点、设备和病害数据安全同步至中心云；网络中断时按本地容量策略缓存并记录校验信息，恢复后断点续传。视频流在边缘侧按业务配置进行接入、抽帧或转码，需长期留存或参与全局分析的数据按授权上传中心云。BIM模型的重型解析和全局版本发布在中心云进行；需要现场快速预览时，边缘侧可缓存已发布的轻量化成果，不在边缘重复生成权威版本。

### 2.3 服务组成与数据流

新增`wx-module-bim`，分为对外API/业务服务、IFC解析适配器、RVT解析适配器、几何转换与发布Worker。导入流程为：分片上传与校验、创建导入任务、按格式路由解析、归一化构件和坐标信息、生成GLB或3D Tiles、校验发布清单、激活模型版本。任务状态通过API查询和现有WebSocket能力推送。原始模型与发布产物保存在MinIO不可变版本目录，MySQL保存业务元数据、构件属性、空间信息及版本映射，Kafka驱动异步任务，Redis提供短期幂等和任务缓存，数据库作为最终状态来源。

### 2.4 模块与依赖边界

| 单元 | 责任 | 约束 |
| --- | --- | --- |
| `wx-module-bim-api` | 跨服务数据传输对象（DTO）、查询接口、枚举和契约版本 | 不依赖数据库、Revit或解析库 |
| `wx-module-bim-biz` | 权限、上传、任务、构件、坐标、版本、发布与审计 | 独立启动，唯一提交BIM正式业务数据的服务 |
| IFC/RVT解析工作进程（Worker） | 读取源文件，输出统一构件记录、几何及诊断清单 | 独立运行，按适配器能力和版本路由，不直接写BIM正式表 |
| 几何及发布Worker | 几何优化、细节层级（LOD）、分块、构件索引及产物校验 | 产物写任务尝试目录，完成后由BIM服务决定是否登记及发布 |

业务接口只接收平台定义的输入快照及中间契约，不暴露厂商对象或SDK类型。首期以IFC打通真实导入链路，同时保留RVT适配器入口；引擎不可用时返回明确的`ENGINE_UNAVAILABLE`，不接受后长期挂起或用普通网格转换冒充解析成功。

场景对象和设备绑定由三维服务维护；病害、定位结果和安全评级由巡检病害服务维护。BIM提供构件、空间、配准与版本接口，以及关联查询所需的聚合入口；不在本服务重复建设巡检、审批或设备主数据。

## 3 BIM模型处理能力

### 3.1 IFC与RVT格式导入

平台支持IFC 4.0及以上版本的格式识别、解析和导入，提取空间层级、构件类型、源GUID、属性集、材料、几何包围盒和几何引用。IFC解析适配器首期评估IfcOpenShell，实际版本通过样本验证后冻结，解析器版本与转换配置随模型版本留档。通过实体统计、几何成功率、属性覆盖率及错误清单识别解析缺失，标准IFC 4.0导入成功率目标不低于95%。成功率口径为：在测试前确认并冻结的有效标准IFC 4.0样本集中，完成约定几何、构件、属性和空间检查的成功文件数除以全部有效标准样本数。无效或损坏文件的判定在测试前完成，不以待测解析器能否读取决定样本有效性，也不在测试后移除失败的有效模型。

平台支持Autodesk Revit原生RVT文件导入。RVT由独立适配器调用Revit API或经验证的商业转换引擎读取，转换为统一构件中间结构后进入与IFC一致的发布流程。实施启动时双方确认目标Revit主版本、运行环境及许可方案，并形成兼容矩阵；对矩阵内版本提供导入支持，对不匹配或损坏文件返回明确错误码和诊断日志。该设计避免将RVT误当成普通网格格式处理，也避免解析运行时影响在线业务。

RVT后台引擎应明确选择允许模型上传的APS自动化服务，或已验证的本地商业SDK；普通桌面Revit插件运行成功不等于服务端无人值守能力通过。实际选型、独立基准、导出契约、比对工具和验收边界见[05 RVT原生模型导入验证方案](./05_RVT原生模型导入验证方案.md)。样本及引擎环境落实前，本节能力属于拟交付设计，不能记为已实测通过。

本版先确定上述适配边界。已收到含源码的`RevitExportPlugin`，静态检查仅涉及选中构件属性导出；本机未安装Revit，暂无实际运行结果。该插件可作为后续导出适配或独立基准工具的候选，具体版本适配和缺失能力在RVT实施支线处理，不影响总体设计评审。

### 3.2 500MB上传、10,000构件解析及首屏性能

文件上传采用MinIO分片直传，支持至少500MB单模型文件、断点续传、分片重试、合并校验、文件大小及哈希校验。上传完成后由异步任务处理，任务具备进度、阶段、失败原因、可恢复重试和取消能力。解析、几何优化及发布过程不占用HTTP请求线程，Worker按CPU、内存、临时磁盘和任务类型配置资源限额。

模型发布采用GLB与3D Tiles双格式策略：GLB用于中小模型及局部构件交互；对大型模型按空间范围和层级切分3D Tiles，生成LOD（细节层级）并按视距渐进加载。发布时保留构件ID到渲染节点的索引关系，支持10,000个及以上构件的检索、属性查询、高亮和病害定位。首屏通过模型分块、视锥裁剪、LOD、压缩纹理、按需请求、缓存及首屏优先加载优化，三维模型首屏加载时间目标不超过15秒。

首屏验收以约定的代表性模型及部署环境进行，记录模型文件大小、构件数、三角面数、纹理量、浏览器、终端配置、网络带宽与时延、缓存状态和测试次数；首屏时间从客户端发起模型场景加载至首个可交互视图完成计时。若模型复杂度显著超出样本约定范围，应按同一性能口径扩充分块及资源配置后复测。

### 3.3 统一解析与发布契约

| 契约部分 | 必需内容 |
| --- | --- |
| 输入快照 | 任务、租户/应用/项目、模型版本、源资产与SHA-256、格式年份、链接依赖清单、筛选规则、坐标和发布配置版本 |
| 引擎能力 | 适配器/引擎版本、格式及年份范围、可导出属性/几何/链接/坐标能力、运行模式、授权可用状态 |
| 构件记录 | `sourceElementId`、`sourceUniqueId`、`occurrencePath`、名称、类别、空间层级、实例/类型属性、几何引用、包围盒及坐标框架 |
| 诊断记录 | 源对象、阶段、错误码、严重程度、是否缺失必要几何/属性、重试建议；空结果和未解决关键错误不得静默标记完整成功 |
| 发布清单 | 契约版本、模型版本、源摘要、解析器/生成器、配准版本、单位轴向、几何格式、资源哈希、构件索引、统计及检查报告 |

RVT分别保留原生数字ElementId和稳定UniqueId；IFC保留GlobalId，并在链接实例路径内建立源对象命名空间。链接文件哈希及完整实例变换纳入输入快照。同一链接重复插入时，几何可复用，但构件实例身份与变换必须分别保留。

Worker以有界批次或逐行JSON记录输出，业务服务批量导入暂存数据，避免整模构件长期驻留Java堆或逐构件发起HTTP调用。参数保存原始值、类型、单位、参数标识和显示值，实例与类型属性分别标注，不用本地化显示文本替代机器可计算值。

发布清单中的资源ID及相对地址长期稳定，下载签名地址由资源接口临时生成。分块、实例化或合批后，额外保存瓦片/几何特征到平台Element ID的映射；不能依赖节点名称推断构件。前端通过查看器适配层完成清单加载、拾取、高亮、剖切和定位，避免业务代码依赖某家引擎对象。

### 3.4 任务状态与版本状态

任务与模型版本分别管理生命周期：

```text
任务：QUEUED → RUNNING → SUCCEEDED
                 ├→ RETRY_WAIT → QUEUED
                 ├→ FAILED
       QUEUED/RUNNING/RETRY_WAIT → CANCEL_REQUESTED → CANCELED

模型版本：STAGING → READY → PUBLISHED
              └→ FAILED
```

任务阶段为预检、解析、归一化、几何处理和校验；`SUCCEEDED`表示产物及构件暂存结果通过校验，模型版本进入`READY`。只有BIM发布接口完成一致性检查和事务提交后，版本才进入`PUBLISHED`。旧的已发布版本仍保留该状态，`current_version_id`决定默认版本；归档标志和引用保护另行管理，回滚不改写旧版本内容。

- 创建任务与发件箱记录同事务提交。幂等键按租户、项目和操作范围唯一，并保存请求摘要；同键不同输入拒绝复用。同源文件因配置变化需要重处理时允许创建新模型版本。
- Worker租约包含`taskId + attempt + leaseToken`及输入快照哈希；心跳续租，超时回收。阶段回调按任务尝试和批次号幂等，旧租约和过期尝试不得提交结果。
- 自动重试只处理明确可恢复的错误，次数和退避按策略配置；不支持格式、缺许可、关键数据缺失等错误保留原因，避免无效重试。
- 取消先设置`CANCEL_REQUESTED`并阻止发布，再终止或等待工作进程释放资源；取消与完成并发时以数据库条件更新裁决，已取消任务的迟到结果不进入正式索引。
- 手动重试创建关联原任务的新任务，保留原诊断；未发布失败版本可重新暂存。已发布版本的重新处理创建新版本，不覆盖原资源。
- 暂存结果按任务尝试隔离。BIM服务确认完整性后提交版本数据；部分成功只生成诊断和预览，不进入正式发布，除非后续另有显式批准的降级交付规则。

## 4 坐标系与配准

模型入库时记录源坐标系、现场目标坐标系、坐标基准、单位、轴向、原点、旋转、平移及坐标变换版本；模型源坐标系已与现场世界坐标系一致时记录其基准与验证结果，否则保存明确、可追溯的转换关系。平台提供坐标转换API，供图像定位和业务系统将病害空间位置映射至BIM世界坐标。

病害图像坐标转换链路使用相机内参、相机外参、图像像素坐标、深度信息或射线交点、现场控制点及模型坐标变换关系计算BIM世界坐标；缺少深度或有效配准信息时返回不可定位状态，不将像素坐标直接误作世界坐标。坐标转换参数按模型版本保存，所有病害位置记录转换版本和定位来源，确保复算与追溯。

平台提供可视化坐标校准工具，支持控制点录入或拾取、模型与现场基准点对应、平移/旋转微调、预览验证和检核点报告。单位换算与几何缩放分开管理，不通过无约束缩放改变工程尺寸制造配准合格结果。涉及地理参考系变化时先执行投影/基准转换，再做局部变换，不以一个四乘四矩阵替代所有坐标计算。配准验收采用独立检核点，目标误差不超过5cm；报告包含坐标基准、控制点和检核点数量、最大误差、均方根误差、样本来源及测量方法。若输入图像缺少相机标定、深度或控制点等必要信息，平台明确提示补充，不将不具备测量条件的数据宣称为达到精度指标。

巡检病害服务编排图像定位并记录相机标定和深度来源，BIM服务执行明确框架之间的坐标变换及构件空间查询。前端采用局部原点渲染，服务端保留双精度世界坐标；定位请求显式指定模型及配准版本。已发布配准参数不可直接修改，校准变更生成新修订并通过新模型/场景版本发布。

## 5 构件ID与编码管理

每个导入构件分配平台全局唯一且不可变的Element ID，作为病害、工单等业务关联的统一标识。平台同时保存源模型构件ID（IFC GUID或RVT稳定标识）、平台Element ID及分类编码，三者用途分离。渲染节点名称或导出器临时序号不作为业务主键。

平台身份存于`bim_component`，每个模型版本的属性、空间和几何存于`bim_component_version`。源匹配键使用逻辑模型命名空间加`occurrencePath + sourceUniqueId`，不把一个RVT内的数字ElementId当作全平台唯一ID。源标识唯一性只在约定模型及链接实例范围内成立；跨文件复制、另存和拆分合并必须单独匹配。

版本更新时优先依据源构件标识匹配；源标识变化时综合构件类型、属性、空间位置和几何特征生成跨版本映射，并记录匹配方法、置信度和人工复核状态。低置信度匹配进入复核流程，不静默改写既有病害关联。系统支持通过Element ID快速查询构件、取得发布节点并在三维场景中高亮。构件分类编码按GB/T 51269-2017《建筑信息模型分类和编码标准》校验和保存，并支持按编码查询、筛选和统计。

## 6 模型版本管理

一个项目可关联多个BIM模型，同一模型可登记多个源文件及发布版本。版本记录包含源文件哈希、格式及版本、解析器版本、坐标配置哈希、发布参数、构件统计、发布清单和状态。支持版本列表、切换、历史追溯、差异统计、回滚和引用查询；切换版本时加载对应发布清单、坐标变换和构件索引，保证三维场景、属性和空间位置来自同一版本。

版本发布采用不可变产物目录。所有产物和构件索引校验通过后，才原子更新当前版本指针；新版本失败时保留当前稳定版本。病害数据持续关联原模型版本及Element ID，并通过映射关系关联新版本。映射成功时可展示新版本关联结果；未匹配或低置信度时提示重新映射与人工确认，不丢弃历史病害记录。

发布请求携带预期当前版本或修订号，通过数据库条件更新防止并发发布相互覆盖。资源先完成写入与哈希检查，再在一个事务中登记正式索引、切换默认版本指针并写发布事件发件箱；事务失败留下的未引用产物按保留期回收，不提前对外可见。场景使用`scene_model_ref`固定模型版本；模型发布事件仅通知有新版本，不直接替换已发布场景引用。

## 7 三维可视化与交互

Web端基于WebGL实现浏览器内三维渲染，无需安装插件。渲染客户端支持模型旋转、缩放、平移、鼠标点击选择构件、属性详情查看、按构件ID高亮、名称或ID搜索定位、预设俯视/正视/侧视、自定义视点保存及任意平面剖切。渲染节点与构件索引相互映射，保证分块加载后仍可定位和选择。

平台按安全评级配置构件着色：A级绿色、B级黄色、C级橙色、D级红色；评级映射可按项目权限配置并保留原始评级值。病害位置使用三维标记及悬浮信息展示，悬浮信息包含病害类型、发现时间、置信度和参数信息。对不可见构件、被剖切构件和分块未加载构件，定位操作自动加载目标分块并将视点移动至目标位置。

## 8 病害可视化与业务联动

病害位置以BIM世界坐标及模型版本为依据进行三维标注，定位误差目标不超过5cm，并保留位置来源、坐标转换版本和误差评估信息。病害记录至少包含病害类型、发现时间、置信度、参数信息、评级等级、关联模型版本、Element ID和空间坐标。

病害列表支持按病害类型、评级等级、时间范围筛选；点击列表项后定位并高亮模型中的构件和病害点，点击三维标记后打开病害详情。病害列表和三维场景共享统一筛选条件及版本上下文，避免模型切换后显示旧版本坐标。病害关联构件在版本更新后按跨版本映射更新视图；无法确认的映射会提示用户复核。

## 9 开放接口与安全

平台提供RESTful接口，采用JSON数据结构，接口定义遵循OpenAPI 3.0并交付完整接口文档、鉴权说明、错误码、请求示例和版本策略。开放查询接口支持按Element ID查询构件信息、几何引用、空间位置、自定义属性及关联病害；大型几何通过对象存储授权地址或分块服务返回，避免接口直接返回超大几何负载。

| 接口类别 | 示例路径 | 能力 |
| --- | --- | --- |
| 模型上传与导入 | `POST /admin-api/bim/models/upload/init`；`POST /admin-api/bim/models/import` | 分片上传、校验、创建异步导入任务 |
| 模型及版本 | `GET /admin-api/bim/models/{modelId}`；`GET /admin-api/bim/models/{modelId}/versions` | 模型信息、版本列表、状态和发布信息 |
| 构件查询 | `GET /admin-api/bim/models/{modelId}/components/{elementId}?modelVersionId=...` | 构件ID、几何引用、空间坐标、分类和自定义属性 |
| 空间查询 | `GET /admin-api/bim/models/{modelId}/spatial-query` | 点、包围盒或空间范围检索构件 |
| 坐标转换 | `POST /admin-api/bim/models/{modelId}/coordinates/transform` | 明确源/目标框架、模型版本和配准版本的三维坐标转换；图像定位由巡检病害API编排 |
| 配准检查 | `POST /admin-api/bim/models/{modelId}/alignment/check` | 控制点、检核点误差计算及报告查询 |
| 病害关联查询 | `GET /admin-api/bim/components/{elementId}/defects` | 按构件查询关联病害及定位信息 |
| 任务管理 | `GET /admin-api/bim/tasks/{taskId}` | 阶段、进度、错误及重试状态 |

接口通过现有网关认证、租户隔离、角色权限和审计机制保护。Worker回调使用服务身份及内部令牌/签名，并按任务ID、阶段和尝试次数幂等处理。上传文件进行大小、哈希、格式和路径校验；Worker采用独立进程或容器、资源配额、临时目录隔离和任务超时控制。

### 9.1 导入、发布与内部回调

| 方法与路径 | 约束 |
| --- | --- |
| `POST /admin-api/bim/models/upload/complete` | 校验上传会话归属、文件长度、摘要及源格式，返回受控源资产ID |
| `POST /admin-api/bim/models/import` | 使用源资产ID和冻结配置创建版本及任务；返回`202`及模型/版本/任务ID |
| `POST /admin-api/bim/tasks/{taskId}/cancel`、`/retry` | 校验状态、权限和幂等；手动重试返回新任务ID |
| `POST /admin-api/bim/versions/{modelVersionId}/publish`、`/rollback` | 校验预期当前版本及发布权限；回滚目标必须已发布且产物完整 |
| `GET /admin-api/bim/models/{modelId}/component-mappings` | 指定来源/目标模型版本，返回映射方法、置信度及复核状态 |
| `POST /internal-api/bim/tasks/{taskId}/heartbeat`、`/progress` | 服务身份、尝试号、租约令牌及输入快照必须一致 |
| `POST /internal-api/bim/tasks/{taskId}/components/batch`、`/artifacts` | 有界批次上报或暂存资产引用；不允许Worker提供任意数据库主键或任意文件路径 |
| `POST /internal-api/bim/tasks/{taskId}/complete`、`/fail` | 幂等提交结果，由BIM服务检查后变更任务状态；完成回调不直接激活版本 |

构件、空间、坐标和病害聚合查询均带版本上下文，响应回显版本和坐标框架。病害写入走巡检病害服务；BIM病害聚合查询通过受鉴权内部API取数，不跨库查询。请求中对象ID采用字符串，分页使用稳定排序；错误至少区分不支持版本、引擎不可用、输入损坏、缺少依赖、租约失效、映射待复核及发布冲突。

## 10 数据与部署设计

核心数据包括模型、模型版本、导入任务、构件、构件属性、空间摘要、跨版本映射、坐标变换、发布产物、病害关联及任务事件。关系数据库保存查询字段和审计信息，长尾构件属性使用结构化JSON或属性表，模型原文件、GLB、3D Tiles、纹理及检核报告存入对象存储。空间查询依据实际查询负载配置空间索引；消息队列用于任务解耦和恢复，不作为业务状态的唯一存储。

### 10.1 领域表与主要约束

下表为逻辑模型，正式字段类型及迁移脚本在接口细化阶段确定。新表沿用租户、应用、项目、审计及逻辑删除规范；跨服务对象使用逻辑引用。

| 表 | 主要内容 | 关键约束或索引 |
| --- | --- | --- |
| `bim_model` | 逻辑模型、项目引用、名称、当前发布版本、修订号 | 租户/项目查询索引；默认版本必须属于本模型 |
| `bim_model_version` | 版本号、源资产/摘要、格式、引擎、配置快照、配准及发布状态 | 模型内版本号唯一；发布后不可覆盖 |
| `bim_upload_session` | 上传归属、分片会话、长度/摘要、有效期和完成状态 | 会话唯一；完成操作幂等；过期会话清理 |
| `bim_task` | 输入快照、阶段、状态、尝试号、租约、心跳、幂等键、错误和父任务 | 租户/项目/操作范围内幂等唯一；按状态和心跳索引回收 |
| `bim_component` | 稳定Element ID、逻辑模型归属、创建和退役信息 | 平台Element ID全局唯一，不随版本覆盖 |
| `bim_component_version` | 模型版本、Element ID、源标识与实例路径、属性、空间摘要和几何引用 | 版本内Element ID唯一；版本内源实例身份唯一；名称/分类及范围检索索引 |
| `bim_component_property` | 构件版本、参数标识、属性集、原始值、显示值、类型和单位 | 构件版本/属性集/参数身份唯一；允许同显示名称的不同参数 |
| `bim_component_mapping` | 来源/目标版本及构件、匹配方法、置信度、复核与关系类型 | 支持一对多/多对一；已确认结果保留审计，禁止静默覆盖 |
| `bim_coordinate_transform` | 配准修订、源/目标框架、单位、投影/局部变换、控制点及独立检查报告 | 模型版本引用固定修订；已发布修订不可修改 |
| `bim_artifact` | 模型版本、格式、资产ID、对象键、摘要、清单及构件索引 | 版本内资产身份唯一；回收前检查业务引用 |
| `bim_release_record` | 发布/回滚前后版本、操作者及时间 | 每次版本指针变更追加记录 |
| `bim_task_event`、`bim_outbox`、`bim_inbox` | 任务诊断、待发领域事件和消费去重 | 回调事件幂等；发件箱可重试；消费者/事件ID唯一 |

病害正文和关联锚点归巡检病害服务，场景引用和设备/构件绑定归三维服务；BIM可保存只读引用登记用于回收保护，不反向成为第二套病害或场景主数据。

### 10.2 空间、属性与资源访问

三维空间摘要采用双精度位置和六维包围盒数值，统一注明坐标框架；按项目、模型版本和楼层/分区粗筛后做三维范围判断。MySQL二维空间索引按需要辅助筛选，不能代替三维相交或精确几何命中。几何命中通过已发布几何和构件索引执行，结果记录命中来源与版本。

稳定检索字段使用结构化列，长尾参数按属性集保存；常用条件按实际查询建立索引，不对所有JSON属性无差别建索引。构件分页及批量写入保持有界，几何、纹理和源模型通过授权资源访问，详情接口只返回摘要及资源引用。

生产环境按API服务、解析Worker、RVT运行节点、几何发布Worker及数据存储分别部署和配置资源。API服务可水平扩展；解析和发布Worker按队列积压、CPU、内存及磁盘使用情况扩缩。RVT节点单独受控，按目标Revit版本和许可部署。采用健康检查、优雅退出、僵尸任务回收、日志指标告警、对象存储版本保护、数据库备份和故障恢复演练。

## 13 验收资料与保障措施

项目交付模型格式及样本报告、接口与OpenAPI文档、架构及部署说明、坐标配准报告、构件ID与版本映射说明、性能测试报告、安全配置说明、运维手册和培训材料。性能及精度报告记录测试模型、硬件、网络、软件版本、测量口径及结果，保证指标可复核。

针对RVT引擎和许可、IFC样本差异、现场坐标基准、首屏模型复杂度等关键条件，项目启动阶段确认样本和环境，形成双方签字的测试基线；正式验收按同一基线执行。任务失败保留错误码、阶段日志和输入哈希，支持可恢复重试；新版本未通过完整性校验前不影响当前稳定版本。通过独立Worker、不可变版本产物、权限隔离和备份恢复保障系统稳定运行。
