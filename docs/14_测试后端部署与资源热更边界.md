# 测试后端部署与资源热更边界

本地 `jtyf-cloud` 是三维编辑器后端的唯一源码。测试服务器 `192.168.10.148` 的旧服务已由本工程的三维、系统权限、基础设施和网关替代。部署、备份、授权、验证与回退步骤见[部署记录](../deploy/test148/README.md)。

初始部署使用独立库 `wx_editor_test148`，81 张核心表统一使用 `wx_` 前缀；初始映射见[表名清单](../deploy/test148/table-map.json)。ART-01 增量迁移后为 82 张表，新增一张资源操作表，原映射保留为部署基线。实体映射、手写查询、租户忽略表和单元测试 SQL 的前缀已同步。未部署模块不受本轮命名迁移影响。

资源模板沿用转换资源主表模型，目标表为 `wx_dim3d_resource`，资源不绑定项目。`wx_dim3d_model`、`wx_dim3d_icon`、`wx_dim3d_template` 继续承载目录；`wx_resource`、`wx_resource_info` 等保留旧业务兼容用途。不能把旧 `metabase_3d.assets` 直接视为本系统的资源主表。

资源热更的目标仍为“资源 ID 不变，完整上传并校验新内容后，在数据库事务中更新当前内容指针”。场景实例保留稳定资源 ID，重新进入场景时解析当前内容，已加载的旧实例不会被后台静默替换。

权限目标为跨租户全局系统资源和租户共享资源两类：平台超级管理员维护全局资源，本租户超级管理员维护租户资源，普通用户读取全局及本租户共享资源。ART-01 已落库显式范围字段，约定全局资源所有者为字符串 `0`；ART-02 候选服务已通过 40 项真实身份/范围/操作检查，但主服务未切换。不能把现有 `resource_belong=SYSTEM` 或历史 `tenant_id=000000` 当作全局权限。

本轮没有迁移旧服务的 7 条资源记录，也没有完成 MinIO 美术包替换及浏览器效果验收。ART-01 已固定[数据及接口合同](15_资源模板数据结构与接口合同.md)，并整理[21 张相关表结构](16_资源相关表结构清单_ART01.md)；结构和回退结果见[ART-01 证据](evidence/backend-art01-20261029/README.md)。ART-02 候选授权/读取结果见[ART-02 证据](evidence/backend-art02-20261029/README.md)。后续进入 ART-03 单资源对象校验和替换事务。
