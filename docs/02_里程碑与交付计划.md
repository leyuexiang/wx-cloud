# 里程碑与交付计划

版本：V1.1 评审稿。日期：2026-10-31。对应设计：[01 项目总体设计](01_项目总体设计.md)。

## 1. 计划口径与人员假设

以相对工作周 W1～W28 表达完整平台参考节奏。W1 从范围、人员和环境确认后的实际启动周起算，不按本文日期自动开工。该窗口是初步估算，不是已确认工期；M0 后按差异清单重估。

参考人员：两名后端、一名前端、一名 Unity/图形工程师、一名模型/物联集成工程师、一名测试工程师，共六名主要执行人员；架构、业务和运维按阶段参与。模型及物联默认由同一岗位先后承担，不同时排满两条主线。若人员、专项范围或外部依赖不同，调整窗口，不通过减少验收维持日期。

M2 交付首个编辑保存闭环，M3 完成完整二维、模板和发布，M4 接入 Unity 双端。后续行业领域不作为首批可用性的前置条件。

## 4. Unity 和行业专项工作包

### 4.1 M4：双端图形交付

核对 Unity 权威工程、实际版本、StartScene、构建参数和产物；冻结 Web/Windows 资源兼容矩阵。统一对象身份和场景代次，覆盖选中、变换、删除、清场、重载和主动事件。联调真实资源、地址续签、损坏包、缺依赖及权限拒绝。

信令/启动器能力确认后落地申请、续租和释放。两端分别记录画面、日志、资源占用和释放结果；一端成功不替代另一端，首帧不替代编辑交互。

### 4.2 M5：BIM 与模型数据

以 建筑模型及 RVT 验证专项为基础，让真实源文件经隔离工作进程产出可校验的几何、构件、属性、坐标和清单，再完成业务版本和场景绑定。重试不污染成功产物。模型容量、构件规模、首屏、解析成功率和精度分别测量，冻结样本及硬件后判定；RVT 由依赖支线落实。

### 4.3 M6：物联及数据通道

先找回可构建 IoT 权威源码，确认与现有服务器版本及维护归属。选择一种有真实设备/平台的协议，冻结身份、单位、事件时间、质量、幂等和回执。

遥测、业务接口拉取和媒体分开验收。媒体复用已有网关设计，接入新认证时核对用户及成功码检查；可播放不代表有设备控制权限。

### 4.4 M7：行业业务

先选一个可复现试点：设备温度异常 → 告警 → 人工确认 → 派单/审批 → 受控处置 → 回执关闭，再加入病害证据和构件绑定。告警、流程、命令各自维护权威状态，不直接改写其他领域表。

模型配准、图像定位和构件评级分别验证。缺少真值时可验收人工录入/复核，但不宣称自动定位精度达标。

## 6. 测试与验收门槛

| 层次 | 验证范围 | 时点 |
| --- | --- | --- |
| 合同测试 | 路径、请求头、封套、类型、编号、分页及错误 | M0 起持续 |
| 单元测试 | 身份、状态、范围、四包、幂等及冲突 | 每项新增行为 |
| 基础设施集成 | MySQL 真事务/并发、缓存失效、对象校验及清理 | M2 起持续 |
| 浏览器业务 | 登录、编辑保存重开、模板、发布及授权 | M1～M3 |
| 引擎及格式 | 两端真实播放器、资源和 IFC/RVT 产物 | M4～M5 |
| 外部及现场 | 遥测/命令、视频、定位和业务流程 | M6～M7 |
| 发布运维 | 负载、安全、迁移、备份恢复和回退 | 各批验证，M8 综合演练 |

复杂逻辑先失败用例再实现。关键安全、一致性及状态分支逐项覆盖；覆盖率不替代业务验收。模拟、真实接口、真实画面和现场测量分开记录，历史报告不抵扣新增能力验证。

每阶段须同时具备正常流程、拒绝路径、失败恢复、合同、部署回退和证据，才标为完成。代码完成但待真实联调或用户验证，登记为“待联调/待验收”，不能计入已交付能力。

## 7. 发布及变更治理

各里程碑形成可部署批次，登记源码/差异、前端与 Unity 构建、程序包摘要、迁移和配置版本。先隔离验证，再试点切换，观察指标后扩大。

迁移优先新增字段/表和兼容读写。程序包能回退不等于可删除已有新业务数据；优先前向修复。每批准备自己的回退方案，不重复借用“退回 metabase”的一次性部署脚本。

范围变化记录收益、合同/数据影响、测试和工期，由业务与技术负责人确定进入哪个批次。不能用新增功能挤占已冻结的安全、并发和恢复验收。

## 8. 立即执行的首轮工作

1. 收敛两端角色及首批业务范围，把普通使用者和管理员动作列清。
2. 完成首批真实请求清单：认证、字典、场景管理、锁、四包保存、普通文件。
3. 冻结租户识别、应用登记、保存必填和冲突语义，建立样例及错误规则。
4. 盘点新库现有数据，设计增量结构和基础配置迁移，保留 82 表部署基线。
5. 从前端真实四包生成失败测试样例，覆盖混合场景、长编号和未知依赖。
6. 登记 Unity、IoT、解析器、样本及许可依赖，由实际负责人填报到位时间。

本轮完成设计和计划，后续首先推进 M0/M1，再按 M2/M3 形成用户可用闭环。六人及 28 周仅是参考规划假设，须在 M0 后重估并据实际资源排定周计划。
