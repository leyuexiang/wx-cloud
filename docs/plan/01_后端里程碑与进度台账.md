## 4. 下一节点交付要求

`IOT-M1` 的设计范围及故障边界见[专项设计第 4、6 节](../design/05_IoT动态多连接接入方案.md)。

- **输入**：现有连接器、绑定、MQTT 适配器、租约及接收链路；部署租户范围；连接数量和并发上限配置。
- **交付**：动态发现与多会话管理、有效配置版本及迟到状态防护、有界建连执行器、独立故障退避、退出清理、单连接模式兼容策略。
- **验收**：同进程至少两个连接独立运行；新增、变更、停用无需重启；一个代理故障不阻塞另一个；旧回调及失租约实例不能误确认或覆盖状态；资源回收可核验。
- **限制**：凭据仍用环境变量时，只支持已注入引用；新秘密的后台动态新增及轮换另归 M2。首版保持 MQTT 3.1.1、通用单点 JSON 和确切主题，不捆绑工业协议或多租户全表扫描。
- **联调条件**：真实 Broker 和账号未落实时可以完成本地实现与相应验证，不能将该节点写成真实环境已验收。配置变化的旧会话积压处理需明确，不能承诺无中断、无丢失切换。
