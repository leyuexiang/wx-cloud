## 1. 文档用途与唯一维护规则

本文档集中记录管理界面与三维编辑器已经确认或明确补充的真实接口契约，包括路径、请求参数、响应字段、鉴权、字段映射、调用顺序、验收状态和未提供能力。

本文由类似项目的历史接口文档适配而来。当前项目为 `wx-cloud`，2026-11-17 本轮核对范围为本地控制器、框架前缀和网关配置。第 2.2 节及各节“当前项目”说明记录本轮路径结果；历史请求字段、前端实现和 2026 年 9 月验收记录保留原项目来源，当前项目接入时还需对照相应合同与实际响应。

用户确认两套接口业务逻辑基本一致，差异主要在查询数据来源和请求路径的中间拼接段。本文沿用原有业务流程与字段说明，按当前项目补充完整路径、平台段映射和查询数据归属。对源码中确有差异的发布、预览等入口，保留对应说明。

本文维护人工阅读的接口路径说明，机器可读契约及专项规则沿用 `contracts/editor/`、`contracts/art01/` 和模型专项合同。修订时同步相关差异，任务状态统一维护在 03。

接口状态按当前项目源码、调用链和对应版本的证据维护。

| 状态 | 含义 |
| --- | --- |
| 源码已接入 | 当前业务页面或适配器有实际调用，后端存在对应入口，仍需注明契约差异及联验范围 |
| 部分接入 | 已接入部分操作或部分分支，剩余分支存在明确差异或缺口 |
| 仅后端实现 | 后端有对应入口，当前消费者链路中未发现调用 |
| 已有类似接口，契约不一致 | 已实现同类能力，但路径、方法、请求、响应、数据域或鉴权存在差异，详见差异表 |
| 前端有调用，后端缺对应入口 | 当前前端仍请求文档路径，源码与网关中未找到对应实现或映射 |
| 待当前联验 | 当前源码的真实请求、页面行为、权限或失败分支证据尚待补齐 |

### 2.3 请求头与编号

- 登录态管理接口复用当前会话的 `Authorization`、`ClientId` 及现有 `tenant-id` 处理，由 `getDim3dHeaders()` 等既有请求入口注入。可信身份由服务端认证与租户上下文判定。
- 当前匿名发布读取使用专用请求头 `X-Scene-Ticket`，具体路径见第 9.4 节。原项目会话解析与五个分片接口的鉴权约定仅适用于其历史实现。
- 联调临时令牌和客户端编号来自浏览器本地存储：`jtyf.dim3d.temp-token`、`jtyf.dim3d.client-id`；令牌允许纯令牌或带 `Bearer` 前缀。
- OpenAPI 的 `int64` 编号、响应中的 `id`、`ossId`、`modelFileId`、`sceneId` 均按字符串序列化和保存，禁止转换为 JavaScript 数字。
- 页面不得提供鉴权按钮或弹窗；权限失败应保留后端返回的业务码和原文，并按页面约定提示。

- 2026-11-18 起两个测试网关对携带令牌的请求逐次调用权威身份校验。退出/管理撤销后开始的新校验不复用本地旧身份，保护接口按既有错误约定拒绝；认证依赖网络、超时、异常响应或非预期业务失败返回 HTTP `503` 且不访问业务下游。明确无效令牌及匿名公共接口保持原语义，已开始请求/已建立连接不承诺追溯取消。源码及候选/正式验证见[网关撤销证据](evidence/gateway-auth-20261118/README.md)。

### 2.4 响应与分页

- 当前通用响应 `CommonResult` 通过 `GlobalErrorCodeConstants.SUCCESS` 返回业务成功码 `200`。前端兼容适配还需结合实际部署版本，直接调用当前服务时按实际响应校验。
- 模型分页由 `Dim3dModelPageResponse` 返回根级 `code`、`msg`、`total`、`rows`；图标与文件型模板当前返回 `CommonResult<PageResult>`，分页在 `data.list`、`data.total`；场景分页返回 `CommonResult<Map>`。分页结构按对应接口读取。
- 详情通过 `data` 返回。模型新增、编辑、删除成功时 `data=null`；MODEL-11 上下线成功响应也已统一为 `data=null`，本次调整已部署并通过接口验收。其他写入可能返回编号、布尔值或发布记录，按控制器响应及专项合同处理。
- MODEL-10 收敛后的模型详情及分页记录统一为参考的 16 个业务字段，使用独立响应对象。文件关联统一返回 `modelFileId`；`priceYuan` 为两位小数字符串，编号为字符串，时间格式为 `yyyy-MM-dd HH:mm:ss`，创建人与更新人名称来自系统用户批量查询。文件相对路径通过第 5.4 节资源详情获取，MODEL-12 已移除其中此前的签名及到期字段，本次调整已部署并通过接口验收。MODEL-10/11 已通过双入口发布验收，实际版本及结果见 MODEL-11-DEPLOY 台账；既有 MODEL-09 证据保留此前响应结构。
- 植被控制器直接返回任务、发布或动态窗口对象，创建和动态窗口使用 HTTP `202`，详见第 9.5 节。
- 权限失败保留实际状态码与消息，明确成功的空列表才展示暂无数据。

### 3.3 字段和枚举映射

- 模板类型：`INDUSTRY`（行业方案）、`EXHIBITION`（展厅模板）。
- 资源归属：`SYSTEM`（系统资源）、`MINE`（我的资源）。
- 模型付费状态：`FREE`（免费）、`PAID`（付费）。模型返回价格字段为 `priceYuan`，写入字段为 `price`，转换必须集中在适配层。
- 上线状态：`ONLINE`（已上线）、`OFFLINE`（已下线）；路径中的 `{status}` 只提交后端约定值。
- 模型上下线使用 `PUT /admin-api/dim3d/model/{status}/{id}`，无需请求体，要求 `dim3d:model:edit`。MODEL-11 已统一历史及受管模型的状态维护，成功返回 `code=200`、`data=null`；同状态重复请求成功并保全原更新审计。系统目录要求平台维护权限，个人目录限定当前租户及账号，已删除目录拒绝操作。本次调整已部署，状态及验证见 MODEL-11-DEPLOY 台账。
- 缺失值统一展示 `--`，不得以常量、随机值或其他字段替代真实值。

### 3.4 图标目录响应与维护

- 分页及详情记录共用 `id/iconName/iconDesc/category/secondaryCategory/resourceBelong/iconFileId/status/createBy/createByName/createTime/updateBy/updateByName/updateTime`。详情记录位于 `data`；编号以字符串返回，审计时间为 `yyyy-MM-dd HH:mm:ss`，操作人名称通过系统用户批量查询，查无名称时返回空值。
- 分页默认编号倒序，单页最多 200 条。`orderByColumn` 可为 `id/iconName/category/secondaryCategory/resourceBelong/status/createTime/updateTime`；`isAsc` 接受 `asc/desc`，忽略大小写。同值记录按编号倒序，非法排序返回业务码 `400`。
- 新增及编辑提交第 3.2 节必填字段，可附 `iconDesc` 和 `secondaryCategory`。新增按图片上传专项合同返回字符串目录编号，编辑、删除及上下线成功返回 `code=200`、`data=null`。上下线仅接受 `ONLINE/OFFLINE`，使用图标编辑权限，重复同状态保留原更新时间与操作人。
- 文件预览按 `iconFileId` 调用第 5.3 节普通文件查询，复用已冻结的文件归属、租户范围和授权。部署状态及验收见 [IMG-07](03_近期执行任务.md#img-07-图标目录接口契约对齐2026-11-18)。

### 3.5 文件型模板目录响应与维护

以下接口均要求路径参数 `publicationId: int64` 和必填查询参数 `ticket: string`；前端按全局规则把发布编号作为字符串传输和保存。OpenAPI 将 `Authorization`、`ClientId` 列为可选请求头，但公开票据预览的实际调用边界不变：入口解析和五个数据接口均不得发送这两个请求头。

| 能力 | 方法与路径 | 请求体 | 成功响应 `data` |
| --- | --- | --- | --- |
| 场景基础 | `GET /dim3d/scenePreview/published/{publicationId}/sceneBasic` | 无 | `AppPublishedSceneBasicVo`：`publicationId`、`sceneId`、`sceneJson` |
| 三维场景 | `GET /dim3d/scenePreview/published/{publicationId}/threeD` | 无 | `AppPublishedThreeDVo`：`publicationId`、可空 `sceneType`、`threeDJson` |

实例依赖 `items[]` 的真实结构如下：

```jsonc
{
  "instanceId": "88901789182541824",
  "resources": ["{...单条资源依赖 JSON 原文...}"],
  "dataBindings": ["{...单条数据绑定 JSON 原文...}"],
  "behaviors": ["{...单条行为 JSON 原文...}"],
  "deviceBindings": ["{...单条设备绑定 JSON 原文...}"]
}
```

同一响应的 `resourceMetas[]` 是发布级资源元数据字典。每项包含 `assetId`、`kind` 及资源描述字段；模型通过 `resourceRelativePath` 返回文件服务器相对路径，图片通过 `url` 返回直接可用地址。该字典是预览响应数据，不属于场景四包持久化内容。

植被资源已经在保存时登记到 `dependenciesJson.resources`，拥有者分别为 `vegetation-system`、`vegetation-layer`，不是普通实例。在本次接口补充前，公开预览接口只能按普通 `instanceId` 返回 `items` 依赖；发布级 `resourceMetas` 偶尔会包含已登记的物种模型元数据，但不会按植被聚合拥有者返回清单、根瓦片、图层瓦片和密度瓦片地址。前端不能用合成资源编号调用资源中心，也不能在公开页调用登录态植被历史接口补齐。2026-09-17 已在真实公开预览场景复现该缺口。

2026-09-17 对公开场景 `2100418491590856706` 追加验证：`dependenciesByinstances` 分别传入空数组、随机字符串和 `vegetation-system` 时，响应都会回显请求编号对应的 `items`，但各项 `resources` 均为空；同一响应仍返回 3 条物种模型 `resourceMetas`（包含 `assetId` 和 `resourceRelativePath`）。因此当前网关的 `resourceMetas` 表现为发布级资源字典，不能据此推断特殊 `instanceId` 已成为植被聚合拥有者，也不能把该行为固化为前端契约。

资源地址的实际关联链路是：`items[].instanceId` 只用于定位实例依赖，依赖正文中的 `resourceKey` 再指向 `assetId`，最后由 `resourceMetas[].assetId` 取得 `resourceRelativePath` 或 `url`。植被物种模型目前可通过发布级字典取得地址，但发布清单、根瓦片、图层瓦片和三档密度入口仍未返回；保存时写入特殊字符串或伪造普通实例编号不能补齐这些资源。

本次附件已为上述缺口提供独立只读接口：前端应按 `publicationId + ticket` 查询，并以场景发布快照绑定的 `publicationVersion` 为准，不回退到植被当前版本。接口返回物种模型、发布清单、根瓦片、图层入口、三档密度入口及瓦片子资源的受控访问信息；返回地址仅用于当前预览运行时，前端只合并到内存，不能回写四包或模板。由于本次仅补充了 OpenAPI 契约，真实网关是否返回完整资源和地址有效期仍待验收。

- 调用顺序：仅当 `resolve.resultCode=OK` 且同时取得 `publicationId`、`ticket` 后，首屏并行调用场景基础、三维和二维接口。三个包分别从 `sceneJson`、`threeDJson`、`twoDJson` 字符串解析，合并去重其中的实例编号后一次批量读取首屏实例依赖；若三维包包含植被运行时引用，再调用 9.4.3 接口读取发布快照资源，最后统一组装并根据 `sceneJson.sceneType` 选择地理信息场景运行时或局部三维运行时。
- 实例依赖：请求不携带域；响应按 `instanceId` 归属。四类数组元素均是 JSON 字符串，前端必须逐条解析并校验，不能把字符串直接交给依赖组装器，也不能静默忽略非法条目。首屏不得由逐对象挂载事件发送多个单元素请求；后续动态目标只读取尚未缓存的实例。
- 缓存边界：三个完整包按当前 `ticket + publicationId` 会话缓存；实例依赖按 `ticket + publicationId + instanceId` 缓存。漏项或解析失败项不得标记为已加载，以便后续重试。OpenAPI 未声明数组上限、部分成功语义和缓存控制响应头，待真实联调确认。
- 旧接口退出：前端不再兼容 `/dim3d/scenePreview/fragments/{publicationId}/manifest`、`threeDChunks`、`twoDFragments`、`behaviors` 和 `assetsResolve`。普通实例资源继续使用 `resourceMetas` 补全地址；植被聚合资源改用 9.4.3 接口，不再调用 `/dim3d/resource/info/{id}` 或 `/resource/oss/listByIds/{ids}`；结果只存运行时内存。
- 失败响应：五个接口均声明 HTTP `401` 字符串主体；其他业务错误保留后端 `code`、`msg` 原文。票据过期后清理当前会话缓存并重新解析，禁止改走旧接口。

#### 9.4.3 原项目发布植被运行时资源接口（历史）

| `generatorVersion` | 字符串 | 否 | 生成器协议版本，由服务端冻结覆盖，前端可不传 |
| `seed` | 64 位整数（`int64`） | 否 | 随机种子，不是编号 |
| `gridSizeM` | 双精度数（`double`） | 否 | 网格边长，米 |
| `originLongitude`、`originLatitude` | 双精度数 | 否 | 投影原点经纬度；本模型未声明数值上下限 |
| `elevationSource` | `ElevationSource` | 否 | 数字高程模型引用 |
| `generationRegion` | `GenerationRegion` | 否 | 正式生成范围 |
| `densityProfiles` | 字典，值为 `DensityProfile` | 否 | 高清（`high`）、均衡（`balanced`）、性能（`performance`）密度子集；键名来自描述 |
| `clipToGenerationRegion` | 布尔值 | 否 | 是否按生成范围裁剪；描述明确动态地块为 `true` |
| `dynamicTileId` | 字符串 | 否 | 动态地块编号；描述注明静态任务为空 |
| `idempotencyKey` | 字符串 | 否 | 长度 0—128；为空时服务端按快照生成幂等键 |

公共子模型：

| 模型 | 必填字段 | 其他字段与约束 |
| --- | --- | --- |
| 高程来源 `ElevationSource` | `url`、`version`、`verticalDatum`，均为非空字符串 | 高程数据地址、版本和垂直基准；未声明垂直基准枚举 |
| 生成范围 `GenerationRegion` | `polygon: GeoPoint[]`，至少 1 项 | 描述要求闭合多边形；至少 1 项只是导出的数组下限，不代表单点可构成有效范围 |
| 经纬度点 `GeoPoint` | 未声明 | `longitude`、`latitude` 均为双精度数，经度范围 −180—180，纬度范围 −90—90；未声明高程字段 |
| 物种 `Species` | `speciesId`、`assetId`、`assetUrl`、`assetKind`，均为非空字符串 | 可选 `assetVersion: string`、`weight`、`minimumScale`、`maximumScale`（后三者为双精度数）；资源类型描述仅接受二进制三维模型（`glb`），正式任务必须冻结资源市场稳定编号 `assetId` |
| 密度配置 `DensityProfile` | 未声明 | `densityRatio: double` 范围 0.0001—1；`selection: string` 描述仅支持稳定子集（`stable-subset`）；`tileSizeM: int32` 范围 1—10000 米 |

规则模型 `VegetationRule` 仅将非空字符串 `ruleId` 列为必填，其余字段如下。按规则类型提交业务需要的字段；类型间的条件必填关系未在本次模型中完整表达。

| 字段组 | 字段与类型 | 取值或用途 |
| --- | --- | --- |
| 规则类型 | `type: string` | 多边形（`polygon`）、行道树走廊（`corridor`）、海拔分带（`altitude-zonation`）；正式枚举 |
| 通用归属 | `layerId: string`、`seedOffset: int32` | 图层编号、种子偏移 |
| 几何 | `polygon: GeoPoint[]`、`path: GeoPoint[]` | 多边形与行道树路径；规则内数组未声明最小项数 |
| 分布 | `distribution: string` | 描述列出泊松（`poisson`）、网格（`grid`）、随机（`random`），未声明正式枚举 |
| 密度与坡度 | `densityPerHectare`、`minimumSpacingM`、`minimumSlopeDegrees`、`maximumSlopeDegrees` | 均为双精度数；依次为每公顷密度、最小株距（米）、最小与最大坡度（度） |

| 分带空隙 | `gapPolicy: string` | 留空（`leave-empty`）、拒绝（`reject`）；正式枚举 |

#### 9.5.4 原项目动态九宫格请求及响应（历史）

动态请求模型 `AppVegetationDynamicTileWindowBo` 必填 `generation: AppVegetationGenerationBo` 与 `tiles: Tile[]`，其中地块数组下限和上限均为 9；可选 `protocolVersion: int32`。后端代码已将协议版本固定为 `1`，版本变化必须递增并使旧缓存失效。九块共享规则快照，每块分别提交几何与缓存身份。

| 模型 | 必填字段 | 可选字段 |
| --- | --- | --- |
| 地块 `Tile` | `tileId: string`（非空）、`polygon: GeoPoint[]`（至少 1 项，描述为闭合边界）、`cacheIdentity: CacheIdentity` | `latitudeRow`、`longitudeColumn`、`longitudeColumnCount`（32 位整数）；`originLongitude`、`originLatitude`（双精度数，分别限定 −180—180、−90—90） |
| 缓存身份 `CacheIdentity` | `sceneId`、`ruleVersion`、`tileId`（均为非空字符串） | `protocolVersion: int32`、`seed: int64`、`elevationSource: ElevationSource` |

缓存身份模型说明：客户端提交结构化身份便于审计；真正缓存等价性由服务端依据规范化快照和高程数据计算。当前无 TTL、主动清理、最大并发数或真正限流，生成器调用按九块串行投递，连接超时 3 秒、读取超时 10 秒。

后端代码核对已确认响应地块包含 `tileId`、`status`、`taskId`、`tilesetUrl`、`sourceHash`、`errorMessage`；状态为 `HIT/PENDING/RUNNING/FAILED`，协议版本固定为 `1`，请求必须为 9 块，响应保持请求顺序且逐块隔离失败。`READY` 为遗留枚举，当前不会返回；`PARTIAL_FAILED` 会折叠为 `FAILED`。这些结论来自后端源码，仍需一次真实动态请求验证传输层实际返回。

#### 9.5.5 原项目调用顺序、现有差异与验收边界（历史）

以下调用约束结合附件契约、前端实现和 2026-09-17 后端代码答疑整理；标注为“待决策”的内容不属于接口调用可直接推断的事实。

- 静态生成：冻结规则、物种资源编号与高程版本 → 创建任务取得字符串 `taskId` → 查询状态 → 仅 `SUCCESS` 任务允许发布 → 读取当前版本确认。生成成功不代表已经发布；用户取消任务后，前端无论迟到查询返回何种状态都禁止发布该任务，必须重新生成；取消后的生成器最终停止语义仍待后端/生成器处理。取消后读取真实任务状态，不因请求发出就展示“已取消”。
- 发布与回滚：发布返回当前稳定版本视图；回滚版本来自该场景历史记录，放入查询参数 `publicationVersion`，不能放入请求体。发布、取消和回滚的重复请求按后端实现具有幂等或状态复用行为；取消任务的前端发布禁用规则已经确定，取消与查询竞态的后端最终状态问题先记录后续处理。无当前版本时的空数据语义仍待确认。
- 整场发布：调用 `POST /dim3d/scene/publish/{id}` 前，前端读取当前修订的 `threeDJson.vegetation.publication`，再调用植被当前版本接口，严格比较 `publicationVersion`、`ruleVersion` 和 `sourceHash`；无植被字段的普通场景沿用原流程，植被引用缺失、服务端版本缺失或任一字段不一致时阻止发布。整场发布不冻结植被，校验通过后才发起场景发布请求。
- 幂等与并发：创建请求使用显式键或服务端按规范化快照生成的永久键；同键同快照复用任务，同键不同快照返回业务码 `400`。唯一索引当前不含租户编号，跨租户显式同键可能落为 `500`，需后端修正或接受该边界。发布与回滚由场景数据库行锁串行，生成任务查询与取消没有乐观锁，存在后提交覆盖先提交的风险。
- 生命周期与性能：任务查询只覆盖活动任务，终态停止轮询，离开页面清理计时器和未完成请求。动态窗口一次提交九块，响应固定九块且按请求顺序返回；单块失败隔离为 `FAILED`，其余地块继续可用。当前九块生成器调用串行，最坏等待约 117 秒，是否改为异步批量投递待性能和运维决策。
