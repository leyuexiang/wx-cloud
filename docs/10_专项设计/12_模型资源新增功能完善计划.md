# 模型资源新增功能完善计划

更新日期为 2026-11-13。本次按用户要求参照现有图片新增流程收敛方案。后续实施以本文为准，任务状态和历史验证统一维护在 [03 近期执行任务](../03_近期执行任务.md#model-00-模型资源新增功能完善计划2026-11-12)。

## 1. 交付目标与用户流程

用户在现有弹窗中完成新增，操作保持四步。

1. 填写名称、分类、归属等信息，按需选择封面和计费。
2. 选择一个模型压缩包，页面自动上传并等待后台转换，显示文件名和处理结果。
3. 点击保存，成功后关闭弹窗并刷新列表。
4. 在列表中查看封面、详情和模型预览，刷新页面后结果一致。

页面交互以“上传中、处理中、上传成功、失败”为主。转换耗时较长时由上传适配自动等待或查询结果，用户通过原弹窗完成操作。目录成功落库后显示新增成功。

## 2. 本轮范围

| 项目 | 实施范围 |
| --- | --- |
| 模型文件 | 单个 ZIP 压缩包，包含一个 OBJ、FBX 或 3DS 主模型及依赖文件，沿用 500 MiB 上限 |
| 转换结果 | 当前页面默认生成二进制模型格式（GLB），复用现有转换服务和已验证的输入格式 |
| 目录字段 | 名称、描述、分类、归属、可选封面、免费或付费状态及价格，覆盖当前弹窗已有字段 |
| 查询展示 | 保存后刷新列表、分类数量和封面，详情、刷新重开及现有预览正常 |
| 身份与权限 | 复用场景列表相同的登录、租户和模型新增或编辑权限 |
| 存储 | 复用 148 服务器已有对象存储服务 MinIO，服务端维护连接和凭据 |
| 部署 | 代码提交推送后由服务器拉取、构建和更新，按实际两个目标库核对必要增量 |

文件替换的高级恢复、专门任务管理页面、断点续传、批量导入、新源格式、交易支付、完整场景保存重开及运行端专项兼容列入后续任务。先交付当前新增、保存和查看闭环。

## 3. 参照图片新增的实现方式

图片页面现有做法是上传文件取得编号，再由保存接口写入目录并刷新列表。模型沿用这层分工，模型特有的转换由后端负责。

| 环节 | 前端职责 | 后端职责 |
| --- | --- | --- |
| 文件上传 | 选择文件、检查空文件和大小、调用上传适配、显示结果 | 校验权限和文件，调用转换服务，检查产物并存入 MinIO，返回保存所需标识 |
| 保存目录 | 校验表单，提交模型标识及业务字段 | 验证分类、归属、封面和价格，关联模型内容与目录并提交事务 |
| 列表与预览 | 保存成功后刷新，用户点击查看或预览 | 返回正确目录数据和已有授权读取结果 |
| 失败处理 | 保留表单，显示可理解的原因，支持重新上传或再次保存 | 返回明确业务错误，保持已有可用数据，回收本次失败产生的临时文件 |

文件摘要、存储路径、转换阶段和资源提交由后端及现有适配层管理。页面使用统一的模型上传和保存方法，操作编号、签名上传和内部阶段保持为实现细节。

上传优先通过现有业务后端完成，浏览器和接口调试工具（Postman）使用相同的登录信息调用。后台沿用现有转换、文件和受控资源服务，复用已经实现并验证的能力。

## 4. 接口与数据约定

### 4.1 优先复用现有入口

下表为现有源码入口，后续围绕这些入口完成必要适配。

| 入口 | 简化后的用途 |
| --- | --- |
| `POST /admin-api/dim3d/resource/uploadConvert` | 模型文件上传和后台转换的统一入口，返回可用于保存的模型标识 |
| `POST /admin-api/dim3d/model/add` | 当前新增弹窗的统一保存入口，提交完整业务字段并完成目录关联 |
| `GET /admin-api/dim3d/model/page`、`GET /admin-api/dim3d/model/info/{id}` | 列表和详情读取 |
| 现有封面上传与编号读取接口 | 沿用图片上传能力 |
| 现有资源内容及成员读取接口 | 由预览适配调用，维持已有读取权限和固定内容关系 |

旧上传接口与服务器实际转换器的返回协议需要在后端适配。已有模型导入的内部步骤由后端编排，现有受管资源提交和归属校验继续复用。耗时处理的等待或状态查询封装在上传适配中。

### 4.2 字段规则

- 名称去除首尾空白后为 2～50 字符，描述沿用 500 字符上限并允许空描述。
- 分类使用现有启用模型字典。字段无效时返回清晰错误，用户修正表单后再次保存。
- 系统与租户归属使用当前枚举，用户、角色和租户从已有登录信息解析。
- 封面复用图片文件编号和归属校验，支持 PNG、JPEG、WebP，大小沿用 5 MiB 上限。
- 计费沿用现有免费或付费规则。页面显示元，后端按整数分保存，校验小数位和溢出。
- 受管模型沿用稳定 `resourceId`，历史 `modelFileId` 在服务端或既有适配边界兼容。目录编号继续用于目录操作。
- 保存事务共同维护目录、模型关联和封面归属，失败时回滚相关写入。重复点击保存应得到同一新增结果。

## 5. 控制复杂度的执行原则

1. 每项改动对应当前弹窗的上传、保存、列表或预览结果，或者这些操作实际遇到的权限、一致性和性能问题。
2. 优先修改现有页面、接口适配和服务。已有校验、转换、存储、权限及资源提交能力直接复用。
3. 业务请求通过已有登录令牌和方法权限校验，跨域来源沿用系统配置，兼容多个本地前端、局域网前端和无来源头的接口调试请求。
4. 文件采用流式处理并核对上传上限和请求时限。必要摘要在后端计算，处理结束释放文件流、临时文件和查询循环。
5. 数据变更依据当前上传或保存的真实结构缺口制定增量，先备份并保留现有数据。删除与场景引用表的差异归入对应操作的后续核对。
6. 验证复用已有有效证据，代码或配置变化后检查受影响路径。用户实际模型的网页上传、保存和回读作为本轮重点。
7. 发现额外优化机会时登记到后续项，当前新增闭环优先。范围确需变化时先更新本文，记录具体用户收益及技术依赖。

## 7. 本轮验收

1. 使用用户实际模型压缩包，从现有新增弹窗完成自动上传转换和一次保存。
2. 名称、描述、分类、归属、封面及计费字段保存正确，列表刷新和重新打开详情一致。
3. 模型预览可读取实际模型文件，封面来自实际上传的图片。
4. 非法文件、无效分类、缺失贴图及无权限请求给出明确失败，表单可修正或重新上传。
5. 重复点击和请求重试保持单条目录，保存失败保持已有可用内容。
6. 多个本地或局域网前端以及 Postman 通过现有登录方式调用，部署版本、必要迁移和回退有记录。

新增闭环验收后，继续按 MODEL-07 检查文件替换、场景加载和保存重开，沿用项目已有运行端联调要求。
