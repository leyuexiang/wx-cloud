# 模型资源新增功能完善计划

更新日期为 2026-11-13。本次按用户要求参照现有图片新增流程收敛方案。后续实施以本文为准，任务状态和历史验证统一维护在 [03 近期执行任务](../03_近期执行任务.md#model-00-模型资源新增功能完善计划2026-11-12)。

2026-11-16 用户追加保存成功后列表为空和运营端个人测试资源需求。本轮接续 MODEL-06 的列表与详情范围查询，运营端与租户端管理员均可上传我的资源。列表和详情共用系统资源公共可见、我的资源限定上传账号的条件，保留现有分页和筛选参数。历史个人目录以 data_user_id 为主，缺失时使用 create_by，均缺失时不推断所有者。预览、场景引用及删除仍按后续任务接续。

## 1. 交付目标与用户流程

用户在现有弹窗中完成新增，操作保持四步。

1. 填写名称、分类、归属等信息，按需选择封面和计费。
2. 选择一个模型压缩包，页面自动上传并等待后台转换，显示文件名和处理结果。
3. 点击保存，成功后关闭弹窗并刷新列表。
4. 保存成功后触发现有列表刷新。

页面交互以“上传中、处理中、上传成功、失败”为主。转换耗时较长时由上传适配自动等待或查询结果，用户通过原弹窗完成操作。目录成功落库后显示新增成功。

## 2. 本轮范围

| 项目 | 实施范围 |
| --- | --- |
| 模型文件 | 单个 ZIP 压缩包，包含一个 OBJ、FBX 或 3DS 主模型及依赖文件，沿用 500 MiB 上限 |
| 转换结果 | 当前页面默认生成二进制模型格式（GLB），复用现有转换服务和已验证的输入格式 |
| 目录字段 | 名称、描述、分类、归属、可选封面、免费或付费状态及价格，覆盖当前弹窗已有字段 |
| 保存后刷新 | 新增成功后触发现有列表刷新；列表归属筛选、分类数量及预览适配接续 MODEL-06 的独立列表任务 |
| 身份与权限 | 复用场景列表相同的登录、租户和模型新增或编辑权限 |
| 存储 | 复用 148 服务器已有对象存储服务 MinIO，服务端维护连接和凭据 |
| 部署 | 代码提交推送后由服务器拉取、构建和更新，按实际两个目标库核对必要增量 |

文件替换的高级恢复、专门任务管理页面、断点续传、批量导入、新源格式、交易支付、完整场景保存重开及运行端专项兼容列入后续任务。本批交付上传、归属与账号记录、保存及成功后刷新。列表筛选和预览按后续独立任务接续。

## 3. 参照图片新增的实现方式

图片页面现有做法是上传文件取得编号，再由保存接口写入目录并刷新列表。模型沿用这层分工，模型特有的转换由后端负责。

| 环节 | 前端职责 | 后端职责 |
| --- | --- | --- |
| 文件上传 | 选择文件、检查空文件和大小、调用上传适配、显示结果 | 校验权限和文件，调用转换服务，检查产物并存入 MinIO，返回保存所需标识 |
| 保存目录 | 校验表单，提交模型标识及业务字段 | 验证分类、归属、封面和价格，关联模型内容与目录并提交事务 |
| 保存后刷新 | 新增成功后通知现有列表刷新 | 返回新增提交结果 |
| 失败处理 | 保留表单，显示可理解的原因，支持重新上传或再次保存 | 返回明确业务错误，保持已有可用数据，回收本次失败产生的临时文件 |

文件摘要、存储路径、转换阶段和资源提交由后端及现有适配层管理。页面使用统一的模型上传和保存方法，操作编号、签名上传和内部阶段保持为实现细节。

上传优先通过现有业务后端完成，浏览器和接口调试工具（Postman）使用相同的登录信息调用。后台沿用现有转换、文件和受控资源服务，复用已经实现并验证的能力。

## 4. 接口与数据约定

### 4.1 优先复用现有入口

下表为现有源码入口，后续围绕这些入口完成必要适配。

| 入口 | 简化后的用途 |
| --- | --- |
| `POST /admin-api/dim3d/resource/uploadConvert` | 模型文件上传和后台转换的统一入口，返回可用于保存的模型标识 |
| `POST /admin-api/dim3d/model/add` | 当前新增弹窗的统一保存入口，提交完整业务字段并完成目录关联 |
| `GET /admin-api/dim3d/model/page`、`GET /admin-api/dim3d/model/info/{id}` | 列表和详情读取 |
| 现有封面上传与编号读取接口 | 沿用图片上传能力 |
| 现有资源内容及成员读取接口 | 由预览适配调用，维持已有读取权限和固定内容关系 |

旧上传接口与服务器实际转换器的返回协议需要在后端适配。已有模型导入的内部步骤由后端编排，现有受管资源提交和归属校验继续复用。耗时处理的等待或状态查询封装在上传适配中。

### 4.2 首批新增接口适配记录

本节记录 2026-11-13 的异步新增实现，2026-11-17 用户要求五类目录接口按文档收口，当前目录表单和响应以第 4.5 节为准；上传及原操作查询能力继续复用。

- 上传表单包含 `file` 和 `resourceBelong`，后端返回已有导入状态中的字符串操作编号与稳定资源编号。后台计算摘要、存储原包并入队，前端适配自动查询到转换完成。
- 新增保存提交操作编号、资源编号及目录字段，复用原操作的受控发布事务。页面适配自动等到提交成功后关闭并刷新。重复保存沿用同一操作取得原回执。
- 省略上传归属参数的历史调用沿用旧回执。旧模型文件编号保存继续沿用原实体校验和目录入口。
- 浏览器关闭或身份切换后终止本地等待。新增弹窗移除手动查询按钮和会话恢复缓存，保留表单校验及普通重选文件。

### 4.3 字段规则

- 名称去除首尾空白后为 2～50 字符，描述沿用 500 字符上限并允许空描述。
- 分类使用现有启用模型字典。字段无效时返回清晰错误，用户修正表单后再次保存。
- 系统资源供所有租户查询和使用。我的资源仅创建账号可查询和使用，同一租户的其他账号也需隔离。用户、角色和租户从已有登录信息解析，前端提交的归属字段沿用当前枚举。
- 上传时固定系统或我的归属，服务端从统一登录信息记录上传账号、租户和操作人。保存目录继承原操作归属及账号，前端只提交业务字段。列表接口接续实现系统资源全租户可见、我的资源仅所属账号可见的筛选规则。
- 封面复用图片文件编号和归属校验，支持 PNG、JPEG、WebP，大小沿用 5 MiB 上限。
- 计费沿用现有免费或付费规则。页面显示元，后端按整数分保存，校验小数位和溢出。
- 受管模型沿用稳定 `resourceId`，历史 `modelFileId` 在服务端或既有适配边界兼容。目录编号继续用于目录操作。
- 保存事务共同维护目录、模型关联和封面归属，失败时回滚相关写入。重复点击保存应得到同一新增结果。

### 4.4 目录详情预览与接口核对增量

2026-11-17 按用户提供的真实接口契约补充目录详情。历史目录通过 `modelFileId` 查询真实转换记录并返回 `resourceRelativePath`，由前端既有对象存储根地址生成预览地址。受管目录通过 `resourceId` 复用资源可见性、已提交清单验证和私有签名，返回 `modelFileUrl` 及到期时间，保持文件与目录身份独立。清单错误、资源不可见和存储故障沿用明确失败，不猜测文件路径。

详情与分页沿用系统公共、个人按账号的范围。分页新增合同排序参数并使用固定列白名单，价格响应采用精确元字段 `priceYuan`，整数分写入继续保留。列表读取不逐条签发文件地址，详情按需读取清单，避免分页产生对象存储循环访问。五类接口的调整与验证统一登记在 MODEL-09，本轮沿用现有登录及 `/admin-api` 网关。

### 4.5 五类接口按参考合同收口

2026-11-17 用户进一步要求实际调整全部五类接口。新增、编辑统一要求名称、分类、归属、付费状态及字符串 `modelFileId`，成功新增、编辑、删除返回 `data=null`；分页采用根级 `code/msg/rows/total`。价格写入保持整数分，响应采用精确元字段。系统与个人均按付费状态验证正整数价格，免费归零。

`modelFileId` 对外表示模型文件资源编号。历史目录映射原转换编号，受管目录在响应投影中映射 `resourceId`，数据库继续保持受管 `resource_id` 与空历史 `model_file_id` 的约束。客户端提供的租户、所属账号和审计字段不参与归属决策。系统目录落公共租户 0，个人目录绑定当前账号与租户。类别验证在加锁前调用既有字典，目录和封面归属同事务提交。

未发布的受管上传按文件编号定位当前账号的原 CREATE 操作，复用原发布确认和执行器定向发布。成功响应以 COMMITTED 和目录落库为依据；正在被其他执行器处理时明确返回可重试状态，不能提前返回成功。无需在请求线程重复转换、复制原包或轮询等待。

普通元数据编辑使用资源行后目录行的顺序加锁。描述和封面省略时在最终目录行锁内保留当前值，显式空值才清空，避免覆盖并发更新。更换文件时目录编号保留，新受管上传的提交事务同时改绑目标目录并提交候选资源；目标目录编号由服务端校验后写入内部发布描述，公开确认请求不能注入该字段。原资源和既有发布快照继续保留，内容修订的替换入口仍可独立使用。新文件已有其他有效目录时拒绝竞争绑定，避免一个待发布操作生成两个目录。

删除受管模型通过既有 DELETE 资源操作及提交事务完成，复用资源行锁、历史发布引用保护和逻辑删除审计。历史目录只逻辑删除目录，文件保留。请求重试、并发编辑及发布确认需要回查原操作和目录当前关联，失败不得改动旧目录或封面。

补充参考文档的 `/admin-api/dim3d/resource/info/{id}`，复用目录可见范围，返回真实资源类型和相对路径。此前增加的私有文件临时签名地址及到期时间已由 MODEL-12 按第 4.8 节收敛。详情和分页均输出可用于该入口的文件编号。完整网页预览以真实地址配置和浏览器验收为依据。

### 4.6 模型目录响应收敛增量

2026-11-17 用户要求对外响应采用参考字段。详情与分页使用独立响应对象，仅输出 `id/modelName/modelDesc/category/resourceBelong/isPaid/priceYuan/coverImageId/modelFileId/status/createBy/createByName/createTime/updateBy/updateByName/updateTime`。编号与金额使用字符串，元价格保留两位小数，时间格式为 `yyyy-MM-dd HH:mm:ss`。

目录读取只查询已授权元数据。模型路径由现有文件资源详情接口提供，MODEL-12 按第 4.8 节保留相对路径；私有下载采用既有受控文件接口。受管数据库关联继续由内部资源主键维护，对外投影统一使用模型文件编号。操作人名称复用系统用户批量接口，编号去重后每批最多 200 个，分页最多两批，空结果跳过远程查询，名称缺失保留空值。

### 4.7 模型上下线补充设计

2026-11-17 MODEL-11 将模型状态入口接入统一写入服务，复用 `dim3d:model:edit` 及已有资源维护权限。已授权目录先做范围预检，再在短事务中锁定有效目录并复核归属。状态变化只更新目录状态、可信更新人及更新时间；同状态请求直接返回成功，避免重复写入审计字段。

系统目录要求平台维护权限，个人目录限定当前账号与租户，已删除目录拒绝操作。只接收 `ONLINE/OFFLINE`，成功 `data=null`。状态操作使用目录行锁，文件替换及删除仍按原资源行、目录行顺序执行；锁定后发现归属变化时返回冲突。状态修改不调用文件转换、签名或分类查询，保存及文件替换继续保留锁定目录的当前上下线状态。

### 4.8 模型文件详情相对路径收敛

2026-11-18 MODEL-12 按用户给出的参考响应收敛文件详情路径。`GET /admin-api/dim3d/resource/info/{id}` 保留现有五个业务字段，唯一的路径字段为 `resourceRelativePath`。该接口读取元信息时跳过下载签名；受管路径仍从当前已提交快照的已校验清单入口取得，历史路径按有效模型文件及归属读取。

原签名模型入口方法及资源当前修订、固定修订文件下载接口继续复用同一可信校验。当前私有桶需要既有受控文件访问能力，详情字段收敛后的相对路径与网页静态根地址能否直接拼接访问须单独验证。文件相对路径收敛与静态文件服务部署分别记录。

### 4.9 普通模型内容路径简化

2026-11-18 MODEL-13 新发布模型内容使用 `resources/{resourceScope}/{tenantId}/{resourceId}/{内容版本标识}/`。版本标识复用当前发布租约的服务端唯一尝试编号，正式目录直接从可信操作的归属及资源编号生成。一次发布的主清单、模型入口及依赖成员共同位于该版本目录。操作编号、尝试编号、提交修订和不可变快照的关联由已有数据库记录维护。

每次失败恢复及租约重领使用新的版本目录，避免旧执行器迟到写入影响新内容。源包和转换中间产物继续按其操作身份管理；既有模型正式路径、旧修订及原热更包按已存储前缀读取，读取与签名校验接受两种布局。资源指针及提交快照在原事务中共同固定新前缀，现有对象保持其原路径。

测试对象回收限定本轮新建的独占资源，核对范围、租户及资源编号后，在逻辑删除确认成功时清理完整资源前缀，覆盖失败尝试遗留及新旧布局；共享业务资源与历史发布引用沿用原生命周期规则。本轮无需数据库结构变更，源码验证与部署验收分别登记。

### 4.10 中文模型入口转换兼容

MODEL-14 在转换产物校验阶段兼容模型入口的中文等本地化文件名。入口保留所在目录，正式文件名归一为 `model.glb` 或 `model.gltf`。固定发布计划同时保存归一后的名称和原 ZIP 成员名，发布时按原成员读取并按归一后的名称写入，字节、摘要及同目录相对依赖保持原值。历史计划缺少原成员字段时使用现有成员名。

只允许符合受限字符集合的本地化入口文件名，目录段、依赖成员和引用继续使用现有路径约束。路径冲突、多个入口、远程引用及内容校验失败按原规则拒绝。模型清单、对象名称、签名和相对路径统一使用归一后的名称，目录及修订沿用原提交机制。

### 4.11 目录保存、文件访问及面板分页

MODEL-15 将管理页上传状态与目录提交回执分开。上传在原任务达到转换就绪后提供字符串文件编号，新增或编辑提交完整目录表单，由服务端在受控发布提交后返回空数据。受管原位替换携带操作编号，服务端复核原目录关联、原操作者、操作类型及预期资源修订。相同表单可用原操作重试。历史替换使用已有上传创建新文件，再由目录编辑事务改绑，旧文件引用继续可读。

管理页和编辑器以授权目录为依据查询模型文件访问方式。受管模型保留稳定资源编号，由网页播放器沿现有受控文件协议加载。历史文件使用既有对象存储根地址及服务端返回的相对路径。访问失败不使用列表中的过期路径。文件访问查询只读取目录和资源元数据，不读取清单或签名。面板以 200 条逐页查询在线目录，按编号稳定排序并去重；每次加载内共享相同文件与封面请求并限制并发。

### 4.12 保存时确定模型归属

MODEL-16 以完整目录表单的资源归属为最终意图。受管上传暂存于认证租户，兼容上传时传入的旧归属参数。最终发布在原租约内校验上传者、来源与目标权限，由同一事务提交资源范围、目录、封面和回执。发布失败时维持此前可见范围。

编辑沿用目录和文件编号。已发布文件只改归属时，新建同内容修订，继续使用原不可变对象，并保留已发布场景的固定引用。历史文件沿用原预览路径及独占校验。原封面可随目录迁移，其他目录共用的封面需更换或移除。

## 5. 控制复杂度的执行原则

1. 本批改动对应新增弹窗的上传、归属选择、上传账号记录和保存。列表归属筛选、资源读取及场景使用规则分别进入后续任务。
2. 优先修改现有页面、接口适配和服务。已有校验、转换、存储、权限及资源提交能力直接复用。
3. 业务请求通过已有登录令牌和方法权限校验，跨域来源沿用系统配置，兼容多个本地前端、局域网前端和无来源头的接口调试请求。
4. 文件采用流式处理并核对上传上限和请求时限。必要摘要在后端计算，处理结束释放文件流、临时文件和查询循环。
5. 数据变更依据当前上传或保存的真实结构缺口制定增量，先备份并保留现有数据。删除与场景引用表的差异归入对应操作的后续核对。
6. 验证复用已有有效证据，代码或配置变化后检查受影响路径。用户实际模型的网页上传、保存和回读作为本轮重点。
7. 发现额外优化机会时登记到后续项，当前新增闭环优先。范围确需变化时先更新本文，记录具体用户收益及技术依赖。

## 7. 本轮验收

1. 使用用户实际模型压缩包，从现有新增弹窗完成自动上传转换和一次保存。
2. 名称、描述、分类、归属、封面及计费字段保存正确，上传账号与当前登录账号一致。
3. 保存时使用表单选择的归属及已认证账号，成功后关闭弹窗并触发现有列表刷新。上传阶段只建立暂存范围。
4. 非法文件、无效分类、缺失贴图及无权限请求给出明确失败，表单可修正或重新上传。
5. 重复点击和请求重试保持单条目录，保存失败保持已有可用内容。
6. 多个本地或局域网前端以及 Postman 通过现有登录方式调用，部署版本、必要迁移和回退有记录。

新增闭环验收后，MODEL-06 的列表任务接续核对系统全租户共享、我的资源按账号筛选及预览。MODEL-07 接续文件替换、场景加载和保存重开，沿用项目已有运行端联调要求。
