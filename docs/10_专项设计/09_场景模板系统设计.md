# 场景模板系统设计

2026-11-06，设计草案。开发节点、前置条件和验收状态统一维护在[近期执行任务](../03_近期执行任务.md#51-场景模板系统里程碑)。

## 1. 场景模板的范围

场景模板将编辑器当前内容保存为可独立复用的四包快照。四包包括场景容器、三维、二维和依赖。用户可以选择仅二维、仅三维或全部内容，随后从模板目录找到快照，应用到正在编辑的场景，或从模板创建新的独立场景。

| 能力 | 已有基础 | 本计划交付 |
| --- | --- | --- |
| 另存模板 | 网页已有运营端弹窗、内存四包采集和范围裁剪，相关定向回归 17 项通过 | 实现真实写入、目录关联和四包回读 |
| 模板目录 | Java 已有文件型模板的目录增删查和上下线 | 支持场景快照型模板，并保持文件型模板兼容 |
| 应用到当前场景 | 网页已有模板载入和范围处理 | 用真实模板复验类型校验、撤销或失败恢复 |
| 从模板创建场景 | 已有契约草案 | 新建独立场景和修订，重建场景内编号及引用 |

首期交付面向运营端，先覆盖当前编辑器另存、目录发现、回读和测试数据清理。应用到当前场景已在 Web 本地接入模板读取、保存范围校验、跨类型二维清理和场景编号回映射，进入 TPL-05 的本地实现阶段。TPL-04 真实联验通过后，再使用真实快照补齐三维应用、失败恢复、撤销和保存重开证据，并回填 NODE-M6-04、复核 NODE-M6-08。后续实例化、完整治理和跨租户共享分别验收。

TPL-05 的撤销暂不提前标记完成。Web 已补最小异步场景快照命令事务，模板首次应用保留既有命令历史，撤销和重做先同步切换领域快照，再恢复二维仓库、相机和请求状态。真实运行端仍需验证三维表现、失败重试和保存重开。

异步命令事务至少需要满足四点。场景替换不能默认清空既有历史，模板应用要以当前草稿和目标快照组成一条历史记录，二维片段和三维宿主必须在同一提交边界完成，撤销或重做失败时要按原快照恢复并保持保存状态。实现完成前，TPL-05 只计入类型校验、范围处理和失败回放，不计入撤销验收。

## 2. 数据归属和事务

```mermaid
flowchart LR
    A["编辑器当前内存四包"] --> B["按范围裁剪并提交"]
    B --> C["Java 核对权限、结构和引用"]
    C --> D["同一事务写入"]
    D --> E["独立模板场景与首版修订"]
    D --> F["模板目录关联"]
    F --> E
    E --> G["回读、应用或创建新场景"]
```

- **模板目录**保存名称、类型、分类、封面、状态和快照场景编号。目录编号与场景编号分别返回，长编号对外统一使用字符串。旧文件型记录继续使用文件编号。
- **模板场景**复用现有场景身份和四包修订。模板另存生成新场景及首版修订。模板快照有独立身份，普通编辑场景的租约、保存书签和线上发布身份仅保留在源场景。普通场景列表只展示实例场景，普通编辑写入只作用于实例场景。
- **资源引用**继续保存既有稳定编号，由资源服务按调用身份鉴权和解析。封面文件、模板文件、快照场景及模型资源各有独立标识。首期以现有平台测试身份和租户数据范围为边界，跨租户可见性留在后续专项。
- **失败恢复**将场景主记录、首版修订和目录关联放在同一事务，任何一步失败都回滚。提交中禁止重复点击。本地候选请求携带请求编号（`requestId`），回执不确定时先查询目录确认结果。自动重试规则在跨端合同评审中确认。

## 3. 首期接口与范围

| 能力 | 接口或入口 | 合同要点 |
| --- | --- | --- |
| 另存快照 | `POST /admin-api/dim3d/scene/saveAsTemplateFromSnapshot` | 候选请求增加来源场景编号、来源修订和本次请求编号。沿用编辑器名称、描述及模板类型字典编码。四包来自当前编辑器内存。租户取自认证，回执分别返回目录编号和模板场景编号，以及场景种类 `TEMPLATE` 和保存范围。 |
| 目录发现 | 资源管理页传 `includeSnapshots=true`，编辑器使用独立快照分页 | 合并分页按当前认证租户读取旧文件型记录和快照摘要。独立详情返回模板首版四包。普通场景列表和编辑写入过滤模板身份。 |
| 回读与清理 | 现有场景详情和模板管理入口 | 回读模板的独立四包。清理同时处理目录和模板场景的可见性，保留审计及共享资源引用。 |
| 应用和实例化 | 现有网页应用入口，实例化使用 `POST /admin-api/dim3d/scene/fromTemplate` | 应用修改当前编辑草稿。实例化另建场景和修订，并维护内部引用映射。 |

| 保存范围 | 保留内容 | 适用规则 |
| --- | --- | --- |
| 仅二维 `twoD` | 二维组件、舞台和仍被引用的依赖。三维槽位保存标准空结构。 | 应用或实例化时可跨场景类型。 |
| 仅三维 `threeD` | 节点树、三维设置和仍被引用的依赖。二维槽位保存标准空结构。 | 目标场景类型与来源一致。 |
| 全部 `all` | 二维、三维和完整可复用依赖，保留旧档未知扩展。 | 目标场景类型与来源一致。 |

网页先裁剪工作副本，Java 独立校验四包结构、节点父子关系、选中范围和已知依赖引用，拒绝裁剪范围之外的数据。选中范围内的未知扩展按四包兼容约定保留。来源场景专属的发布文件和临时签名地址在保存前按合同处理。

实例化请求使用模板场景编号 `templateSceneId`、目标场景名称 `name`、请求编号 `requestId`，描述和分类可选。Java 只读取当前认证租户下处于 `ONLINE` 的快照模板，创建新的实例场景和首版修订。三维对象的 `instanceId`、父级引用、图层引用及依赖归属按同一映射表重建，分块中的来源场景编号改为新实例编号，资源编号继续沿用原稳定资源身份。相同请求编号和内容重复提交时返回首次创建的实例，内容不一致时拒绝。

实例引用映射同时覆盖分块 `objectIds`、二维组件和其私有部件快照、二维结构树的分组/成员、图层 `layerKey`、依赖 `ownerKey`、行为与场景动作的目标编号。普通 `id` 只在明确的场景身份位置重建，资源及未知扩展中的普通 `id` 保留，避免同值资源编号被误改。2026-11-07 已补充这些字段的定向回归，真实模板的业务入口应用和保存重开继续验收。

## 4. 接口评审与联验门槛

1. **先冻结合同**。核对网页模板类型字典编码与旧后端枚举的映射、分类合法性、缺省资源归属、封面编号以及平台维护权限。现网页省略资源归属字段，后端缺省行为应依据认证身份明确推导。按实际依赖核对 M3-01 中首期需要的目录、封面和权限子集。
2. **先验证事务再部署**。本地数据库测试覆盖三种范围、越权、非法范围及写入中途失败。增量迁移单独演练，记录旧记录兼容、回退条件和数据保留。148 使用隔离候选端口和专用测试库，留存构建摘要和实际测试记录。
3. **验收走真实编辑器入口**。创建带二维组件和三维父子节点的专用样本，在源场景存在未保存修改时分别另存三次。验证新模板可发现、回读内容符合范围、未保存修改进入选中域、源场景修订和四包摘要一致。另验错误范围、账号权限、写入失败及退出清理。
4. **后续验收各自收口**。应用模板须覆盖跨类型规则、失败时保留原草稿和源模板保持原样。实例化须覆盖新编号、父子及行为引用重定向和保存重开。上下线、版本演进和跨租户共享进入治理节点，单独审定权限及资源可见性。

### TPL-07-03 版本与回退合同

模板版本使用模板目录身份和单调递增的 `versionNo` 组合标识。模板场景修订仍是版本正文来源，但不能把模板场景的 `current_revision` 直接当作线上消费版本。

- `publishedVersionNo` 表示当前允许新消费者读取的不可变版本。
- `previousPublishedVersionNo` 只在发布切换成功后更新，用于一次明确的回退操作。
- 发布先校验版本正文和目录状态，再在同一事务内切换发布指针并写入治理审计。任一校验或写入失败时，原发布指针保持不变。
- 下线只改变目录可发现性和新消费者准入，不删除已创建实例引用的版本正文。删除继续使用软删除，必须先下线并记录操作者和原因。
- 旧文件型 `wx_3d_template` 没有版本指针时按兼容版本 `1` 只读投影，不能参与快照模板回退。

TPL-07-03 的失败门禁覆盖发布到不存在版本、回退到已删除版本、跨租户版本引用、发布指针切换中途失败和下线后新实例创建。完成前不执行生产发布和跨租户共享启用。

首期候选实现只允许平台租户的超级管理员另存，快照归属当前认证租户。分类由系统服务校验为模板类型对应的启用字典项。单域请求校验被排除包为空，并拒绝另一域的依赖归属。文件服务尚无可复用的封面编号归属校验，148 候选仅接收无封面快照。网页每次主动提交创建新的请求编号，回执不确定时先查目录。

TPL-04 专用库只在执行真实联验前创建，平时不保留测试库、候选容器或候选部署文件。Java、Web 和迁移校验优先在本地完成。
