# 场景不可变发布记录合同

日期：2026-11-09。对应里程碑：DATA-09-01。本文只冻结发布记录和验收边界，不执行生产发布、数据库迁移或跨租户数据写入。

## 1. 发布对象

发布记录固定绑定以下身份，发布后不得改写：

- `publicationId`：对外返回的字符串编号。
- `tenantId`、`sceneId`、`revisionNo`：发布所属租户、场景和完整四包修订。
- `sourceHash`、`indexVersion`：发布时的四包摘要和派生索引版本。
- `dependencySnapshot`：发布时依赖资源的稳定编号、修订和清单摘要。
- `createdBy`、`createdTime`：首次发布操作者和服务端时间。

发布快照必须引用同一修订的场景、三维、二维和依赖四包。草稿后续保存不得改变已发布记录读取到的正文、依赖或索引版本。

## 2. 状态和操作

| 状态 | 允许操作 | 约束 |
| --- | --- | --- |
| `PUBLISHED` | 读取、生成访问票据、撤销 | 只能读取绑定的不可变快照 |
| `REVOKED` | 查询历史、审计 | 新票据和新授权必须拒绝 |
| `FAILED` | 查询失败原因、重新发起新发布 | 不得产生可消费的半成品记录 |

发布提交采用短事务。先锁定场景和目标修订，复核四包摘要、依赖清单和租户归属，再写入发布记录和不可变指针。任一校验、依赖保留或指针写入失败，原场景发布状态保持不变。

## 3. 撤销和回退边界

- 撤销只改变发布记录状态和新访问准入，不删除历史四包、依赖快照或已创建实例。
- 回退通过创建一条新的 `publicationId` 指向已验证的历史修订完成，禁止直接修改原发布记录的 `revisionNo` 或 `sourceHash`。
- 版本切换必须保留前一条发布记录和审计原因。程序回退只恢复服务和配置，不依赖删除数据库历史记录。
- 依赖资源已被其他发布或实例引用时，发布撤销不回收资源。资源回收必须由独立引用审计和保留策略决定。

## 4. 验收门禁

1. 同一场景只能有一个当前可消费发布指针，但历史发布记录可以保留多条。
2. 草稿保存、模板共享撤销和发布撤销互不改写既有不可变发布正文。
3. 同一请求编号重试返回首次发布回执，正文或依赖摘要变化时拒绝重放。
4. 未登录、跨租户、未发布修订、依赖缺失、摘要不一致和中途写入失败均拒绝消费，且不产生可消费脏记录。
5. 真实生产发布、票据签发、物理发布表迁移和依赖回收不属于 DATA-09-01，进入后续独立节点。

## 5. 当前实现边界

现有模板版本表和治理审计已具备版本发布/回退基础，但场景发布记录、票据和依赖快照尚未接入业务服务。本文冻结合同后，下一步先补失败用例和本地事务模型，再另行评审迁移和真实环境联验。
