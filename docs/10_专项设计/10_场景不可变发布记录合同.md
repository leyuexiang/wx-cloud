# 场景不可变发布记录合同

日期：2026-11-09。对应里程碑：DATA-09-01。本文只冻结发布记录和验收边界，不执行生产发布、数据库迁移或跨租户数据写入。

## 1. 发布对象

发布记录固定绑定以下身份，发布后不得改写：

- `publicationId`：对外返回的字符串编号。
- `tenantId`、`sceneId`、`revisionNo`：发布所属租户、场景和完整四包修订。
- `sourceHash`、`indexVersion`：发布时的四包摘要和派生索引版本。
- `dependencySnapshot`：发布时依赖资源的稳定编号、修订和清单摘要。
- `createdBy`、`createdTime`：首次发布操作者和服务端时间。

发布快照必须引用同一修订的场景、三维、二维和依赖四包。草稿后续保存不得改变已发布记录读取到的正文、依赖或索引版本。

## 2. 状态和操作

| 状态 | 允许操作 | 约束 |
| --- | --- | --- |
| `PUBLISHED` | 读取、生成访问票据、撤销 | 只能读取绑定的不可变快照 |
| `REVOKED` | 查询历史、审计 | 新票据和新授权必须拒绝 |
| `FAILED` | 查询失败原因、重新发起新发布 | 不得产生可消费的半成品记录 |

发布提交采用短事务。先锁定场景和目标修订，复核四包摘要、依赖清单和租户归属，再写入发布记录和不可变指针。任一校验、依赖保留或指针写入失败，原场景发布状态保持不变。

## 3. 撤销和回退边界

- 撤销只改变发布记录状态和新访问准入，不删除历史四包、依赖快照或已创建实例。
- 回退通过创建一条新的 `publicationId` 指向已验证的历史修订完成，禁止直接修改原发布记录的 `revisionNo` 或 `sourceHash`。
- 版本切换必须保留前一条发布记录和审计原因。程序回退只恢复服务和配置，不依赖删除数据库历史记录。
- 依赖资源已被其他发布或实例引用时，发布撤销不回收资源。资源回收必须由独立引用审计和保留策略决定。

## 4. 验收门禁

1. 同一场景只能有一个当前可消费发布指针，但历史发布记录可以保留多条。
2. 草稿保存、模板共享撤销和发布撤销互不改写既有不可变发布正文。
3. 同一请求编号重试返回首次发布回执，正文或依赖摘要变化时拒绝重放。
4. 未登录、跨租户、未发布修订、依赖缺失、摘要不一致和中途写入失败均拒绝消费，且不产生可消费脏记录。
5. 真实生产发布、票据签发、物理发布表迁移和依赖回收不属于 DATA-09-01，进入后续独立节点。

## 5. 本地接口边界

服务已提供以下受控管理路由，2026-11-10 已在 148 data08 隔离网关完成管理链路联验：

- `POST /admin-api/dim3d/scene/publication/publish` 固定场景修订并返回 `publicationId`。
- `GET /admin-api/dim3d/scene/publication/current/{sceneId}` 读取当前发布摘要。
- `GET /admin-api/dim3d/scene/publication/{publicationId}` 读取当前租户可见的固定摘要。
- `GET /admin-api/dim3d/scene/publication/{publicationId}/snapshot` 读取发布时固定的依赖快照和索引版本。
- `POST /admin-api/dim3d/scene/publication/{publicationId}/revoke` 撤销新消费准入。
- `POST /admin-api/dim3d/scene/publication/{publicationId}/rollback` 以新编号恢复历史修订。
- `POST /admin-api/dim3d/scene/publication/{publicationId}/ticket` 签发短时只读票据。
- `DELETE /admin-api/dim3d/scene/publication/ticket/{ticketId}` 撤销票据。

发布、撤销和回退需要租户管理员或平台管理员角色。查询接口仍按认证租户过滤，不能通过路径编号跨租户读取。

## 6. 当前实现边界

场景发布记录、查询、撤销、回退、票据管理和匿名固定四包读取已在 148 data08 隔离网关联验。正式依赖资源保留、按票据签发资源文件以及 Web/Unity 消费尚未完成；匿名四包入口的通过不代表资源依赖闭包、完整预览界面或生产迁移已经验收。证据见[真实联验](../evidence/data09-20261110/README.md)。

## 7. 访问票据合同

- 票据只授予 `READ` 范围，默认 300 秒，允许范围为 60～3600 秒。
- 数据库只保存票据的 SHA-256 摘要，不保存明文。明文只在签发响应中返回一次，不写入日志或发布记录。
- 票据验证同时检查 READ 范围、票据状态、过期时间和发布状态。发布撤销后，已有票据也必须拒绝。
- 票据撤销保留历史行和操作者信息，不删除发布记录，不影响不可变快照本身。
- 依赖快照读取返回发布时固定的依赖 JSON 和索引版本，不回查当前草稿或资源当前指针。

## 8. 匿名消费子合同（DATA-09-25）

- `POST /admin-api/dim3d/scene/publication/preview`，只接收请求头 `X-Scene-Ticket`，不从地址或正文接收票据，也不接受租户、场景或发布编号覆盖绑定身份。
- 此精确路由免后台登录及租户头，既有管理路由继续要求登录。票据必须为 `READ`、`ACTIVE`、未过期且所属发布为 `PUBLISHED`；无效票据统一返回业务码 401。
- 单次数据库查询按票据摘要关联发布和其绑定的修订，返回 `publicationId/sceneId/revisionNo/sourceHash/indexVersion/schemaVersion` 和原文四包 `sceneJson/threeDJson/twoDJson/dependenciesJson`。不返回租户、操作者、请求号、票据摘要或管理能力。
- 读取不追随当前发布或草稿指针。修订缺失、四包摘要与发布摘要不同、依赖原文与固定快照不同，返回业务码 409；不得回退到最新修订或未校验内容。响应禁止缓存（`Cache-Control: no-store`）。撤销提交后新消费请求即拒绝，已开始返回的响应无法追溯撤回。
- 本子项仅验证正文读取准入与完整性，不意味着依赖资源存在、可下载、已保留或完整闭包已通过；这些仍进入后续独立验收。既有发布未被消费验证的历史摘要也不能据此认定正确。

## 9. 发布资源引用冻结（DATA-09-26 发布侧子项）

- `dependenciesJson.resources` 必须是数组，最多 256 条，`resourceKey` 为非空字符串（最多 160 字符）且不得重复。本子项支持 `kind=unity-model` 的受管资源；其他类型在对应发布解析器落地前返回 409，不影响四包草稿保存。
- `assetId` 为规范的正整数字符串；可选 `revision` 也是正整数字符串。未提供版本时，发布事务按编号顺序锁定可见资源，并固定其当前已提交版本；提供版本时只使用指定版本。可选 `contentHash/manifestSha256` 必须与服务端固定快照一致，禁止默默改用最新版本。
- 只允许租户自身 `TENANT_SHARED` 或所有者为 0 的 `GLOBAL_SYSTEM` 资源；资源须未删除且为 READY 模型，操作须 COMMITTED，操作与资源范围/所有者一致，快照的编号、版本、摘要、格式、平台及存储路径须合法。
- 新增 `wx_3d_scene_publication_resource`，保存发布、场景内资源键、受管资源及固定版本、摘要、提交操作和内部资源快照。发布记录采用索引版本 2。原文依赖包与四包摘要不改写；引用、发布指针、审计在同一事务提交，失败全部回滚。相同请求重放不重新解析资源当前指针，不重复写引用。
- 撤销与回退不删除引用；回退复用原发布已冻结的资源版本和摘要，重新校验归属及提交快照后创建新发布与引用，不能因原文未提供版本而追随资源当前指针。旧索引版本 1 的非空资源发布没有冻结引用，无法证明原版本时明确拒绝回退；不自动按当前资源补齐历史。
- 本轮只校验已提交的数据库快照元数据并建立可追溯引用，不在数据库事务内读对象存储。物理文件、清单字节及成员闭包、按票据文件签发、引用回收保护仍为后续门禁，不能把引用行当作这些能力已完成的证据。
