# 图片资源新增上传功能完善计划

日期为 2026-11-10。本文覆盖图片管理从新增到保存、展示及重新打开的完整业务链路。执行状态和验证结果统一维护在 [03 近期执行任务](../03_近期执行任务.md#img-00图片资源新增上传功能完善计划2026-11-10)。

## 1. 目标与范围

用户应能在现有图片管理页面填写名称和描述、选择分类及归属、上传图片并保存。保存后列表、分类数量、预览和编辑回显一致，刷新页面后仍可正常使用。

文件内容先使用 `192.168.10.148` 已部署的 MinIO 对象存储。图片业务通过现有文件与资源服务接入，后续统一存储调整时保留业务编号和调用契约。

| 本次工作 | 交付要求 |
| --- | --- |
| 新增弹窗 | 沿用现有布局、字段、上传组件与交互，完善校验、上传状态及重复提交保护 |
| 图片分类 | 使用真实字典及分类编码，覆盖设备、建筑、药材、仓储及已有有效分类 |
| 图片上传 | 返回稳定文件编号及可访问地址，明确文件类型、大小、归属和失败行为 |
| 资源新增 | 校验文件可用性和归属，保存图片目录及文件关联，返回真实新增结果 |
| 列表与数量 | 保存后刷新当前列表和分类数量，筛选、分页、状态及资源归属口径一致 |
| 预览与回显 | 按文件编号读取地址，刷新、重新打开与地址过期后均可恢复 |
| 权限及一致性 | 服务端校验真实身份，处理越权、上传失败、保存失败、取消和重试 |
| 部署验收 | 备份、隔离验证、真实页面验证及适用回退形成完整证据 |

既有模型、模板封面与图片选择器同用文件接口，将其列为兼容回归对象。本次实施以图片新增闭环为主，模型转换、模板新增和场景发布沿用各自专项。

## 3. 完整业务流程

1. 打开弹窗，读取启用的图片分类和当前身份允许的归属选项。
2. 填写名称、描述和分类，选择系统资源或我的资源。
3. 选择或拖入图片，前端初检后发起上传，上传期间禁用保存和重复上传。
4. 后端验证身份及文件，写入 MinIO，登记稳定文件身份，返回文件编号和即时预览地址。
5. 点击保存，后端再次验证分类、归属、操作权限和文件可用性，再提交图片目录及关联。
6. 保存成功后关闭弹窗，刷新列表、当前筛选与分类数量，展示真实图片。
7. 刷新页面或重新打开编辑时，按 `iconFileId` 解析文件地址，恢复图片及全部表单字段。
8. 图片选择器继续通过同一文件编号读取新资源，验证其显示和引用能力。

文件上传成功、图片目录保存成功、页面展示成功分别判定。保存失败时保留表单及有效文件编号，允许重试。

## 4. 接口、数据与权限方案

### 4.1 接口契约

| 接口组 | 计划要求 |
| --- | --- |
| 图片分类读取 | 复用字典接口，返回真实编号、名称、业务编码和顺序，停用或非法分类在保存时拒绝 |
| 文件上传 | 保留前端现用 `/api/resource/oss/upload` 协议，表单字段为 `file`，响应固定 `ossId/url/originalName/fileSuffix` |
| 文件编号读取 | 保留 `/api/resource/oss/listByIds/{ids}` 协议，首期 `{ids}` 为单个本地文件编号，响应 `data` 为 0 或 1 项，不猜测批量分隔符 |
| 图片新增 | 复用 `/api/operation/dim3d/icon/add` 与 `/api/tenant/web/dim3d/icon/add`，字段沿用 `iconName/iconDesc/category/resourceBelong/iconFileId`，编号以字符串返回 |
| 图片详情及分页 | 对齐当前前端详情对象与 `rows/total`，支持既有筛选字段并限制分页大小 |
| 图片预览 | 每次按可信文件身份生成最长 10 分钟的临时读取地址，过期后重新获取 |

2026-11-11 用户确认当前前端为 `wx-vue-unity`，运行配置采用 admin 模式，普通文件实际请求 `/admin-api/resource/oss/...`，图片目录使用 `/admin-api/dim3d/icon/...`。网关同时适配该模式与既有 `/api` 入口，文件请求转发至 `/admin-api/infra/file/resource/oss/...`，两种入口均保留可信身份并移除外部伪造身份头。编译、真实存储及迁移验证的实际结果维护在 03。

`oss` 仅为既有消费者接口命名，底层复用基础文件服务及 MinIO；既有 `/admin-api/infra/file/upload` 字符串响应与 RPC 合同不变，新适配只为新路径返回稳定本地编号。

### 4.2 数据与文件身份

- 图片目录继续使用 `wx_3d_icon`，通过 `iconFileId` 关联普通文件。目录编号、普通文件编号和受控模型 `resourceId` 各自独立，对外均按字符串传输。
- 优先复用 `wx_infra_file`、`wx_infra_file_config` 及现有文件客户端。新适配层应取得上传时写入记录的主键，避免按文件名或地址反查身份。
- 文件归属在 IMG-01 合同中冻结为 `tenant_id/uploader_id/visibility_scope` 增量字段；历史行保持待核验，不推断归属；由于文件表被现有租户拦截忽略，读取必须显式带范围谓词。
- 上传中的文件仅对上传者和已授权业务可用。保存系统资源或我的资源时，服务端结合可信身份和目录归属绑定文件权限，页面归属值不能直接赋予全局读写权限。
- 现有目录和文件记录先清点引用再处理，无法确定归属的历史文件进入待核验清单。两库本轮空文件表也须在实施前再次确认。
- 永久业务数据保存稳定编号、存储配置和对象键，签名地址只用于临时访问。系统资源在其他租户的读取仍须经过授权检查。

### 4.3 校验与一致性

| 环节 | 必须处理的规则 |
| --- | --- |
| 表单 | 名称去空白后校验，名称和描述长度前后端一致，分类必须启用，文件编号必填 |
| 文件 | 支持现有页面声明的 WebP、SVG、PNG、JPG、JPEG，单文件上限沿用现有 5 × 1024 × 1024 字节，拒绝空文件 |
| 内容 | 校验扩展名与真实媒体类型，位图校验可解码及合理尺寸，矢量图（SVG）校验活动内容和外部引用风险 |
| 授权 | 令牌、应用、租户和操作权限一致，服务端校验系统资源维护权、个人归属和文件读取权 |
| 保存 | 文件真实存在且上传完成，当前用户有绑定权，禁止通过伪造 `iconFileId` 引用他人文件 |
| 重试 | 上传和新增的重复请求行为写入合同，目录提交与新增幂等回执保持一致，响应丢失后可取回原结果 |
| 替换兼容 | 编辑时未换图继续使用原文件，替换上传或保存失败保留原关联及预览 |

新增长度建议按当前页面的名称 1～50、描述最多 200 个字符对齐。实施前检查现有消费者及历史数据，旧记录读取保持完整，避免无关数据截断。

文件上传与目录保存跨越对象存储和数据库，采用短事务与失败补偿。对象键由服务端生成并保持每次上传独立，避免同名覆盖。存储写入失败时拒绝登记可消费记录，元数据提交失败时仅清理本次确认写入的对象。目录保存失败可重用已上传文件重试。

弹窗取消、浏览器关闭或重复上传可能留下未绑定文件。记录其归属和创建时间，先核对有效目录及场景引用，再按保留期回收。关闭弹窗只中止客户端请求，服务端仍可能完成上传，因此回收流程需覆盖迟到成功结果。

## 5. MinIO 接入与性能

- 复用 148 上现有 MinIO 实例及现有简单存储服务兼容协议（S3）客户端。核对模型桶、文件前缀及应用授权后，为图片选择独立受控前缀或专用私有桶，并登记具体选择和依据。
- 图片存储配置显式绑定到文件适配，优先复用可用配置。新增配置前备份，核查是否影响全局默认文件配置及其他消费者。
- 区分服务端存储访问地址与浏览器下载地址，验证地址可达、签名主机一致、证书与跨域响应。以真实图片请求验证读取能力。
- 凭据沿用部署端受控配置，禁止进入前端、代码、接口样例及验收日志。后续统一存储通过文件编号映射处理。
- 服务端限制文件大小、并发、超时和资源占用，优先流式上传及有界缓冲，正确关闭输入流和存储响应。
- 列表按页查询文件元数据并去重解析地址，避免逐行重复查询。分类数量复用真实统计，核对筛选口径后按实际需要聚合查询。
- 弹窗及列表取消过期请求，防止迟到响应覆盖新表单或新筛选。短时缓存签名地址时同时按身份和文件编号隔离，并处理到期失效。

6. 验收后在 03 登记实际产物、命令、结果、部署状态及遗留事项，保存脱敏证据。移除测试临时文件，审计备份按既定保留规则保存。

本计划的交付出口为用户从现有页面完成图片新增，并能在列表、预览和重新打开后持续使用。文件接口完成、MinIO 连通、目录写入或页面出现成功提示，均仅作为对应环节的验证证据。
