# DATA-08 正文共享层迁移说明

更新于 2026-11-08。已在 148 授权隔离库 `wx_editor_data08` 完成结构迁移、历史回填及三端联验，并完成业务库 `wx_editor` 的结构迁移、历史回填和租户 1、2 灰度。业务服务当前使用候选包和 `dual-write-tenants="1,2"`。

本目录只描述兼容期的最小结构变更：新增 `wx_3d_scene_content` 共享正文表，并给现有 `wx_3d_scene_revision` 增加可空引用列。脚本不回填数据、不删除旧四包列、不修改场景当前修订指针，也不改变请求幂等唯一键。

执行前必须完成：

1. 导出 `wx_3d_scene`、`wx_3d_scene_revision`、`wx_3d_scene_template` 的结构和数据备份。
2. 确认目标数据库表名为 `wx_3d_scene*`，并核对新增列不存在；不能把历史 `wx_dim3d_*` 名称直接套用到当前库。
3. 在事务和停写窗口策略评审后，先只执行结构脚本，再运行逐行摘要回填和双读比对。
4. 任何校验失败都关闭共享读取开关，保留旧四包列读取。结构回退顺序为 `002-revision-columns.down.sql`、`001-content-table.down.sql`。`rollback-data08-schema.py` 要求共享正文表为空且引用列无数据，已有业务引用时采用应用开关回退。

回填入口为 `deploy/test148/migrate-data08-db.py`。默认试运行，传入 `--apply --confirm DATA08-APPLY` 才写入。SQL 从标准输入传入 MySQL，支持超过进程参数上限的大四包。

## 双写关闭后的恢复步骤

1. 确认隔离服务的数据库、端口和配置，备份场景、修订及共享正文表。
2. 停止该库的所有应用写入者。回填工具按现有最大正文编号规划新编号，规划及提交期间必须保持停写。
3. 执行回填，已有相同租户、结构版本和摘要的正文直接复用，为关闭期间新增的修订补齐引用。
4. 运行 `verify-data08-roundtrip.py`，确认四包、租户、版本、摘要、字节数和引用校验通过。再次运行回填试运行，新增正文和待补引用应均为 0。
5. 核对当前修订指针、修订号、请求身份均与停写前一致，再开启双写并启动服务。通过真实详情、固定修订分片和一次新保存确认恢复。

双写兼容期仍保留修订行内四包，增加共享正文层会增加实际存储占用。预计去重字节仅表达后续移除冗余正文的潜在收益。没有完成模板首版、发布引用、活动锁、幂等回执和分片书签引用审计前，继续保留共享正文及修订记录。
