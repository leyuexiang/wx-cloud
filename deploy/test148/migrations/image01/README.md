# 图片文件归属增量迁移

迁移前基线为 2026-11-11 核实的 `wx_editor`、`wx_editor_data08` 文件表，当时两库均缺少下列三个归属列。两库现已按用户授权完成三个字段及两个索引的增量迁移，并经独立连接复核；两表记录数均保持为 0，原结构和数据保留，见[实际迁移证据](../../../../docs/evidence/image01-20261111/database-migration.json)。下述应用前要求供后续其他环境使用，不代表本次两库尚未执行。已在真实 MySQL 8 独立验证库中克隆现有表并验证增量、查询权限和回退，验证库已清理。业务库应用前重新核对结构及引用、备份相关表，实际执行和部署状态维护在 [近期任务](../../../../docs/03_近期执行任务.md)。

## 1. 预期新字段

对已有 `wx_infra_file` 增加可空、无默认值的 `tenant_id`、`uploader_id`、`visibility_scope`。既有文件保持未归属，现场后续若已存在这些列，应检查其定义并跳过已执行的迁移，定义不一致则先核对差异。

| 字段 | 类型 | 新写入要求 | 说明 |
| --- | --- | --- | --- |
| `tenant_id` | `bigint NULL` 候选迁移列（若现表已含等效列则不得重复新增） | 新写入必填真实正租户 ID | 来源为登录身份，不取请求体或表单；执行前核对现场所有旧值与列默认值 |
| `uploader_id` | `bigint NULL` | 必填真实用户 ID | 来源为登录身份 |
| `visibility_scope` | `varchar(20) NULL` | `PRIVATE_UPLOAD/TENANT/GLOBAL` | 上传成功初始为 `PRIVATE_UPLOAD` |

迁移新增的三个候选列在旧记录上全部保持 `NULL`，语义为 `LEGACY_UNCLASSIFIED`；不回填租户 `0`，不按图标文件编号、文件名、桶键或 URL 猜归属。若现场发现同名既有归属列，正式脚本需基于备份与实际数据差异重新设计，绝不能运行此通用候选。没有主键外键写入和索引性依赖之前不执行回退删列。

推荐索引：

- `idx_infra_file_scope_owner (visibility_scope, tenant_id, uploader_id, id)`：按上传者私有范围/当前租户/全局可见性查询。
- `idx_infra_file_config_path (config_id, path)` 用于历史下载入口核验新图片归属，避免扫描文件表。
- 是否为 `tenant_id` 单列加索引须依据生产真实执行计划和 `SHOW INDEX`，不重复创建语义重叠索引。

部署前必须确认真实列名、字符集/排序规则、表引擎、现有索引及数据库大版本。候选字段类型按本机 MySQL 长整型预期；具体列定义、字符集/注释和现场实际类型未核对，不得直接执行草案覆盖现场结构。

## 2. 显式访问谓词

`wx_infra_file` 表仍在 infra 多租户忽略列表。所有新适配 mapper 必须显式地在 SQL 中带范围谓词，不能假设租户拦截器代加条件。当前实现首片只放行 `PRIVATE_UPLOAD` 上传者本人；TENANT/GLOBAL 是后续目录绑定阶段状态，不得由客户端请求设置。目标文件仅在以下一条成立时可由请求读取/绑定：

1. `visibility_scope='PRIVATE_UPLOAD' AND tenant_id=:actorTenant AND uploader_id=:actorUser`；
2. `visibility_scope='TENANT' AND tenant_id=:actorTenant`；
3. `visibility_scope='GLOBAL' AND tenant_id=0` 且资源用途允许该读者访问。

`LEGACY/NULL` 永不自动可见。GLOBAL 的写权限另经可信平台租户与系统角色检查，租户管理员与客户端传入 `SYSTEM` 不构成平台权限。查询按单编号时不可见/不存在一致投影空数组，避免文件编号枚举。

## 3. 事务和对象存储边界

1. 上传前验证身份、图片格式/大小、master FileClient 可用及其实际配置 ID；对象键由服务端随机生成。
2. 对象上传成功后，先验证 GET 签名可用，再用 `TransactionTemplate` 插入 FileDO 与归属字段。提交边界的异常返回后只删除本次唯一对象；清理失败附加原异常，目前没有独立清理日志/告警，须在运维验收补齐。
3. 按编号读取先完成文件归属 SQL，再签发该存储客户端的 GET 读取签名；`FileClient.getPresignedObjectUrl` 现有实现是 PUT 签名，不能复用。新 `FileClient.getPresignedDownloadUrl` 默认失败关闭，仅 S3 客户端已实现 GET，其他存储端不能自称具备读取签名。
4. 图标新增后续事务需要 `SELECT ... FOR UPDATE` 或等效行锁校验上传身份/范围，并在写图标和将 visibility_scope 由 PRIVATE_UPLOAD 改为 TENANT/GLOBAL 的同一 DB 事务提交。若图标写失败，文件保留为用户私有待重试，不自动删对象。

## 4. 必须在应用前检查

- 目标库、服务实际所连库及租户用途是否由用户/运维明确，不能从历史名称猜生产/测试。
- 精确备份文件表和关联图标记录，核对备份可读；生成列/唯一约束/历史文件数和 `icon_file_id` 引用均不得被初始化脚本覆盖。
- 比较两个目标库的真实 DDL；重复执行应识别“列和索引已存在且定义完全一致”为 no-op，不兼容则失败停止，不能吞掉 SQL 异常。
- 在独立空库执行 up、回查、down；回退只移除本次新增且无业务依赖的索引和字段，不删文件行或物理对象。
- 业务文件已经写入归属字段后，程序回退优先保留新增列和数据。`down.sql` 用于无业务依赖的隔离回退，执行前确认本批归属列和索引可以移除。

## 5. 部署顺序与配置

1. 核对网关指向的基础设施及三维服务，确认两者连接同一目标数据库，备份现有程序、外部配置、文件表和图片目录。
2. `wx_editor`、`wx_editor_data08` 现已完成结构增量及 MinIO 主配置，文件配置编号均为 `1`，存储类型 `20`。本批按用户明确授权通过数据库维护同一事务写入，采用现有 S3 配置类格式并独立连接复核，见[配置证据](../../../../docs/evidence/image01-20261111/minio-configuration.json)。后续环境优先通过既有文件配置服务维护，并核对主配置消费者。
3. 真实 SDK 联通验证使用私有桶 `9tyf`。现场模型服务配置当前使用 MinIO 桶 `wx-art-test148`，服务内地址为 `http://127.0.0.1:9000`。图片文件配置应复用该模型桶并由对象键 `images/` 隔离，S3 端点使用浏览器可达的 `http://192.168.10.148:9000`，使 GET 签名地址可由浏览器访问。`domain` 留空时由客户端按端点和桶名生成下载域。真实访问密钥来自服务器环境文件 `/opt/wx/editor-test148/.env` 中的 `WX_MINIO_ACCESS_KEY`、`WX_MINIO_SECRET_KEY`，不得写入仓库或验收证据。`9001` 为管理控制台入口。
4. 合入本次图片上传、编号读取及必要的平台别名路由，保留现场已有认证、场景、发布预览和端口配置。同步更新网关、基础设施和三维候选包，避免用源码生成器默认端口覆盖现场配置。
5. 在当前 `wx-vue-unity` 页面使用真实账号验证分类、上传、保存、列表数量、预览、编辑和刷新重开，并检查系统资源与我的资源权限。完成后登记程序摘要、配置、迁移和证据。
