# 转换器缺图修复

属于 MODEL-03。现场版本的预处理跳过缺失贴图，实际工具继续转换，导致错误成功。本目录通过已安装镜像构建派生版本，不覆盖现场运行容器。

## 验证和部署边界

1. 记录现场容器镜像编号、端口、挂载及非秘密运行参数，基础镜像不从远端更新。
2. 提交推送后服务器拉取固定提交。先将 `verify-materials.cjs` 只读挂载到基础镜像，以 `node` 执行，确认缺图行为检查失败。
3. 使用本目录为构建上下文，显式传入 `BASE_IMAGE`。构建时核对两份现场源码摘要，修补唯一位置，再运行行为检查；任何不匹配均中止。
4. 派生镜像恢复原 `node` 用户和原启动入口。仅在未占用回环端口启动独立转换候选，后台候选指向该接口，不改正式功能开关。
5. 缺图原包必须真实得到 `UNSUPPORTED_INPUT` 且不可重试；再回归 OBJ、FBX、3DS 的 GLB/glTF 六组。所有测试样本、会话和本次对象按验收脚本限定范围清理。

标准贴图选项、带空格文件名、引号和 Windows 导出路径有行为检查。既有路径归一化、同名贴图冲突检查及工具链保持复用。补丁不声称检查 FBX 内嵌依赖或未经过材质预处理的分支，这些按主计划实测。

回退时将独立后台候选恢复原转换地址；原转换容器和镜像保留。正式切换需在 MODEL-08 记录实际镜像编号、源码提交、配置、产物摘要和适用回退。
